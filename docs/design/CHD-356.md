# CHD-356: how a member's effort reads in a proposal, `/team show` and the agent list

Part of CHD-352. A team file can now give each agent an `effort`, as it gives a
`model` and a `mode`. The person reviewing a proposal sees everything that will
be written to the file (CHD-332), so the effort has to be in the table. This
document says where it goes, and how a change to it reads. It also covers the
same table in `/team show`, the running form, and the agent list's rows. The
owner had no view on this (CHD-352, answer 5), so this is a proposal for the
owner to approve before CHD-357 starts.

Every table below was laid out by @cliffy/table under bun, with the widths
and wrapping rules described here. Content width is 74 at 80 columns and 114
at 120 columns, as in CHD-333. The before screens are captures of main at
e6f368fa, under `evidence/CHD-356/` and `evidence/CHD-332/`, `CHD-333/`.

## Summary

- **The proposal table and `/team show`:** the effort gets its own column,
  between `agent · model` and the mode. Where an agent sets none, the cell is
  `—`, as for the mode. The column is there only when some agent of the
  table sets an effort, or had one before a change. A team with no efforts
  reads exactly as it does today.
- **A change:** a changed effort reads `high was medium`, in its own cell,
  with the `was …` dim, as the mode's is. Opened, a changed cell that has to
  wrap breaks before `was`, so the old value is on a line of its own.
- **The running form of `/team show`:** the same column, from the file. At
  80 columns it gives way to the latest headline, so 80 reads as today.
- **The agent list:** the effort an agent is really on, after its model, as
  `claude · Opus · high`. When a row has to shrink, the effort goes before
  the model, so 80 reads as today.
- Efforts are written as their ids in lower case (`high`, `xhigh`), as the
  file holds them and as Claude Code's own `◐ medium · /effort` does.

## Why a column, and not `claude · opus · high`

Putting the effort at the end of the agent · model cell saves a column, but
it fails in three places:

- **An effort with no model reads as a model.** `model` is optional, and
  `claude · high` reads as a model called "high".
- **Narrow, the effort is cut first.** The folded table cuts the agent ·
  model cell from its end once the role is down to 12 cells, so the effort
  would become `claude · opus · hi…` and then vanish, before the model. The
  effort is part of what the person approves, as the mode is. Neither is
  ever cut.
- **`was` has nowhere to go.** `claude · opus · high was medium` puts the old
  value after the cell. On a row whose mode also changed, that row has two
  `was` 20 cells apart.

In its own column, the effort is never cut, its `was` sits where the mode's
does, and the column lines up so the eye can run down it.

A column with no header has to be readable from its values alone. Effort
values (`minimal`, `low`, `medium`, `high`, `xhigh`, `max`) do not overlap
with any mode id Claude or Codex has, and the column always sits in the
same place, between the model and the mode.

## A change

The `~` row marks a changed agent. Today the mode cell is the only one that
says what it was. The effort cell does the same. In this change, tester's
effort and mode both change, coder sets an effort it had none of, and
reviewer's mode changes:

### Opened, 120 columns

```
         lead      claude · opus          high             default
                   Splits the job, says who edits which files, reports to main
      ~  tester    claude · sonnet        high was medium  acceptEdits was bypassPermissions
                   Writes the failing test, then proves the fix
      ~  coder     codex · gpt-5.3-codex  xhigh was —      auto
                   Writes the fix, in the files the lead names
      ~  reviewer  claude · opus          —                plan was read-only
                   Reads the diff and edits nothing
```

### Opened, 80 columns

```
         lead      claude · opus          high             default
                   Splits the job, says who edits which files, reports to main
      ~  tester    claude · sonnet        high was medium  acceptEdits
                                                           was bypassPermissions
                   Writes the failing test, then proves the fix
      ~  coder     codex · gpt-5.3-codex  xhigh was —      auto
                   Writes the fix, in the files the lead names
      ~  reviewer  claude · opus          —                plan was read-only
                   Reads the diff and edits nothing
```

- The effort is in the default colour, like the model. It has no warning
  colour: no effort skips the person's ok. Its `was …` is dim, as the mode's
  is.
- `xhigh was —` follows the mode's own `bypassPermissions was —`: the dash
  means that nothing was set and the runtime chose.
- A row whose only change is its effort is `~`, with the `was` in the effort
  cell and the mode cell plain.
- An effort removed by the change reads `— was high`.

### Folded, 80 columns: the effort's `was` goes before the model is cut

With both `was`s whole, the name, effort and mode cells take 65 of the 74
cells, and the role keeps 12. That leaves the model 1 cell, so every model
would read `…`. The effort is short, and
the `~` already says the row changed. So, folded, **the effort's `was …` is
dropped before the model is cut.** The mode's `was` stays, because the mode
is the permission the person approves:

```
         lead      clau…  high   default                            Splits the …
      ~  tester    clau…  high   acceptEdits was bypassPermissions  Writes the …
      ~  coder     code…  xhigh  auto                               Writes the …
      ~  reviewer  clau…  —      plan was read-only                 Reads the d…
```

Folded, the order cells give way is therefore: the role cut to 12, the
effort's `was …` dropped, then the model cut. The name, the effort, the mode
and the mode's `was` are never cut. This is a worst case: a change with a
33-cell mode cell. Today the same change already cuts the model to
`claude · op…`. ctrl+o has it all. At 120 columns everything is whole:

```
         lead      claude · opus          high             default                            Splits the job, says who …
      ~  tester    claude · sonnet        high was medium  acceptEdits was bypassPermissions  Writes the failing test, …
      ~  coder     codex · gpt-5.3-codex  xhigh was —      auto                               Writes the fix, in the fi…
      ~  reviewer  claude · opus          —                plan was read-only                 Reads the diff and edits …
```

## When an opened row does not fit: the wrapping order

CHD-333's order with the effort in it. Where an agent's first row does not
fit, the cells give way in this order:

1. **The mode cell, at its spaces**, down to its longest word.
2. **The effort cell, at its spaces**, down to its longest word.
3. **agent · model, at its spaces** only, so the model id stays whole.
4. **Inside a word**, as the last resort.

New for both changed cells: **a changed cell that wraps breaks before
`was`**. The new value is alone on the first line and `was …` starts the
next. Only then does cliffy wrap within `was …`. Without this rule, cliffy
fills lines greedily and gives `acceptEdits was` / `bypassPermissions`, or
`high was` / `medium`. Those read as if the old value were the new one.
CHD-333 asked for `was acceptEdits` under the new mode, and its examples
happened to land that way. With a column more, they no longer do. The
engineer gets this by putting a line break before ` was ` in a cell wider
than its column, and cliffy keeps the break.

The long-model change at 80 columns (`security-review` with
`claude-sonnet-4-5-20250929`, the 15-cell name CHD-333 used):

```
         lead             claude · opus                high    default
                          Splits the job, says who edits which files, reports to
                          main
      ~  tester           claude · sonnet              high    acceptEdits
                                                       was     was
                                                       medium  bypassPermissions
                          Writes the failing test, then proves the fix
      ~  coder            codex · gpt-5.3-codex        xhigh   auto
                                                       was —
                          Writes the fix, in the files the lead names
      ~  reviewer         claude · opus                —       plan
                                                               was read-only
                          Reads the diff and edits nothing
      -  security-review  claude ·                     max     bypassPermissions
                          claude-sonnet-4-5-20250929
                          Reviews the diff for security problems and edits
                          nothing
```

The effort goes to three lines (`high` / `was` / `medium`) so that the model
id stays whole. That is step 2 before step 3. The model is the thing a
person most needs to see whole (CHD-333). This team is the worst case: a
15-cell name, a 26-cell model id, `bypassPermissions` and `medium`. Its
long id stays whole down to 73 cells of content, about 79 columns, and
breaks inside a word, at step 4, below that. Without the effort column the
limit is 65 cells. 80 columns is just inside it.

- **The effort is the file's, like the model and mode beside it.** The
  running form's first three cells are the team as written. What an agent is
  really on is the agent list's job (below). When a runtime refuses the

  the proposal do not switch. Only the running form, a snapshot printed
  once, does.

## The agent list

The list is live: each row's model is the one the agent is on, as the status
line names it. The effort is live too: the effort the agent reports, after
its model, dim like the rest of the cell.

Before, 120 (`evidence/CHD-356/before-running-and-list-120x40.txt`):

```

    bugfix     team · fake · Fake Large with a 1M context window  ✓ replied 8s ago
    ├─ tester  fake · Fake Small                                  ● permission 6s
    └─ coder   fake · Fake Large with a 1M context window         ✓ replied 7s ago
```

After, 120:

```
    main       fake · Fake Large with a 1M context window · medium
    bugfix     team · fake · Fake Large with a 1M context window · high  ✓ replied 8s ago
    ├─ tester  fake · Fake Small · low                                   ● permission 6s
    └─ coder   fake · Fake Large with a 1M context window · medium       ✓ replied 7s ago
```

coder's file sets no effort, so its row says what its runtime started it on
(`medium`). In `/team show` the same agent is `—`. The list says what is,
and the file says what was asked for.

```

    bugfix       team · claude · Opus · high     ✓ replied 40s ago
    ├─ tester    claude · Sonnet · medium        ● permission 12s
    ├─ coder     codex · gpt-5.3-codex · xhigh
    └─ reviewer  claude · Opus · high            ✓ replied 1m ago
    parser       codex · gpt-5.3-codex · medium  ✻ working 9s
```

80 columns, before and after alike (`evidence/CHD-356/before-running-and-list-80x24.txt`):

```
    main       fake
    bugfix     team · fake  ✓ replied 18s ago
    ├─ tester  fake         ● permission 16s
    └─ coder   fake         ✓ replied 17s ago
```

- **Here the effort is in the cell, not a column.** The list has no unset
  value to show: an agent is always on some effort, or its runtime has none,
  and then nothing is added. A model is always there before its effort,
  since both come in the same config options. That makes the "effort reads
  as a model" problem from the table impossible here. A list row is also
  one value per agent, read across, not a column to compare.
- **Narrow, the effort goes first.** The list's fitting steps drop the model
  when rows do not fit. The effort is dropped one step before it, so a
  medium width keeps `claude · Opus` and 80 columns reads as today. The
  model says which agent is which, and the effort tunes it.
- **No refusal mark.** When a runtime refused the file's effort, the row
  shows the effort it is really on. The refusal is in the transcript, once.
- **A runtime with no effort** (no `thought_level` option): the row is as
  today.

## Colours, dark and light

- The table's effort cell is the default foreground, like the model. Its
  `was …` takes the dim the mode's `was` uses. Both themes already have
  those tones, so this adds no new colour.
- The list's effort is part of the dim runtime cell, as the model is.
- No effort is drawn in a warning colour. `max` or `xhigh` costs more, but
  it does not act without the person's ok, and the mode's warning colour
  means exactly that.

## Keys

None new. ctrl+o opens and folds the proposal and `/team show` as today. The
list's keys are unchanged.

## Not proposed here

- The status line naming the picked agent's effort, as Claude Code's
  `◐ medium · /effort` does. That belongs with the person's own sessions
  (CHD-355) if anywhere, and this task does not ask for it.
- The running form showing live model and mode. Today all three of its file
  cells are the file's, and this keeps the effort the same.

## Library first

@cliffy/table does all of this as it is: one more column with
`minColWidth`/`maxColWidth`, the same `Cell(...).colSpan(n)` role line, and a
line break placed before ` was ` in a cell wider than its column, which
cliffy keeps as a line of the cell. The tables above came from a scratch
script outside the repository that drives @cliffy/table, string-width and
cli-truncate from `node_modules`, with the widths described here. No new
library is needed.
