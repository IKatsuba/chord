# CHD-393: a tool call's headline, whole and wrapped

The owner (2026-10-15, answered 2026-10-17 as Q5 and Q6) wants a tool
call's headline to read as Claude Code's does. Every call's headline, its
ACP title, is drawn whole and wrapped to the transcript's width, every
line of it, in the main view. There is no cap: a 300-line command is 300
rows. This replaces the rule that a headline is one row
(`Headline.more` in `src/ui/transcript/tools/tools.ts`, and "each
command is one row" in `docs/decisions.md`).

Evidence:

- `evidence/CHD-393/claude-code/`: Claude Code 2.1.301, 120×40 and 80×24,
  in the main view and in ctrl+o, with its README. The table and findings
  are in the board comment on CHD-393.
- `evidence/CHD-393/today/`: chord today on the fake agent's `bash`,
  `shell`, `tools` and `permission` scenarios, run with
  `bun dev chord --fake -C` on a `mktemp -d` directory, the path replaced by
  `/tmp/chord-qa`.
- `evidence/CHD-393/mock/`: the heredoc command and the long one-line
  command, before and after, at both sizes. They are wrapped as
  `wrapLine` (`src/ui/transcript/message.ts`, wrap-ansi) wraps.

## The rule

A headline is `Name(argument)` and its note, as today. It is laid out as
one text that wraps instead of one row cut at the edge:

- **Room.** Every row of the headline gets the entry's `width`, the
  window's columns less four (`TRANSCRIPT_INSET`): 116 cells at 120
  columns, 76 at 80. That room is counted from column 3, after the
  marker, its space and the leading column (` ⏺ `). The name and `(`
  take room on the first row only. The transcript's right padding column
  stays empty, as it does for replies and `⎿` lines.
- **Continuation rows start at column 3, under the name's first letter.**
  That is where `⎿` starts. It is chord's version of Claude Code's main
  view, where wrapped rows start under the text after `⏺` (column 2,
  because Claude Code has no leading column).
- **Soft wraps.** The text breaks between words. A word longer than the
  room (a URL, a base64 blob) breaks at the edge with no hyphen. The space
  a row broke on is dropped. This is `wrapLine`'s behaviour.
- **The argument's own lines.** Each line of the argument, a heredoc's for
  one, starts a new row at column 3. Its leading spaces are kept, so an
  indented line inside a heredoc stays indented by its own spaces from
  column 3. If such a line is wider than the room, it wraps by the
  soft-wrap rule, its later rows at column 3. An empty line in the
  argument is an empty row.
- **The closing `)`** goes straight after the argument's last character,
  on its last row. It wraps with the last word, so it never sits alone at
  column 3 unless the last word filled a whole row. The dim note (` ·
  41s`, a task's runtime) comes after the `)` and wraps the same way.
- **No cap.** Every line is drawn however many there are. Scrolling is how
  to get past a long one.
- **The fold goes away.** The dim ` … +N lines)` form, and the extra rows
  only ctrl+o drew (`shown` in `Tool.tsx`), are both gone. `Headline.more`
  has no reader left.

## ctrl+o does not change the headline

In Claude Code, ctrl+o changes only the indent of a wrapped headline:
column 6, under the text after `Bash(`, or under the `(` after an MCP
call's `(MCP)`. It never changes how much is shown. chord draws the
headline the same way in both views, at column 3. ctrl+o in chord is the
toggle that unfolds output, and a headline that moved its rows sideways on
every press would make a long transcript jump. Column 3 also keeps a long
name like `notes - save_note (MCP)(` from eating a quarter of an 80-column
row on every line. ctrl+o goes on doing what it does today for the `⎿`
output, diffs and folded messages.

## Under it: `⎿` and the gutter

Nothing under the headline changes. The `⎿` row follows the headline's
last row, with `⎿` at column 3 and its text at column 6, the same as under
a one-row headline today. Terminal output, diffs, a proposal's table and
the `… +N lines (ctrl+o to expand)` fold of the *output* hang as they do
now. The blank row above each call stays. The headline only grows taller.

## Every tool

The rule is the same for every call: it is drawn from the call's title,
whatever the tool. The exception is an MCP call, whose arguments come from
its `rawInput` (next section).

- **Read, Update, Write and the rest** show what their title gives, almost
  always a path, which wraps like anything else.
- **An MCP call** shows its arguments, as Claude Code does (CHD-415, below).
- **Agent** keeps its description as its headline
  (`Agent(Count .ts files in src)`). Its prompt stays where it is today,
  in ctrl+o, as in Claude Code. A subagent block's own `Agent(…)` headline
  (`blockHeadline` in `subagents.ts`) wraps too and stops cutting its
  title. The runtime, model and effort stay after the `)`, so nothing has
  to be dropped to make room.
- **chord's own tools** (`chordHeadline`) follow the same rule.
- **A message sent** (`→ to @name`) is a headline too, and wraps the same
  way.

## An MCP call's headline (CHD-415)

The owner (2026-10-17, Q7 on CHD-415): an MCP call's headline shows its
arguments, as Claude Code does. Claude's adapter titles an MCP call by its
name alone (`mcp__notes__save_note`), and the arguments travel only in the
call's `rawInput`. So for these calls chord reads the arguments from
`rawInput`, not from the title. Today the call is drawn
`Tool(mcp__notes__save_note)` (`mock/mcp-before-*`).

The spelling is Claude Code's own. Its MCP tool draws its name as
`` `${server} - ${tool} (MCP)` `` and its arguments with `Vkn` in the
2.1.301 bundle:

```js
Object.entries(input)
  .map(([key, value]) => `${JSON.stringify(key).slice(1, -1)}: ${JSON.stringify(value)}`)
  .join(', ');
```

`Vkn` gives `''` for an input with no keys, and the headline is then the
name alone, with no parentheses. Before printing, it escapes control
characters U+007F–U+009F as `\uXXXX`. That code was read from the
installed binary's strings, not from a run. The capture
(`claude-code/80x24-transcript.txt`, `notes - save_note (MCP)(title: "…",
body: "…", tags: ["ui-test",…])`) agrees with it.

### Which calls

A call is an MCP call when its title has the form `mcp__<server>__<tool>`;
the title alone decides. `<server>` runs up to the next `__`, and
`<tool>` is the rest, `__` included. Any other title keeps today's title
rule, except Codex's, below.

### Codex's MCP calls (CHD-419)

The owner (2026-10-17, Q13 on CHD-419): a Codex MCP call to a server
other than chord's draws as Claude's does,
`<server> - <tool> (MCP)(key: JSON, …)`. Before this, it read
`Bash(mcp.notes.list_notes)` (the fake agent's `codexchordcalls`).

codex-acp titles such a call `mcp.<server>.<tool>`, gives it kind
`execute`, sets `_meta.is_mcp_tool_call`, and wraps its arguments in
`rawInput` as `{server, tool, arguments}`. CHD-377's enricher
(`codexMcpCall` in `src/session/enrichers.ts`) files what it wraps under
`_meta["chord/mcp"]`, and the headline reads it there:

- **The name comes from the wrapper's `server` and `tool`, never from the
  title.** The enricher's field gains `server` beside `tool` and
  `arguments`. A server or tool name with a dot in it (`my.notes`,
  `notes.v2`) then needs no splitting, and a title such as
  `mcp.my.notes.list` is never read for its parts.
- **The arguments** are the wrapper's `arguments`, spelled exactly as for
  Claude: `key: JSON`, joined by `, `. Missing, `null` or `{}` gives the
  name alone.
- **chord's own server:** a wrapper whose `server` is the name chord's
  server went by is chord's own call. `chordHeadline` draws it, as
  CHD-377 ties it.
- **No wrapper** (no `is_mcp_tool_call`, or no string `server` and
  `tool`): the call keeps the title rule, as any other title does.
  Nothing is guessed from a title that only looks like `mcp.…`.

On screen it is the same as Claude's call (`mock/mcp-after-*`), so no
mock of its own: Codex's `mcp.notes.save_note` with the capture's
arguments draws the very rows of `mock/mcp-after-80x24.txt`.

### The name

`<server> - <tool> (MCP)`, as in Claude Code: `notes - save_note (MCP)`.
`<server> - <tool>` is bold, as every headline's name is. ` (MCP)` is dim,
as Claude Code dims its MCP suffix (`hasMcpSuffix` → `dimColor`).

### The arguments

Each argument is written `key: value`, and the arguments are joined by `, `
in `rawInput`'s order, inside the headline's `(…)`:

- **The key** is written bare: `title`, not `"title"`. A key with a quote
  or a control character in it is escaped as JSON escapes it, since the
  key is JSON-encoded with its outer quotes dropped.
- **A string** is JSON-quoted: `"dev server errors"`, with `\"` for an
  inner quote.
- **Numbers, `true`, `false` and `null`** are written bare:
  `timeout_ms: 600000`.
- **Arrays and objects** are compact JSON, with no spaces, nested as deep
  as they go: `paths: ["src/a.ts","src/b.ts"]`,
  `options: {"depth":2,"ignore":["node_modules"]}`.
- **A newline inside a string** is the two characters `\n`, as JSON writes
  it, never a line break. An MCP argument therefore never starts a row of
  its own, unlike a heredoc's lines in a Bash command. It wraps like one
  long line. A tab is `\t`.
- **No arguments** (`{}`): the name alone, `notes - list_notes (MCP)`.
- **`rawInput` that is not an object** (a string, an array): the whole of
  it as JSON, `name("…")`. Claude's adapter always sends an object, so
  this is only a fallback.

At 80 columns:

```
 ⏺ files - write_file (MCP)(timeout_ms: 600000, follow: true, since: null)

 ⏺ files - write_file (MCP)(paths: ["src/a.ts","src/b.ts"], options:
   {"depth":2,"ignore":["node_modules"]})

 ⏺ files - write_file (MCP)(path: "notes.md", content: "# Notes\n\n- one\n-
   two\n")

 ⏺ files - write_file (MCP)
```

### While it streams

Claude's adapter can send the call first and its `rawInput` in a later
update. Until the arguments arrive, the headline is the name alone,
`notes - save_note (MCP)`. A missing `rawInput`, a `null` one and `{}` all
draw the same way, so the row never shows `Tool(mcp__notes__save_note)` first. When
they arrive, it grows, as a title does. A call titled
`mcp__<chord's server>__<tool>` goes to `chordHeadline` from its first
update, whether or not its `rawInput` has come and before chord has tied
it to the request it served, and is drawn with what that input holds so
far (`Monitor` alone, then `Monitor(dev server errors)`).

### chord's own MCP calls

They are left out. A call that chord's own server served carries
`call.chord`, and `chordHeadline` draws it (`→ to @reviewer`,
`Agent(…)`), as today. Arguments in the MCP form would only repeat what
those rows already say. One more rule: a call titled
`mcp__<chord's server>__…` is drawn by `chordHeadline`'s rules from the
first update, even before chord has matched it to the request it served,
so the row never flashes the MCP form first. If chord cannot tell its own
server's name at that point, developer says so and the lead takes it
further.

## What stays one line

Some places name a call in a row that is one row by design. They keep
today's look: the name, the argument's **first line**, then `)`, cut at
the edge.

- **A running subagent's `⎿` rows** (`workLines` and `blockFold` in
  `src/ui/transcript/agents/subagents.ts`, drawn by `headlineText` in
  `Agents.tsx`). These are the last three calls in a summary of three
  rows. A wrapped heredoc there would push out the other two.
- **The sessions list's latest line** (`headlineText` in
  `src/ui/teams/teams.ts`, read in `src/ui/app/sessions.ts`). This is one
  line per agent.
- **The permission box's title** is the box's own and does not change in
  this task (`today/permission-80x24.txt`).

`headline()` used to drop the lines past the first for these places, and
now keeps them. So these places now take the first line themselves.
Their look does not change.

## States

- **Streaming.** A call whose title is still arriving is drawn with the
  title it has. Claude's adapter can send `Bash` first and the command in
  a later update. As the title grows, the headline grows taller and what
  is under it moves down. Nothing is drawn ahead of the title.
- **Pending.** A call waiting on the person (`permission`) draws its whole
  headline, wrapped, above the permission box. At 80×24 a tall headline
  scrolls off the top, as a long transcript does. The box itself, with
  its title and choices, stays whole at the bottom.
- **Running.** The marker blinks in `accent`. The headline is the same as
  when it is done.
- **Done / failed.** The marker is `success` or `error`. The headline is
  drawn the same either way: the name bold, the argument in the default
  text colour, the note dim. A failure shows in red in the `⎿` lines, as
  today.
- **Empty title.** `Bash` alone, one row, as today.
- **Narrow.** The room is the entry's width at any size: 76 cells in an
  80-column window. A window narrow enough that the name
  and `(` fill a row still wraps the argument, a cell at a time if it must.

## Colour roles

Nothing new from `src/ui/theme/theme.ts`. The marker uses its tone's role
(`accent` while running, `success` when done, `error` on failure, the
default colour while pending). The name is bold. The argument is the
default colour on every row. The note and the `→ to` are dim. Agent text
goes through `Ansi`, so colour codes in a title keep their colour on every
row they wrap to.

## Keys

No new key and no change to the shortcuts panel. ctrl+o keeps its entry,
`ctrl + o for verbose output`, which says what it does: it expands output,
not headlines. Scrolling past a tall headline uses the keys that already
scroll (pgup/pgdn, the wheel, `shift + ↑ ↓`, home/end).

## Why

The person reads what went to the shell before it runs and after it ran.
A heredoc's body and the middle of a long pipe are what the call does, and
the fold and the middle cut hid exactly that. Claude Code draws them whole
for every tool, and chord is meant to read like it. The cost is height: a
300-line command is 300 rows. The owner chose that over a cap (Q6), as
Claude Code does.
