# CHD-521: Guardian reviews draw only when not approved

The owner (2026-10-25, CHD-521, Q212–Q214): an approved Codex Guardian
review leaves no trace on screen, live or after `/resume`. While it is in
progress, one dim line says `Guardian reviewing…`. A denied, timedOut,
aborted or unknown status keeps today's full `Guardian(Review)` block.
This is fixed behaviour, with no setting.

## In progress

The exact line is `Guardian reviewing…`, with the single ellipsis glyph
and no leading marker, spinner, bold text, timestamp or state suffix. It
starts at the transcript's usual text column, under the first letter of
a tool-call name (column 3, zero-based). All of it is dim terminal text:
SGR 2, no painted foreground. `theme.ts` deliberately leaves plain and dim
text to the terminal; no new colour role is added. This makes the wait
readable without giving an internal approval check a tool's prominence.

It replaces the review's own entry where that entry arrived in transcript
order. It does not attach to or move the command's headline, arguments or
output, and it does not repeat any of them. The command keeps its normal
rendering. Ordinary spacing between transcript entries remains while the
line is visible; no blank content rows are added inside this one-line
entry. Multiple reviews keep their own positions.

At **120×40**, the transcript excerpt (the rest of the window, prompt and
status line stay as today):

```text
 ⏺ Run(printf 'ready\n')

   Guardian reviewing…
```

At **80×24**, the same excerpt fits without wrapping:

```text
 ⏺ Run(printf 'ready\n')

   Guardian reviewing…
```

These are placement mocks, not a claim that every adapter emits the
command before the review. If the review arrives first, its line precedes
the command at that same transcript position. When the command is waiting
on the review, the existing working/status indicators continue unchanged.

## Approved

When the structured review status is `approved`, the entire review entry
is absent. Its line, marker, content and spacing are absent too. No empty
box, placeholder, blank gap, count, command-row badge or notification is
left. `ctrl+o` does not reveal it.

At **120×40** and **80×24**, the example after approval and command output:

```text
 ⏺ Run(printf 'ready\n')
   ⎿  ready

 ⏺ Done.
```

The blank row between these ordinary entries is the existing transcript
spacing. There is no extra row where the Guardian entry used to be.
Removing adjacent approved reviews also leaves no accumulated blank rows.

## Other statuses

A closed review with `denied`, `timedOut`, `aborted`, or an unknown status
uses today's full tool block: headline, Status, Action, Risk,
Authorization and Rationale, with today's wrapping, colours, folding and
`ctrl+o` behaviour. It stays in its original transcript position. This
design changes no words or styling within that block.

At **120×40**, a short example of the existing block:

```text
 ⏺ Guardian(Review)
   ⎿  Status: Denied
      Action: exec /bin/zsh -lc "printf 'ready\n'"
      Risk: low
      Authorization: high
      Rationale: The command was not authorized.
```

At **80×24**, this short example still fits; longer Action and Rationale
text keeps today's wrapping and output fold:

```text
 ⏺ Guardian(Review)
   ⎿  Status: Denied
      Action: exec /bin/zsh -lc "printf 'ready\n'"
      Risk: low
      Authorization: high
      Rationale: The command was not authorized.
```

These are content mocks; the existing block's renderer determines the
actual call marker, completion tone and output fold in the captures.
Unknown or missing structured data must not silently hide a block. The
structured `rawInput.review.status` / `rawOutput.review.status` is what
identifies the state, never the human-readable `Status:` text. The
adapter-shape contract and its fallback belong in the implementation
handover, because these fields are codex-acp's, not ACP's.

## Resume, keys and unchanged screens

`/resume` replay has the same final appearance: an approved review is
absent immediately, without flashing its old block or a temporary wait
line. Other reviews retain their full blocks. The underlying agent/session
record can retain the review; it is the screen that hides it.

No action or key is added. Existing transcript scrolling, `ctrl+o`, the
prompt, permission prompts, agents list and shortcuts panel stay as they
are. Empty transcripts acquire no placeholder. Ordinary command output,
errors and other agents' tool calls are unchanged.

## Folded subagent projection

The lead settled the nested form for U2: a folded task keeps its parent's
structural `⎿` or tree prefix. The review's own text remains dim
`Guardian reviewing…`, with no review marker or spinner. Expanded work
uses the same text column relative to its own transcript inset. Approved
reviews add no tool-use count, group boundary, mounted height or latest
team-work headline. Progress rows do not count as tool uses either.
