# CHD-454 — a start failure says which step failed, and why

Today an agent that does not start shows one red row, and the whole stderr
tail is run into it:

```
 ⏺ minion-code did not start: The agent exited: Installed 42 packages in 120ms
   Traceback (most recent call last):
     File "/opt/uv/archive-v0/abc/bin/minion-code", line 5, in <module>
   …
 ⏺ kimi did not start: The agent exited.
```

(`evidence/CHD-454/before-trace-120.png`, `before-trace-80.png`,
`before-exit0-80.png`, on stand-in agent commands. No agent was run.)

The owner decided (2026-10-18) that such a failure says why, in words a
person can act on. The owner's answers:

- **Q175 (1):** the step, the exit code, the -32601 wording, the Registry's
  pin and the stderr tail cut short.
- **Q176 (2):** no stdout tail. A line an agent prints on stdout that is
  not JSON is dropped by the ACP SDK's stream, as today, so kimi's exit 0
  shows the headline alone.
- **Q177 (2):** zeroclaw is the only agent with words of its own.
- **Q178 (1):** as designed: the last 6 stderr lines with a dim `… +N
  lines`, the pin line first in CHD-435's sign-in block too, and an
  `open_agent` child's note quoting the tail's last line.

It is CHD-435's row, extended. The sign-in block stays as CHD-435 draws it.

## The row

**The headline** is `⏺`, then `<agent> did not start: <step>`, in `error`.
`<agent>` is `shownAgent`, as in CHD-435. The step is one of these, in
chord's words:

| What happened | The step |
| --- | --- |
| Exited before answering `initialize` | `it exited with code <n> before answering initialize.` |
| Killed by a signal there | `it was stopped by <SIGNAL> before answering initialize.` |
| Closed its stdout with no exit code seen within the bounded wait | `it closed its connection before answering initialize.` (or `… before answering session/new`, the method chord sent). No exit is inferred, and the stderr tail goes only in the block below. |
| Exited while chord waited on `session/new`, `session/load` or `session/resume` | `it exited with code <n> before answering session/new.` (the method chord sent) |
| `initialize` refused | `it refused initialize: <the agent's message>` |
| The session method refused with -32601 | `it does not serve ACP sessions: not an ACP agent, or not at this version.` |
| The session method refused with -32000 | CHD-435's headline and block, unchanged. |
| The session method refused, any other code | `it refused session/new: <the agent's message>` (the method chord sent) |

A command that is not found keeps today's words.

**The block** hangs from a dim `⎿` under the headline, in the terminal's
own foreground, as in CHD-435. Its parts come in this order, each only when
it has something to say. With none of them there is no block, and the
headline stands alone.

1. **The pin**, for an agent chord runs from the ACP Registry through npx or
   uvx (`src/registry.ts`): `chord ran <package>@<version>, the version the
   ACP Registry names.` A command from the person's settings or
   `--agent-command` has no pin line. A sign-in failure gets the pin line
   too, first in CHD-435's block. qoder and minimax fail that way at their
   old pins.
2. **The end of its stderr**: `The end of its stderr:`, then its last 6
   non-empty lines, each indented 2 and kept with its own indent. When
   there were more, a dim `… +N lines` (`+1 line`) comes first, as a fold's
   marker does. A line wraps under the tail's column (2), not under its own
   indent. The lines go through `Ansi`, as written. OpenTUI's word wrap is
   taken as it is: a word wider than the row (a long path, a capped line)
   starts on the next row at the tail's column, so the row it was indented
   on shows only its indent.
3. **The way on.** For zeroclaw only, keyed on its registry id and a -32602
   refusal: `Set a default agent: [acp] default_agent = "<alias>" in
   ZeroClaw's config, or start it with zeroclaw acp --agent <alias>.` For a
   sign-in failure, CHD-435's fixed line. Nothing else has a way-on line.

The headline has said what failed, so the stderr tail no longer goes into
it.

## Outside the window

- **`-p` (headless.ts), on stderr.** One `chord: ` line for the headline,
  then a `chord: ` line for each line of the block, in the same order. The
  stderr tail lines keep their own indent after `chord:   `. The `… +N
  lines` marker is a line too:

  ```
  chord: minion-code did not start: it exited with code 1 before answering initialize.
  chord: chord ran minion-code@0.1.44, the version the ACP Registry names.
  chord: The end of its stderr:
  chord:   … +1 line
  chord:   Traceback (most recent call last):
  chord:     File "/opt/uv/archive-v0/abc/bin/minion-code", line 5, in <module>
  …
  chord:   ImportError: cannot import name 'CodeAgent' from 'minion.agents' (…)
  ```
- **A child opened with `open_agent`**, in its parent's note, as one
  paragraph. It has the step, then the pin and the way on as sentences, and
  only the tail's last line, quoted: an agent reader needs the cause, not
  the traceback.

  ```
  parser (minion-code) did not start: it exited with code 1 before answering initialize. chord ran minion-code@0.1.44, the version the ACP Registry names. Its stderr ended: "ImportError: cannot import name 'CodeAgent' from 'minion.agents' (…)". It takes no messages; open_agent starts another.
  ```

  For zeroclaw, the way on is turned for an agent reader: `The person sets
  a default agent: …`, as CHD-435 does.

## States

- **Failed at start:** the block above. **A resumed or continued session**
  fails on `session/load` or `session/resume` with the same row, and the
  method chord sent is named.
- **Narrow:** at 80 columns, a stderr tail of 6 lines with long paths can
  take 10 rows or more. The window has room under the header. In a
  background pane the rows wrap the same way.
- **Streaming, waiting on the person:** none. The prompt stays, as today.
- **The agents list:** keeps `✗ failed to start`.

## Keys

None. After the failure the window is today's: the prompt, and ctrl+c to
quit. The way on is outside chord, so there is nothing to bind, and the
shortcuts panel does not change.

## Why

- **The step is chord's own knowledge.** It reads the same for every agent,
  so it needs no table (Q175).
- **Six lines of tail** take a Python traceback's last two frames and its
  error line. A Node stack prints its message first and its frames last, so
  six lines may show only frames. Then the pin line is the way on: run that
  package in a terminal and read the whole output. chord does not guess
  which line of the tail holds the error.
- **The pin line** names the version, which is what a stale Registry pin
  needs, and it says the version is the Registry's choice, not chord's.
- **The order** matches CHD-435: what failed in the headline, then what
  chord knows, then the agent's own words, then the way on last.
