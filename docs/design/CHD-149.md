# CHD-149 — Subagents under the turn that started them

An agent can hand part of a turn to a subagent. Over ACP, each subagent is a
session of its own. The parent session gets `subagent_spawned` and later
`subagent_state_update`. Everything the child does (chunks, tool calls, plan,
permission requests) arrives with the child's `sessionId`. Several children can
run at once, and a child can start children of its own. CHD-150 makes the
session layer fold all of this into one `subagent_update` shape and holds each
child apart from its parent. This page says how it looks on screen.

The reference is Claude Code's Task block. A running block shows the latest
few tool calls under `⎿` and `+N more tool uses`. A finished block shows
`Done (N tool uses · tokens · time)`. Agents started together show as one
`Running N agents…` tree with `├─` and `└─`. This page copies that shape. I
did not capture Claude Code drawing a Task for this page, because that needs a
prompt and a spent turn. The shape above is how Claude Code draws it today, and
these mocks follow it.

The mocks are in `evidence/CHD-149/mock/`, at 120×40 and 80×24, one file per
state. They were laid out to exact widths from the real rows of
`deno task chord:fake` (`evidence/CHD-149/today/`: tool calls, a permission
prompt, a plan, ctrl+o), with the directory shown as `~/src/app`. Each state
is drawn below at one width. The file at the other width is in the folder.

## The decisions, in short

| Question | Answer |
| --- | --- |
| Where a subagent hangs | **In the parent's transcript, where its spawn arrived**, as a block shaped like a tool call: `⏺ Agent(<title>)`. It stays there and changes in place. |
| What a running block shows | Its **latest three tool calls** as headlines under `⎿`, then `+N more tool uses (ctrl+o to expand)`. Before its first call: `Initializing…`. Its messages and thoughts stay hidden until ctrl+o. |
| Several at once | Spawns with nothing from the parent between them form **one group**: `⏺ Running 2 agents…`, with one `├─`/`└─` row per child and only that child's current call under it. |
| Ended | `⎿  Done (6 tool uses · 41s)`. Also `Failed`, `Cancelled` or `Disconnected`, with the same counts. |
| ctrl+o | Every block opens. It shows the child's task in full, then its whole transcript (messages, thoughts, tool calls with their output, its plan), drawn as the parent's would be, indented under the block. |
| A child's permission request | The usual permission box. Its first row names who asks: `Agent(Find the session layer) asks`. The child's row in the transcript says `· waiting for permission`. |
| A child's plan | **Never above the prompt.** That place is the parent's. A child's plan shows only in ctrl+o, inside the child's work. |
| The parent's tool call that spawned it | Neither adapter sends one in native mode, so there is nothing to link. A tool call the parent does send, such as Codex's `wait`, is drawn as an ordinary tool call next to the block. chord never guesses a link. |
| A child still running after the turn ends | Its block keeps changing in place. The status line says `1 agent still running` until it ends. |
| New keys | **None.** ctrl+o already expands everything. Esc already cancels the turn, and the adapters cancel its children with it. |

## What the adapters send, and what the screen can rely on

I read the adapters' code for this page (claude-agent-acp 0.86.0, codex-acp
1.13.1's bundle; CHD-140 checked codex-acp 2.1.1's source). These are the
facts the shape rests on:

- **The spawning tool call is not sent.** Claude's adapter in native mode
  holds back every `Agent`/`Task` tool call (`route()` returns `null` for a
  control update). The one exception is a spawn that failed before any child
  existed, which goes to the parent as an ordinary failed tool call. Codex's
  adapter drops a `spawnAgent` call once a child stands for it. Its `wait`,
  `sendInput`, `resumeAgent` and `closeAgent` calls still reach the parent as
  tool calls. So the subagent block itself takes the place of the call.
- **`name` is short and `task` can be long.** Claude names a child by the
  Agent tool's `name`, else its `description` ("Find the session layer"), else
  its type, else `Agent 1a2b3c4d`. Its `task` is the whole prompt the child
  got. Codex names a child by its agent path (`explorer`, `worker`) and gives
  the prompt as `task`. So the headline uses the name, and the task appears
  only in ctrl+o.
- **Children nest.** A child's own spawn arrives with the child's `sessionId`
  as the parent.
- **A finished child can come back.** Claude's `SendMessage` and Codex's
  `resumeAgent` reopen a child as a new session (`<id>:generation:2`), with a
  new `subagent_spawned` and the same name. It is drawn as a new block where
  it arrives. The id's suffix is the adapters' private format, so chord does
  not read it to join the two blocks.
- **Cancelling the turn ends the children.** Claude sends `cancelled` for
  every open child. Codex sends `cancelled` or `failed` for each one.
- **No tokens per child.** A child has no `session/prompt` answer, so ACP
  carries no spend for it. Claude Code's `· 41.2k tokens` has no source here,
  and chord shows counts and time only. A cost from chord's estimate would be
  a guess about a turn chord never sent, so there is none.

## One subagent, running

The block is a tool call whose name is `Agent` and whose argument is the
subagent's title. The `⎿` lines hold the headlines of its three most recent
tool calls, oldest first, each drawn as a tool call's headline is drawn: the
name bold, the argument plain, a failed one in the error colour. They have no
marker of their own. When more calls exist, `+N more tool uses (ctrl+o to
expand)` follows, dim, as `… +N lines` does for output. A nested agent counts
as one tool use and shows as its own `Agent(<title>)` headline.

`evidence/CHD-149/mock/120-one-running.txt`:

```
 › Find where chord hands each session/update to its listeners.

 ⏺ Agent(Find the session layer)
   ⎿  Search(pattern: "sessionUpdate", path: "src")
      Read(src/session/conversation.ts)
      Read(src/acp/connection.ts)
      +2 more tool uses (ctrl+o to expand)

 ✻ Working… (34s · esc to interrupt)
```

Before the first tool call (`120-one-starting.txt`) the only line is
`⎿  Initializing…`, dim, as Claude Code draws it. A child that only writes
text and never calls a tool keeps `Initializing…` until it ends. Its words are
in ctrl+o. Showing a moving line of a child's prose in a block meant for
"what it is doing" would read as if the parent said it.

The marker is the running tool call's marker, in accent. The spinner line is
the turn's own, unchanged. A turn that is waiting on its agents is still
working.

**Why the latest three:** they answer "what is it doing now" without scrolling.
Three is the number of output lines a tool call shows before it folds
(`SUMMARY_LINES`), so a subagent block is no taller than a tool call.

## Two or more at once

Subagent blocks that arrive one after another, from the same parent session
and with nothing from the parent between them, draw as one group. Parallel
spawns arrive back to back from both adapters. A spawn that arrives after the
parent has said or called anything starts a new block. A group of one is the
single block above.

`120-two-running.txt`:

```
 › Where does chord route session/update, and where are tool calls drawn? Look in parallel.

 ⏺ I'll send two agents, one for each side.

 ⏺ Running 2 agents… (ctrl+o to expand)
   ├─ Agent(Find the session layer) · 4 tool uses
   │  ⎿  Read(src/acp/connection.ts)
   └─ Agent(Find where tool calls are drawn on screen and how they fold) · 2 tool uses
      ⎿  Search(pattern: "function Tool", path: "src/ui")

 ✻ Working… (34s · esc to interrupt)
```

- The header is `Running N agents…` while any child runs. Once all have ended
  it is `N agents finished` if all are Done, and otherwise `N agents ended ·`
  followed by what went wrong (`1 failed, 1 cancelled`). `(ctrl+o to expand)`
  follows the header, dim, except in the expanded view.
- Each child gets one row, `├─` for every child but the last and `└─` for the
  last. The row is `Agent(<title>)`, then dim `· N tool uses`, then `· 41s`
  once it has ended.
- Under each row there is one `⎿` line: the child's current tool call
  (`Initializing…` before its first), and once it has ended, `Done`,
  `Failed`, `Cancelled` or `Disconnected`.
- The `│` that joins the rows, the `├─`/`└─` and the `⎿` are dim.
- The marker is in accent while any child runs, success when all are Done,
  error when any Failed or Disconnected, and dim when the worst is Cancelled.

Narrow (`80-two-running.txt`): a row that does not fit drops its
`· N tool uses · time` first, then the title is cut with `…`. The tree glyphs
are never cut.

```
 ⏺ Running 2 agents… (ctrl+o to expand)
   ├─ Agent(Find the session layer) · 4 tool uses
   │  ⎿  Read(src/acp/connection.ts)
   └─ Agent(Find where tool calls are drawn on screen and how they fold)
      ⎿  Search(pattern: "function Tool", path: "src/ui")
```

## Finished

`120-finished.txt`. A single block folds to one line: what it did and how long
it took. The parent's reply under it is what the person reads next.

```
 ⏺ Agent(Find the session layer)
   ⎿  Done (6 tool uses · 41s)

 ⏺ Routing lives in src/acp/connection.ts: each session/update goes to the listeners of its sessionId.
```

```
 ⏺ 2 agents finished (ctrl+o to expand)
   ├─ Agent(Find the session layer) · 6 tool uses · 41s
   │  ⎿  Done
   └─ Agent(Find where tool calls are drawn on screen and how they fold) · 3 tool uses · 28s
      ⎿  Done
```

The time runs from `subagent_spawned` to the update that ended the child, on
chord's clock. `41s` is written as the spinner writes it, and `2m 5s` past a
minute. The child's final message is not shown folded. The parent's answer
already says it, and ctrl+o has it.

## Failed, cancelled, disconnected

`120-failed-cancelled.txt`:

```
 ⏺ Agent(Find the session layer)
   ⎿  Failed (2 tool uses · 9s)

 ⏺ 2 agents ended · 1 failed, 1 cancelled (ctrl+o to expand)
   ├─ Agent(Find the session layer) · 4 tool uses · 12s
   │  ⎿  Cancelled
   └─ Agent(Find where tool calls are drawn on screen and how they fold) · 1 tool use · 12s
      ⎿  Failed
   ⎿  Interrupted by user
```

- `Failed` and `Disconnected` are in the error colour, like a failed call's
  `⎿` lines. `Cancelled` is dim. Each word says what happened, so colour is
  never the only signal.
- ACP gives no reason with a state, so none is invented. Whatever the child
  said before it failed is in ctrl+o.
- The last line above is the turn's own `Interrupted by user`, as today. Esc
  cancels the parent's turn, and the adapters end its children as cancelled.
- `Disconnected` is the adapters' fourth state. chord also uses it for a
  child left with no ending: when the agent process exits, or when a resumed
  session's record has a child that never ended (its agent is gone).

## ctrl+o: a child's whole work

ctrl+o opens every block, as it opens every tool call's output today. Under
`⎿` comes the child's task in full, wrapped (it is the prompt the child got).
Then comes the child's transcript, exactly as the parent's draws in the
expanded view: messages as markdown, thoughts, tool calls with all their
output, its plan. It is indented so the child's `⏺` stands under the task's
first letter (6 columns in, 9 inside a group row). A single block ends with its
`⎿  Done (…)` line. A group keeps its `│` down the side of each child but the
last.

`120-expanded.txt` (the 80×24 file is the bottom of the same view):

```
 ⏺ Running 2 agents…
   ├─ Agent(Find the session layer) · 5 tool uses
   │  ⎿  Find where chord hands each session/update to its listeners and
   │     say which file owns the routing. Report paths and line numbers.
   │
   │     ⏺ Plan
   │       ⎿  ☒ Find the transport
   │          ◐ Find the listeners
   │          ☐ Write the answer
   │
   │     ⏺ Search(pattern: "sessionUpdate", path: "src")
   │       ⎿  Found 14 files
   │
   │     ⏺ Search(pattern: "listeners", path: "src/acp")
   │       ⎿  src/acp/connection.ts:88: const listeners = new Map();
   │          src/acp/connection.ts:214: listeners.get(sessionId)?.(update);
   │
   │     ⏺ Agent(Read the transport tests)
   │       ⎿  Done (2 tool uses · 6s)
   │
   │     ⏺ The listeners are kept per sessionId in openAgent; an id chord
   │       did not open is dropped there.
   │
   └─ Agent(Find where tool calls are drawn on screen and how they fold) · 2 tool uses
      ⎿  Find the component that draws a tool call and the rule that
         folds its output.

         ⏺ Search(pattern: "function Tool", path: "src/ui")
           ⎿  Found 1 file

         ⏺ Read(src/ui/App.tsx)
           ⎿  Running…
```

- **Two levels open, deeper ones stay folded.** A grandchild (`Agent(Read the
  transport tests)` above) is drawn as a folded block inside its parent's
  work, even in ctrl+o. Each level costs 6 columns, and at 80 columns a third
  level would leave a line about 60 columns wide. Its work is not lost: it
  folds the same way the child does.
- A child's plan is drawn once, where the child first sent it, at its latest
  state. The child's plan updates move it in place, and none of them reach
  the list above the prompt.
- Markdown and code are laid out to the width left after the indent, so a
  wide line wraps or cuts inside the child's column and never under the `│`.

## A child asks for permission

`120-permission.txt`:

```
 ⏺ Running 2 agents… (ctrl+o to expand)
   ├─ Agent(Find the session layer) · 5 tool uses
   │  ⎿  Write(notes/routing.md) · waiting for permission
   └─ Agent(Find where tool calls are drawn on screen and how they fold) · 2 tool uses
      ⎿  Read(src/ui/App.tsx)

 ✷ Waiting for permission… (3s)
╭──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────╮
│ Agent(Find the session layer) asks                                                                                   │
│ Write notes/routing.md                                                                                               │
│                                                                                                                      │
│ Do you want to proceed?                                                                                              │
│ ❯ 1. Allow                                                                                                           │
│   2. Always allow                                                                                                    │
│   3. Deny                                                                                                            │
│                                                                                                                      │
│ Esc to reject                                                                                                        │
╰──────────────────────────────────────────────────────────────────────────────────────────────────────────────────────╯
```

- The box, its choices, its keys and Esc are unchanged. One row goes on top:
  `Agent(<title>) asks`, with `Agent` bold and the row in accent. A
  grandchild's request names the path, `Agent(<child>) › Agent(<grandchild>)
  asks`, cut from the left with `…` when it does not fit.
- The parent's own requests have no such row. That missing row is how they
  differ.
- The asking child's current call gets a dim `· waiting for permission` in
  the transcript, so the person can see which row the box belongs to while
  another child keeps working.
- Requests from several children are answered one at a time, as requests
  already are. The tab's wait glyph and the terminal's notification are the
  parent session's, since the request reaches the person through it.

## A child's plan, and the parent's

`120-plan.txt`: the list above the prompt belongs only to the parent. Here the
parent made a plan and then sent an agent, and the agent's own steps are not
mixed in:

```
 ⏺ Agent(Find the session layer)
   ⎿  Read(src/acp/connection.ts)
      Read(src/session/conversation.ts)
      +3 more tool uses (ctrl+o to expand)

 ✻ Working… (34s · esc to interrupt)
  ⎿  ☒ Plan the change
     ◐ Read the session layer
     ☐ Write the design
```

Two agents with plans would otherwise replace each other's list several times
a second, and the person could not tell whose steps were whose. A child's plan
is in ctrl+o, inside its work.

## Running past the turn

`120-background.txt`. A child can outlive the turn: Claude's background agents
do, and an adapter may end the turn before a slow child. Its block stays where
it was spawned and keeps changing. Once the turn has ended, the status line's
left side says so, in place of the hint, until the last child ends:

```
 ⏺ Agent(Run the whole test suite)
   ⎿  Bash(deno task test)

 ⏺ It is running; I will say when it ends.
╭──────────────────────────────────────────────────────────────────────────────╮
│ ›                                                                            │
╰──────────────────────────────────────────────────────────────────────────────╯
  1 agent still running                                 Opus · 91% context left
```

The block may already be scrolled out of sight, so the status line is the
only place left to see that something is still running. There is no spinner,
because no turn is running and the prompt is free.

## The parent's own tool calls

`120-codex-wait.txt`. The parent's tool calls stay the parent's. Codex's
`wait` call is drawn as an ordinary tool call after the group, because that is
what it is: the parent waiting.

```
 ⏺ Running 2 agents… (ctrl+o to expand)
   ├─ Agent(explorer) · 3 tool uses
   │  ⎿  Bash(rg -n sessionUpdate src)
   └─ Agent(worker) · 1 tool use
      ⎿  Read(src/ui/App.tsx)

 ⏺ Wait(explorer, worker)
   ⎿  Running…
```

No adapter ties a subagent to a tool call. Neither `subagent_spawned` nor the
SDK's `subagent_update` has a `toolCallId`, and the spawn call itself is not
sent. If a later ACP adds that tie, the block would take the call's place
instead of standing beside it. Until then, chord draws what arrives, in the
order it arrives.

## Colours, light and dark

Nothing new goes in the theme. The marker uses the tool call tones (accent,
success, error, dim). `Agent` is bold like a tool's name. The tree glyphs, the
`⎿`, the counts, `+N more tool uses` and `· waiting for permission` are dim.
`Failed` and `Disconnected` are in the error colour, and the permission
prompt's `asks` row is in accent. Every state also has its own word, so a
light terminal that dims the greys loses nothing.

## Keys

None new. `keys.ts` and the shortcuts panel stay as they are. ctrl+o's entry,
`ctrl + o for verbose output` (Claude Code's words), already covers the
agents' work.

## For the engineer (CHD-151)

- Before drawing the tree by hand, look for a maintained Ink tree or list
  component that survives `deno compile`, as the one rule says, and say in
  the handover what you tried. The tree is three glyphs on rows chord already
  draws (`Tool`, `Under`), so the bar for taking a library is that it lays
  out those rows without a wrapper of our own.
- The block reuses `headline()` for its children's calls and `Under` for its
  `⎿`. The fold count, the group rule and the header words are pure and
  belong in a module next to `tools.ts`, with tests, not in `App.tsx`.
- The mocks are the acceptance: each state at 120×40 and 80×24, captured
  against the fake agent's `subagent` scenario (CHD-150), saved under
  `evidence/CHD-151/`.
