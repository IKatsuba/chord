# CHD-627 — `/new [agent] --name <name>`

The owner, 2026-11-13: `/new` takes an optional name for the agent it
opens. The owner settled the syntax (`/new [agent] --name <name>`, the first
word always an agent), refusal of a taken name, `/fork`'s characters, where
the name shows (where a child's name shows today, nothing new drawn), no
renaming, and the same `--name` for `chord acp`'s `/new`. The lead settled
the parsing and which names are taken (task comment and the lead's brief).
This file fixes only what goes on screen: the refusal lines, the `/new` row
of the slash list, `chord acp`'s hint, and the shortcuts panel.

## What is typed

| Typed | Opens |
| --- | --- |
| `/new` | a child on main's runtime, named as today |
| `/new codex` | a child on codex, named as today |
| `/new --name scout` | a child on main's runtime named `scout` |
| `/new codex --name code review` | a child on codex named `code review` |

`--name` takes the rest of the line, trimmed, as `/fork <name>` does:
`/new --name a --name b` names it `a --name b`, and `/new --name x codex`
names a child of main's runtime `x codex`. Only the spaced form: `--name=x`
is a word that is not `--name`, refused below.

## Refusals

Said where `/new` was typed, as today's `/new` refusals are: the typed
command echoed, the line under it in the error colour (`noted`, `failed`).
They are checked in this order and the first one is said; after them come
today's (`No agent named … ; chord knows …`, a closing session, a full
window).

| Case | Line |
| --- | --- |
| `--name` with nothing after it | `--name needs a name · /new [agent] --name <name>` |
| any other word after the agent (`/new codex x`, `/new codex --name=x`, `/new codex --nme x`) | `/new takes an agent, then --name <name> · /new [agent] --name <name>` |
| a bad character | `An agent name must not contain the character "` (or `… the control character U+0009`), `/fork`'s own words from `agentNameProblem` |
| a taken name: main, chord or an open child | `The name scout is taken in this window` |

At 120x40, one refused `/new` reads:

```
 › /new codex --name reviewer
   The name reviewer is taken in this window
```

At 80x24 the longest line (`/new takes an agent, then --name <name> · /new
[agent] --name <name>`, 67 columns with its indent) still fits one row.

Why these words:

- Both usage lines end with the same form after ` · `, as chord's other
  two-part refusals do (`… is working · /fork once its turn ends`): what was
  wrong, then what to type. One form, written as the slash list and
  `chord acp` hint write it, so a person sees the same thing in all three.
- The taken line names the name and not the agent that holds it: `main`
  and `chord` are not children, and "an agent named …" would read as today's
  `No agent named codex`, which is about runtimes. "is taken" is the word
  `teamNameProblem` already uses for a reserved team name.
- No numbering and no suggestion: the owner chose refusal, and a suggested
  `scout 2` would be chord guessing a name.

## The `/new` row of the slash list

`src/ui/prompt/commands.ts`, description:

```
  /new      Open a new agent beside main and go to it; --name names it
```

58 columns of description: it fits beside `/context`'s name column at 80x24
(the widest description today, `/config`'s, is 60). Completion is
unchanged: after `/new ` the list offers agents, it goes away after the
first word, and `--name` gets no item.

## `chord acp`

`src/session/upstream.ts`, `/new`'s `input.hint`: `[agent] [--name <name>]`

## Shortcuts panel

Nothing: `--name` is a word of a command, not a key, and `/new` has no key
today. The panel (`?` on an empty prompt) is unchanged.

## States

Nothing streams and nothing waits on the person: `/new` either opens a
child (today's screen, the child's chosen name in the agents list, the view
header and main's notice) or is refused with one line (above). Narrow
(80x24) changes nothing but where the echoed command wraps.
