# CHD-378: what a team run, a task agent and the window have spent

**Board task CHD-373** (this page keeps quarry CHD-378's name). Written
2026-10-13, brought up to date on 2026-10-19 for claude-agent-acp 0.93,
codex-acp 2.2.2, the agents studied in CHD-433, and the background view
(CHD-424, CHD-2, CHD-462). Each passage that changed is marked
**Changed 2026-10-19**.

What changed, in short:

- **Codex's estimate is whole.** CHD-374 is closed. At 2.2.2 the answer to
  `session/prompt` carries the whole turn's tokens, and chord prices that.
  The "may undercount" caveat is gone.
- **More agents, and more ways of reporting nothing.** dimcode sends a
  session total, dirac's answer is a session total read as a turn's, and
  several agents report spend only off the standard path, or not at all.
  Any total needs the "not reported" rule, now for most agents.
- **A task's spend is still dropped.** Checked again on 0.55.2: main's
  `/cost` after a task reads its own three turns, and the task's block
  reads `Done (5 tool uses · 2s)`.
- **Tasks have left the agents list** for the background view (CHD-424),
  so option D now has two places: the task's block and its row there.
  CHD-2's `agent` items have no figure of their own (below).
- **The options stay A–F.** None is moot. Only D grew, by its background
  row.

The owner asked (2026-10-13) whether chord can say how much money a run or a
team spent. Today it says this for one session at a time: `/cost` reports
the session in front. This document covers what each kind of agent reports,
what chord does with it today, and the options for showing spend per team
run, per task agent and per window. **Nothing here is built.** The owner
picks among the options.

Every capture was taken with `bun chord:fake` in a `/tmp` directory, with
the fake `bugfix` team copied into `.chord/teams/`. The captures of today
are in `evidence/CHD-378/today/`, and the mocks are in
`evidence/CHD-378/mock/`. Each mock is laid out to exact width (120×40 and
80×24) from those captures, and only the part the option changes is
different. The fake spends $0.0125 and 2,000 tokens a turn, so the sums in
the mocks are the fake's figures, added by hand.

## What each agent reports

| | Each turn's tokens (the answer to `session/prompt`) | `usage_update` | Cost on screen |
|---|---|---|---|
| **claude** (`claude-agent-acp` 0.93) | in, out, cache read, cache written for the whole turn | after each turn: context `used`/`size` and `cost` = the SDK's `total_cost_usd`, in USD | **the agent's own**, cumulative |
| **codex** (`codex-acp` 2.2.2) | in (less cached), cache read, out, thinking, total, for the **whole turn** (Changed 2026-10-19, CHD-374) | context `used`/`size`, **no cost** | **chord's estimate**: the tokens × the model's price in `@pydantic/genai-prices` |
| **dimcode** (Changed 2026-10-19) | none | context and the **session's total cost**, with no opt-in; `0` for an unpriced model | the agent's own; a `$0` may mean "unpriced" |
| **dirac** (Changed 2026-10-19) | the **session's running total**, not the turn's, so chord counts it again each turn | context, and a cumulative `cost` when the provider gives one | the agent's own when sent; chord's token count overcounts |
| **grok, goose, fast-agent, qwen** (Changed 2026-10-19) | only in `_meta`, a custom notification or a text line | none | `not reported`: reading each one's private form would be a guess per agent |
| **bob, cline, cursor, zeroclaw, kiro, devin, Copilot** (Changed 2026-10-19) | none | none | `not reported` (Copilot's premium requests have no ACP cost) |
| **fake**, default | 1,000 in, 200 out, 800 cache read, 2,000 total | context and a cumulative `cost`, $0.0125 a turn | the agent's own |
| **fake** `--tokens-only` | the same tokens | none | chord's estimate (its models are named `gpt-5.3-codex` and `claude-haiku-4-5`, which the price data knows) |
| **fake** `--no-usage`, or any agent that says nothing | none | none | `not reported by <agent>` |

Some of this matters for any total:

- **Claude's figure already includes Claude's own subagents.** The Task
  tool's subagents run inside the same SDK query, so `total_cost_usd` counts
  them. chord's own `spawn_task` agents and long-lived children are separate
  sessions on separate adapter processes. No other session's figure includes
  theirs, so adding them up never counts the same money twice.
- **Claude's figure is per adapter process.** It is cumulative for the
  process. After `--resume` a new process starts. Today chord shows the
  record's last cost until the agent sends a new one. I have not checked
  live whether the new process starts from zero or carries the old total.
  That decides whether "the window's spend" can be told apart from "the
  session's whole life" for claude.
- **Codex's estimate covers the whole turn** (Changed 2026-10-19). The
  2026-10-13 concern that it priced only the last request is settled: at
  2.2.2 the answer's usage is the whole turn's, and `usage_update.used`,
  still the last request's, only sets the context shown (CHD-374).
- **`_meta.quota` is not money** (Changed 2026-10-19). claude and codex
  send a per-model quota to every client. It says how much of a plan's
  allowance is left, not what was spent, so no option adds it up.
- **dirac's tokens would count twice** (Changed 2026-10-19). Its answer is
  a session total, so a sum of turns grows faster than it spent. That is a
  defect of chord's reading, apart from this question. A total over dirac
  takes its `cost`, not its tokens.
- **Claude's background agents (CHD-2) have no figure of their own**
  (Changed 2026-10-19). They run inside the parent's query, so their spend
  is already in the parent's `total_cost_usd`. Their rows in the background
  view show none, and no total adds them again.
- **An estimate exists only for a model the price data knows.** On an
  unknown model the codex row shows tokens and no cost.
- **Every figure is in USD**, as each agent and the price data report it.
  ACP lets a cost carry another currency, and two currencies cannot be
  added. Nothing seen so far uses one.

## What any option has to decide

These come up in every option below, so they are listed once. Each is the
owner's to answer.

1. **What a sum says when one part is chord's estimate.** `/cost` already
   writes `$0.4120 (chord's estimate)`. That suffix doesn't fit in a list
   column, a tab bar or a `Done (…)` line. The mocks use `~$0.4120` there.
   In a total, `~` means at least one part of it is an estimate.
2. **What a sum says when one part reported nothing.** Leaving it out
   understates the total, and counting it as zero claims to know it was
   zero. The mocks show the known sum and say beside it how many reported
   nothing (`Total ~$0.4370 … 1 not reported`).
3. **Whether a closed agent still counts.** A member closed by its lead, a
   task that has ended, and a team run that has finished all spent money.
   If their rows leave the list, the only place left to show it is a report
   such as `/cost`.
4. **"This window" or "this session's whole life".** For a resumed
   session, the record holds what it spent before this window. Main's
   `/cost` already shows the record's figure. Should a window total count
   from when the window opened, or include everything the resumed sessions
   spent before?
5. **Tokens beside money.** Tokens from different models add up to a
   number, but it means little. Claude Code's task block says tokens and
   not money. Money is the only figure that adds up across models.

## The options

There are three needs: a team run, a task agent and the window. Each option
below meets one or more of them. They can be combined, since none rules
out another.

### A — the agent list shows each agent's spend

`mock/A-list-120x40.txt`, `mock/A-list-80x24.txt`

```
  ● tester needs your permission · ctrl+x a    Fake Large with a 1M… · 1% used
    main       fake                                                    $0.0250
    bugfix     team · fake  ✓ replied 14s ago                      run $0.0500
    ├─ tester  fake         ● permission 12s                           $0.0125
    └─ coder   fake         ✓ replied 13s ago                          $0.0125
```

Each row ends with its agent's figure, right-aligned to the status line's
edge. A team's row shows the whole run: the lead, its members and their
task agents, marked `run`.

- **Screen cost:** one column on every row, always visible and live. At 80
  columns it uses space the list already gives up, so nothing else is cut.
  It is dim, like the state column, and has no colour of its own.
- **Leaves out:** the window's total, closed agents (they leave the list),
  and the lead's own share, which the run figure absorbs. Money is shown at
  all times, which Claude Code's screen doesn't do.
- **Needs:** question 1's short form, since a suffix doesn't fit here.

### B — `/team show` shows each agent's spend and the run's total

`mock/B-team-show-120x40.txt`, `mock/B-team-show-80x24.txt`

```
 › /team show bugfix
   ⎿  bugfix · .chord/teams/bugfix.md · $0.0500 so far · working 20s on "Is…"

      lead    fake · fake-large  default      $0.0250  ✓ replied 20s ago  ← @…
      tester  fake · fake-small  acceptEdits  $0.0125  ● permission 19s   Bas…
      coder   fake · fake-large  plan         $0.0125  ✓ replied 20s ago  ← @…
```

The run's total goes before the job's quote on the first line, and each
agent's figure goes before its state, so both survive at 80 columns, where
the last column is already cut.

- **Screen cost:** nothing until asked, then one column and a few words in
  a report that is already there.
- **Leaves out:** anything not in a team: main, its tasks, other tabs. It is
  a snapshot, not live. A member that is `not opened` shows `—`.

### C — `/cost` reports the session, then the whole window

`mock/C-cost-120x40.txt`, `mock/C-cost-80x24.txt`

```
 › /cost
   ⎿  Total cost:   $0.0250
      Tokens in:    2,000
      Tokens out:   400
      Cache read:   1,600
      Session time: 41s

      This window             Cost     Tokens
      1 fake               $0.0875     14,000
        main               $0.0250      4,000
        Fix the tokenizer  $0.0125      2,000  task agent, ended
        bugfix             $0.0500      8,000  team run: lead $0.0250 · tester $0.0125 · coder $0.0125
      2 fake               $0.0125      2,000
      Total                $0.1000     16,000
```

The session's own rows stay as they are. Below them is one table: each tab
with its subtotal, the tab's own agent and each child under it (a task
agent, a team run with its members, a long-lived agent), then the window's
total. At 80 columns a team run's breakdown becomes `team run of 3`.

With an estimate and a missing figure (`mock/C-cost-mixed-*.txt`):

```
      This window             Cost     Tokens
      1 fake               $0.0250      4,000
      2 codex             ~$0.4120    188,400  chord's estimate from gpt-5.3-codex's price
      3 gemini       not reported          —
      Total               ~$0.4370    192,400  part chord's estimate; gemini not reported
```

- **Screen cost:** nothing until asked. When asked it uses one row per tab
  and per child, so with eight children in a tab it is long. The table
  could leave out a tab with no children, or the owner could make it its
  own command, such as `/cost all`.
- **Leaves out:** nothing that was reported. This is the one option that
  covers all three needs and closed agents, including where a figure is an
  estimate or missing. It is not live.

### D — a task agent's block, and its background row, show its cost

`mock/D-task-120x40.txt`, `mock/D-task-80x24.txt`

```
 ⏺ Agent(Fix the tokenizer) · fake · fake-small
   ⎿  Done (5 tool uses · 2.0k tokens · $0.0125 · 13s)
```

This is Claude Code's own `Done (… · 12.4k tokens · …)` with the money
added. A variant keeps Claude Code's line exactly, tokens only.

- **Screen cost:** a few characters on a line that is already there. It
  fits at 80 columns.
**Changed 2026-10-19:** a task is no longer on the agents list but in the
background view (CHD-424). Its row there carries the same figure after its
state, once its turn has ended (`mock/D-background-*.txt`):

```
    Fix the tokenizer  task · fake · fake-small  ✗ failed after 15s · $0.0125  main
```

The view's own shape is still open (CHD-462, Q43). The figure is part of
the state column, so it holds in every shape offered there, and at 80
columns it gives way before the state does. Monitors spend nothing, and
CHD-2's `agent` rows show none (above).

- **Leaves out:** any total. Main's `/cost` still doesn't count the task
  unless C does too. While the task runs, the block shows its work and no
  money, since the figure arrives when its turn ends.

**Settled for the build (CHD-373, 2026-10-19), D's words:**

- **Tokens** as Claude Code writes them: under 1,000 as they are
  (`850 tokens`), then one decimal with `k` (`2.0k`, `12.4k`), then `M`
  (`1.2M`). The count is the task's total when its agent gives one, else
  in, out, cache read, cache written and thinking added up.
- **The ended block:** `Done (5 tool uses · 2.0k tokens · $0.0125 · 13s)`,
  the tokens and money after the tool uses and before the time. Chord's
  estimate reads `~$0.0125`, as in C. When nothing was reported, that part
  is left out; tokens show when they were reported, the money when it was.
- **A row of a group** (`Running 2 agents…`) carries the same parts in the
  same order, once that task has ended. When the row does not fit, the
  tokens give way first, then the money, then the tool uses and the time,
  and only then is the title cut. **Why:** the money is what D is for,
  since a task's spend shows nowhere else, so it stays longest of the
  figures; the title says which task it is, so it is cut last.
- **The background row:** ` · $0.0125` (or `~$0.0125`) after the state once
  its turn has ended, the first thing on the row to give way at a narrow
  width.

### E — the tab bar shows the window's total

`mock/E-tabs-120x40.txt`, `mock/E-tabs-80x24.txt`

```
 chord   1 fake    2 fake                        $0.1000 · /tmp/chord-qa.4TUr
```

- **Screen cost:** one figure on a line that is already there, live.
- **Leaves out:** the breakdown, and any window with one tab, because the
  tab bar appears only from the second tab on. A long directory path
  competes with it for room at 80 columns.

### F — on quit, the window's total above the resume line

`mock/F-quit-120x40.txt`, `mock/F-quit-80x24.txt`

```
This window spent $0.1000: 1 fake $0.0875 (with 1 task and team bugfix), 2 fake $0.0125.
Resume this session with:
chord fake --resume 0f4c2a9e-5b1d-4e7a-9c3f-2d8b6a1e7f40
```

- **Screen cost:** none while working.
- **Leaves out:** everything until the window closes.

## How they cover the three needs

| | Team run | Task agent | Window | Live | Closed agents |
|---|---|---|---|---|---|
| A list | ✓ | — | — | ✓ | — |
| B `/team show` | ✓ | — | — | — | members only |
| C `/cost` | ✓ | ✓ | ✓ | — | ✓ |
| D task block and row | — | ✓ | — | when it ends | ✓ (the row until the next prompt) |
| E tab bar | — | — | ✓ (2+ tabs) | ✓ | ✓ |
| F on quit | — | — | ✓ | — | ✓ |

My recommendation as the designer, unchanged on 2026-10-19: **C with D**. C is the one place that
answers all three needs with the estimate and missing rules written out. D
puts in the task's block what Claude Code already shows there. The rest
are additions the owner can take or leave: A or E if money should be
visible all the time, B if the team view should carry it.

## Keys

`/cost` and `/team show` are commands, so C and B need no new key. A, D, E
and F add no action. If the owner wants A or E to be switched on and off,
that is a setting or a new key, and it goes into the shortcuts panel.

## Colour

No option adds a colour. In A and E the figures take the dim colour of the
list's state column and the tab bar's directory, which already read in
both a dark and a light theme. In C and D the figures inherit the report's
and the block's text. `~` and `not reported` are words, not colour, so they
survive a capture and a terminal without colour.
