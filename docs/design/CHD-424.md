# CHD-424: monitors and tasks in a list of their own

The owner (2026-10-17): the monitors an agent runs and the tasks it spawns
(`spawn_task`) go in a list of their own, apart from the list of agents and
team members under the prompt. CHD-2 then puts an agent's own background
tasks there too: Claude Code's Bash with `run_in_background` and a background
Agent, from claude-agent-acp's `asyncTasks` updates, each with a description
or command, a state, a time running and an end, and stopped through
`_session/async_task/stop`.

This page is a set of options for the owner, not a decision. Each question
has its options and the one I recommend, with the reason. Nothing here is
settled until the owner answers.

What the captures show:

- **A `spawn_task` task has no row at all.** It shows only as its
  `Agent(Fix the tokenizer)` call in the transcript and the messages it sends
  (`← from Fix the tokenizer · fake · report`). While it waits on the
  person's permission, nothing under the prompt says so; only `main ●
  permission` does. So for tasks this is a new row, not a move.
- **Monitors are rows after the agents** (CHD-243), with nothing between the
  two kinds but the `$` of the command. A child's monitor ends with
  ` · parser` in the child's colour; main's has no owner.
- **A monitor's command is cut at its end** (`properti…`, `"ERROR [r…`). The
  owner's standing rule is that text wraps and is never cut in the middle;
  the list predates it. Question (b) takes this up.
- **At 80×24 the list has four rows**, the queue's own limit
  (`agentsRowLimit`): teams fold to their lead, and with the `❯` on a monitor
  the rows above scroll away behind `… +3 more`.
- **An ended monitor or task leaves no row**: its end is a message in the
  transcript only.

## The rows the list will hold

| Item | Whose | Text it has | States | Stopped by |
| --- | --- | --- | --- | --- |
| monitor | any agent's session | description, command | running, events; ends: exit code, killed, timed out, stopped, flooded | chord (`x` today) |
| `spawn_task` task | any agent's session | title (`Fix the tokenizer`), job, runtime, model | working, asking permission or input; ends: report, failed | chord (cancel and close its session) |
| Bash in background (CHD-2) | a Claude session | description, command | running; ends: exit code, killed, stopped | `_session/async_task/stop` |
| background Agent (CHD-2) | a Claude session | description | running, progress; ends: done, failed, stopped | `_session/async_task/stop` |

A row's kind is one word: `monitor`, `task`, `bash`, `agent`. Codex and the
other adapters send nothing like `asyncTasks` that chord reads today; their
rows are monitors and tasks only.

## Colour roles

From `src/ui/theme/theme.ts`, as the agents list already paints them:
`warning` for asking (`●`), `error` for failed and a non-zero exit (`✗`),
`success` for done (`✓`), dim for running, stopped and the heading, the
`permission` role for the `❯`, and an owner's name in its agent colour
(`agents`), `main` dim. No new role.

## (a) Where the list lives, and its key

**A1. Under the agents list, a block of its own.** Below the agents rows, a
dim `background` heading and the rows under it. `↓` from an empty prompt
goes into the agents as today and on past them into the background rows; `x`
stops the focused row. Visible whenever something runs, with no key to
press. (`mock/a1-120x40.txt`)

```
  ● tester needs your permission · ctrl+x a to go · ? for shortcuts      Fake Large with a 1M context window · 2% used
    main               fake · Fake Large with a 1M context window · medium                ✻ working 6s
    bugfix             team · fake · Fake Large with a 1M context window · medium         ✓ replied 2m ago
    ├─ tester          fake · Fake Small · medium                                         ● permission 1m 47s
    └─ coder           fake · Fake Large with a 1M context window · medium                ✓ replied 2m ago
  background
    Fix the tokenizer      task · fake · Fake Small   ● permission 13s                     main
    dev server errors      monitor                    running 14s · 1 event                main
    CI run 4812            monitor                    running 13s · no events              main
    parser tests           monitor                    running 2m 3s · 4 events             parser
```

**A2. A panel opened by a key.** Under the prompt only the agents stay. The
status line counts what runs (`4 in background · ctrl+t`); `ctrl+t` (free
today) opens the rows in place of the agents list, as `/` opens the commands
there, with its own hint line; `esc` closes it. (`mock/a2-120x40.txt`,
`mock/a2-open-120x40.txt`)

```
  ● tester needs your permission · ctrl+x a · 4 in background · ctrl+t Fake Large with a 1M context window · 2% used
```

```
  background · ↑ ↓ to pick · x to stop · esc to close                    Fake Large with a 1M context window · 2% used
  ❯ Fix the tokenizer      task · fake · Fake Small   ● permission 13s                     main
    dev server errors      monitor                    running 14s · 1 event                main
```

**A3. A full-screen picker, as the sessions picker (`ctrl+x w`) is.** The
status line counts as in A2; `ctrl+x b` opens a picker over the transcript
with every item, running and ended, of every tab; `x` stops, `enter` goes to
the tab and the call that started it. Most room, furthest from the prompt.

**Recommendation: A1.** CHD-2's complaint is that nothing says a task still
runs; a list behind a key keeps that true until the person thinks to look.
A1 keeps the place and the `↓ … x` path CHD-243 settled, so nothing learned
is lost, and the heading is what makes it a list of its own. A2 is the
better fallback if the owner wants the space under the prompt for agents
alone.

## (b) What a row shows

Every option has the same columns: what it is (description or title), its
kind, its state with its time, whose it is. They differ in the text that does
not fit, since the owner's rule is that text wraps and is never cut.

**B1. One line, no command; the name wraps.** `name  kind  state  owner`. A
task's kind carries its runtime and model (`task · fake · Fake Small`). The
command or job is not on the row: `enter` on a row scrolls the transcript to
the call that started it, where it is drawn whole. A name longer than its
column (24 cells) wraps inside the column onto a second line.
(`mock/b1-ended-120x40.txt`)

```
  background
    Fix the tokenizer      task · fake · Fake Small   ✗ failed after 1m 12s                main
    dev server errors      monitor                    running 4m 2s · 3 events             main
    CI run 4812            monitor                    ✗ exit code 1 after 3m 12s           main
    Run the parser suite   bash                       running 41s                          main
      in watch mode
    Explore the parser     agent                      ✓ done in 2m 4s                      parser
```

**B2. One line as today: the command after the name, cut at its end with
`…`.** Smallest change, and the command is in sight; it keeps a cut the
owner's rule forbids, and a task's job (a paragraph) would be cut the same.

**B3. Two lines: the row, then the command or job under it, dim, wrapped
whole.** Nothing is ever cut, and the person sees exactly what runs. A row
takes two to four lines; at 80×24 that leaves room for one or two items.
(`mock/b3-120x40.txt`)

```
    dev server errors      monitor                    running 14s · 1 event                main
      $ sleep 1; echo "ERROR [router] POST /login 500: Cannot read properties of undefined (reading 'trim')"; echo "
      at validate (src/routes/login.tsx:41:22)"; sleep 600
```

The states, in every option: `running 2m 3s` (with `· 3 events` for a
monitor, `· 5 tool uses` for a task when known), `● permission 13s` or
`● input 13s`, and the ends `✓ done in 2m 4s`, `✓ reported after 4m`, `✗
failed after 1m 12s`, `✗ exit code 1 after 3m 12s`, `■ stopped`, `✗ killed by
SIGKILL`, `✗ timed out`, `✗ flooded` (CHD-243's ends). The owner is always
named: `main` dim, a child in its colour.

**Recommendation: B1.** The row is for seeing and stopping; one line each
keeps a dozen items in view at 120×40. Nothing is cut: the name wraps, and
the command and job are whole one key away in the transcript, where they
already are. B3 is right if the owner wants the command in sight; B2 breaks
the standing rule.

## (c) How an item is stopped

**C1. `x` on the focused row stops it at once, whatever its kind.** As
CHD-243 settled for monitors: no arming. The end then shows on the row (`■
stopped`) and in the transcript as today. A row whose agent offers no stop
(an `asyncTasks` item where the adapter has no `_session/async_task/stop`)
says so on the status line when `x` is pressed.

**C2. `x` stops a monitor at once, but asks first for a task, a Bash or a
background agent,** whose work is lost: the row's state turns into `stop?
x again · esc` (warning) until the second `x` or `esc`.

**C3. As C1, and `shift+x` stops every running item of the focused row's
owner,** for an agent whose monitors and tasks all go with it.

**Recommendation: C1.** One key, one meaning, as the list has today; `x` is
a deliberate key away from the arrows, and a stopped task is told to its
agent, which can start it again. C2 if the owner wants a guard on work that
is lost.

The shortcuts panel line becomes `x to close an agent or stop a background
item` (`src/ui/shortcuts/keys.ts`, action `agents:close`, the key unchanged);
with B1, `enter` on a background row gets its own line, `enter to see where
it started`.

## (d) What stays in the agents list, and what moves

**D1. Agents stay, everything that runs in the background moves.** The
agents list keeps `main`, each long-lived child and each team's lead and
members, drawn only while there is a child, as today. Every monitor, every
`spawn_task` task and every CHD-2 item moves, a child's too, with the owner
column saying whose.

**D2. As D1, and each agent row says how many it has in the background**
(`2 in background`, dim, after its state), to tie the two lists together.

**D3. Items nest under their owner in the agents list**, with the `├─` tree
the teams use, and the background block holds only main's. Whose it is
needs no column; it splits what the owner asked to be one list.

**Recommendation: D1.** It is the owner's split as stated; the owner column
already says whose each item is, so D2's count repeats it in a row that
fights for width at 80.

## (e) 80×24 with rows in both lists

Today both kinds share four rows.

**E1. One shared limit, as today.** Four rows for the two blocks and the
heading: the agents fold their teams, the background folds to `… +N more`.
Almost nothing of either is in sight.

**E2. Each list its own limit**, four rows each, plus the heading: up to nine
of 24 lines under the prompt. (`mock/e2-80x24.txt`)

**E3. The list without the keys folds to one line.** Unfocused, the agents
show as today and the background is one summary line, the most urgent first;
with the `❯` in the background, it takes the rows and the agents fold to one
line. At most the limit plus one line. (`mock/a1-80x24.txt`,
`mock/a1-focused-80x24.txt`)

    bugfix             team · fake · 3 agents      ● tester: permission 1m 56s
  background  ● 1 task asking · 3 monitors running

**Recommendation: E3.** The transcript keeps its lines, the summary still
says that something runs and that a task is asking, and `↓` brings the rows
in full. The summary line wraps rather than cuts when it grows past the
width.

## (f) How long an ended row stays

The task asks what each row says of how it ended; that needs ended rows to
stay for a while. Today an ended monitor's row goes at once.

**F1. Until the person next sends a prompt in that tab.** The end is seen,
then the row goes.

**F2. For a fixed time, a minute, then it goes.**

**F3. Until `x` on the ended row clears it**, with the block's heading
counting the ended ones.

**Recommendation: F1.** It matches how `✓ replied` and `← message` stand on
an agent row until the person has been there, and needs no key of its own.

- With A2 or E4, `ctrl+t` to open the panel; with A3, `ctrl+x b`. Each is
