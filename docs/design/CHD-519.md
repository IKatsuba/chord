# CHD-519: @@ completes the agents the picked session can message

The owner (2026-10-24/25, CHD-519 and Q211): `@@` names an agent in the
prompt, while `@` continues to find files. Completion offers exactly the
open recipients of `send_message` from the picked session. Task agents and
unopened runtimes never appear. A sent mention is ordinary text to the
picked session: it attaches nothing and routes nothing. A name with spaces
is inserted quoted, `@@"bugfix 2"`.

Main approved this design before the screen was built.

## The list

Use the existing file finder's placement and window: immediately below the
prompt border, replacing the status line while it is open, with the same
horizontal padding, six rows at 80×24 and ten at 120×40. The ordinary agents
list keeps its existing placement and rules. No panel title, border,
selection glyph, extra footer or new column is added to the completion.

Each row contains only the recipient's name, without `@@` or quotation
marks. No session title, runtime, model, state, age or unread mark: this is
choosing a name to insert, and the agents list already carries those
other details. Names with spaces are shown as names, `bugfix 2`.

The highlighted row takes `permission`, exactly as a selected file does.
Other child names use their existing `agents` palette colour, without bold;
`main` uses dim terminal text. A highlighted name uses `permission` rather
than its agent colour, so there is one unambiguous selection. No new role
is added to `src/ui/theme/theme.ts`. Long names are cut to the row width,
as file paths are today, and insertion still writes the whole name.

With an empty query, retain the agents list's order, removing the picked
session and everyone it cannot message. This is stable opening order with
members beside their lead, not alphabetical or ordered by urgency. With a
query, use the file finder's case-insensitive fuzzy matching from its first
character; best matches first, using its existing length tie-break and
stable source order otherwise. Typing resets the highlight to the first
match, as it does for files. The list follows openings, closings and a
change of picked session; a closed recipient cannot be accepted from a
stale row.

## Who is offered

Reachability is the existing `send_message` rule, not a new roster:

- Main sees its open long-lived children, including team leads, but not
  their nested members.
- An ordinary child sees its parent, normally `main`, not its siblings.
- A team lead sees main, its open members and other open runs' leads.
- A team member sees its own lead and its run's other open members.

The picked session itself is absent. A saved but unopened team, a closed
member, a task agent and an installed runtime without an open session are
absent. The completion must use the same recipient scope as message
routing; it must not infer reachability from visual proximity or include
all rows of the window indiscriminately.

## Empty and no match

Keep one nonselectable dim terminal-text row in the same place, at both
sizes. With no reachable recipients, show `No agents to mention`. With
recipients but none matching the query, show `No matching agents`.
There is no highlight, spinner, error colour or instruction to open an
agent. This gives feedback that `@@` was understood in an empty window.

```text
│ › @@                                                                         │
╰──────────────────────────────────────────────────────────────────────────────╯
  No agents to mention
```

```text
│ › @@zzzz                                                                     │
╰──────────────────────────────────────────────────────────────────────────────╯
  No matching agents
```

Unlike the file finder, which closes when no files match, these one-line
empty states remain until the mention ends or Esc dismisses them. Enter
sends the draft as typed to the picked session; Tab does nothing. The row
is feedback, never a choice. No network lookup or loading state is needed:
the candidates are already-open sessions.

## Typing and accepting a name

`@@` is recognized where the file trigger is: at a line's start or after
whitespace, at the cursor. A midword `name@@parser` does not open a list.
The second `@` switches the file completion to agent completion immediately;
it is not part of a file query. `@@` never attaches a file resource link,
even if a real file shares the name. Single-`@` file behavior stays as it is.

An unquoted query ends at whitespace: `@@bug` offers bugfix and bugfix 2.
An opening double quote permits spaces: `@@"bugfix 2` searches for the name
`bugfix 2`; quote characters are not part of the matching query. A closing
quote ends the completed name. While the cursor is just before that closing
quote, completion can still replace the name; beyond it, normal typing
continues without reopening the list.

Tab or Enter inserts the selected whole name, replacing the current `@@`
query (and any existing closing quote), then one separating space. It
leaves the cursor after that space. Names containing whitespace are quoted;
others are not. Picking bugfix 2 from either query writes exactly:

```text
@@"bugfix 2"
```

Picking parser writes `@@parser `; text before and after the current mention
is kept. As with file insertion, acceptance while editing inside a token
replaces that token, rather than leaving a suffix attached to the chosen
name. No special mention styling or chip replaces the literal prompt text.
A manually typed complete quoted mention is sent verbatim too.

## Keys and shortcuts

- ↑/↓ moves the highlight and scrolls within the completion's existing row
  budget, exactly like the file finder. Existing completion rebindings
  apply; no second set of bindings is introduced.
- Tab and Enter both accept the highlighted agent and close the list.
  Neither sends the prompt on that press. A subsequent Enter sends the
  resulting text to the picked session, as it does after adding a file.
- Esc closes the completion without removing or changing its draft text.
  The next Enter sends that text. Dismissal and reopening follow the file
  finder's existing rules.
- With either empty-state message, Tab does nothing; Enter sends the draft;
  Esc dismisses the message. With no completion, all normal prompt keys,
  including Tab steering during a running turn, retain their behavior.

Update the shortcuts panel's existing shared lines, without adding height:

| Key | Description |
| --- | --- |
| `/ @ @@` | `for commands, files or agents` |
| `↑ ↓` | `to pick a completion` |
| `tab enter` | `to add a file or agent` |
| `esc` | `to close completions` |

Keep the existing `tab to complete a command` line. Check the complete
shortcuts panel still fits at 80×24; these replacements are no wider than
its current longest lines. Every acceptance/move/dismiss action remains
listed and uses the same completion key routing as the file finder.
