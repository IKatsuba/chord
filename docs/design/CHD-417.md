# CHD-417: telling an agent its chord call was cut off

When a steer aborts a Claude session's tool batch, a chord call in it can
fail as interrupted with nothing served: it never reached chord, so a
`send_message` in it was lost. The owner decided (Q15, 1 with 3) that chord
then tells the agent at its next turn. This section gives the words of that
note and what the person sees.

## The note to the agent

It is a message from chord, wrapped as chord's other notes are
(`<message from="chord">`), and it goes ahead of whatever starts the
agent's next turn: the person's prompt or a teammate's message, since a
team lead's next turn is often a message. It reads like chord's other
notes to agents (`… did not start: …. It takes no messages; open_agent
starts another.`): what happened, in the past tense, then what to do, with
no apology and no guess at why.

For `send_message`, it names the recipient and quotes the start of the
text, its first line cut at 60 characters with `…`, so an agent that sent
several messages knows which one was lost:

```
Your send_message to @main was cut off before it reached chord and was not delivered ("CHD-393: the owner has a question on Q8…"). Send it again, on its own.
```

For any other chord tool, named as the agent called it:

```
Your open_agent call was cut off before it reached chord and did nothing. Call it again if you still need it, on its own.
```

"On its own" is the owner's rule from Q16: send_message goes alone, never
in a parallel batch. If several of chord's calls were cut off in one batch,
there is one note with one such sentence per call, a line each, in the order
the calls were made.

## What the person sees

The note itself is not drawn as a row: chord's notes that go ahead of a
turn are not drawn today (`aside`), and a `← from chord` row would repeat
what the cut-off row already says. The person sees it on the cut-off call's
own row, where today there is a blank or `Failed` after the text. As
CHD-387 draws a refusal, the sentence goes after the body and its fold, in
`error`, never folded, with the arrow in `error`:

```
 → to @main
   ⎿  CHD-393: the owner has a question on Q8. The options:

      1. Draw the headline whole and wrap it.
      2. Cut it at the edge, as today.
      … +4 lines (ctrl+o to expand)
      Not delivered: cut off before it reached chord. chord tells the agent at its next turn.
```

For another chord tool, the row's sentence is `Cut off before it reached
chord, so it did nothing. chord tells the agent at its next turn.`

At 80 columns the sentence wraps to a second row, which is fine for a line
that is never folded:

```
 → to @main
   ⎿  CHD-393: the owner has a question on Q8. The options:

      1. Draw the headline whole and wrap it.
      2. Cut it at the edge, as today.
      … +4 lines (ctrl+o to expand)
      Not delivered: cut off before it reached chord. chord tells the agent at
      its next turn.
```

A resumed session draws the same sentence from its record: a chord call
that failed as interrupted with no served entry.

## Colour roles and keys

The arrow and the sentence are `error`; the body stays dim, as CHD-387
draws it. No new action and no new key.

## The fake

To see it in tmux, the developer adds a scenario that sends a chord call
cut off as Claude's adapter cuts it: a `tool_call_update` failed with
`_meta.claudeCode.nonExecutionKind` `interrupted`, an empty error, and no
request to chord's server; then a next turn, so the note can be seen going
ahead of it.
