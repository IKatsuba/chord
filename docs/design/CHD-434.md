# CHD-434: telling the person, once, that dimcode can start other agents

Decided by the owner (2026-10-18): when a dimcode session starts, chord
shows a one-time notice that dimcode may start other CLIs without their
approvals, and how to turn that off; the guide says the same in dimcode's
entry (writer's, later). The owner left where it shows, what one-time
means and its words to the slice.

**Settled in the slice** (the lead, 2026-10-21): option B, the box above
the prompt; per machine until dismissed, recorded in chord's user
directory. **Recommended here, and a change to the owner's "when a dimcode
session starts":** the box shows when a dimcode session's `permission`
option is first seen at anything but `read-only`, not at every start (see
[When](#when)).

## The facts

From `docs/agent-capabilities.md`, dimcode, Custom, and dimcode 0.5.19's
published package (read by the lead's request, nothing run):

- Since 0.5.19 each dimcode session looks on PATH for 18 CLIs and its
  `agent` tool may start them as its subagents with their approvals
  bypassed (claude in `bypassPermissions`, ACP CLIs answered
  `allow_always`), on the person's own accounts. Nothing they do reaches
  chord's permission box.
- **There is no single off switch.** Each CLI is off with
  `externalAgents.<type>.enabled: false` in `~/.dimcode/v2/config.json`; a
  CLI missing from the file is on. The 18 types: antigravity, claude-code,
  codebuddy, codex, cursor, devin, droid, goose, grok, hermes, kimi, kiro,
  mcode, mimo, opencode, pi, qoder, zcode. dimcode's own TUI edits the file
  with `/external-agents` (`/agents`). Even when off, dimcode still runs
  `<bin> --version` on PATH.
- **dimcode's ACP `permission` option** has three values: `read-only`, a new
  ACP session's default, refuses the `agent` tool without asking;
  `workspace-write` asks the person first; `full-access` runs it without
  asking.

How chord meets that option (developer, from chord's code):

- `/config` lists it as a generic option, with dimcode's own name and
  values. The status line does not show it.
- chord reads its value from the new, load and resume answers, and hears
  every change: `config_option_update`, and the answer to its own set.
- **chord never sets it on its own**: its starting values cover model,
  effort and mode only, `permissionMode` goes to the mode, and nothing is
  replayed on resume. It changes only when the person sets it in `/config`.
  (Unchecked: if dimcode tagged it `category: "mode"`, chord would take it
  for the mode; dimcode's mode is `agent` / `goal`, so it is not expected.)

So **at a dimcode session's start in chord nothing is bypassed**: the
option is `read-only` and the `agent` tool is refused. The risk begins when
the person sets `full-access`, or `workspace-write` and then allows the
`agent` tool once its request reaches them.

## When

### W1: at the session's start, as the owner first said

The first dimcode session that starts shows the box.

- **Against it:** at that moment chord's dimcode session is `read-only` and
  can start nothing, so the box warns of what is not happening, and a
  person who dismisses it then gets no word when they later turn on
  `full-access`, the moment it matters. The words would have to be
  conditional ("if you set…"), which reads as a manual, not a warning.

### W2: when the option is first seen at anything but read-only (recommended)

The box shows the first time chord sees a dimcode session's `permission`
at `workspace-write` or `full-access`: as the person picks it in `/config`
(the box opens as `/config` closes), or at a start or resume whose answer
already carries it (a dimcode that keeps another default in its own
config).

- **For it:** it shows at the moment the risk begins, about the value just
  chosen; a `read-only` user is never stopped by it. chord sees every
  change already (`config_option_update`, the set's answer), and never sets
  the option itself, so the person's own choice is what brings it.
- **Against it:** it is not "when a session starts", so it is a change to
  the owner's wording, to be confirmed.

## What one-time means (settled)

Per machine, until dismissed. `1` records it in chord's user directory
(beside the user settings file, never the project's) and the box is not
shown again on this machine; `2` and `esc` record nothing, so it shows at
the next time W2 (or W1) fires.

## To whom

- The tab the dimcode session is in; for a dimcode child, task or team
  member, the tab its permission requests reach (the parent's or the
  lead's). Under W2 a child's option changes only if the person set it, so
  it is mostly the front tab.
- Two dimcode sessions firing before the person answers make one box.
- The session is not held: the box holds the keys, so typing does not reach
  the prompt until it is answered.
- A permission or form arriving while it is open hides it, as it hides
  every picker (CHD-462), and it comes back after.
- `-p` (no screen) says the two paragraphs once on stderr, `chord: `
  ahead, and records nothing.

## Words

- Title: `dimcode can start other agents`.
- First paragraph: `With its permission option at full-access, dimcode may
  start other agent CLIs it finds on your PATH, such as claude, codex and
  cursor, as subagents of its own, with their approvals bypassed and on
  your own accounts. At workspace-write it asks you first, and once you
  allow it, the same holds. Nothing those agents do reaches chord's
  permission box.`
- Second paragraph: `To turn a CLI off, set externalAgents.<type>.enabled
  to false in ~/.dimcode/v2/config.json (claude-code, codex, cursor, …), or
  use /external-agents in dimcode's own TUI. Or keep the permission option
  at read-only in /config, where dimcode refuses its agent tool.`
- Choices: `1. Got it, don't show this again`, `2. Show it again next time`.
- Hint: `Enter to pick · 1–2 · ↑↓ to move · Esc to show it again next time`.

The words say what dimcode does at each value, not that it will; the
three CLIs named are the likeliest ones here, and the full list is the
guide's. `--version` probing while off is the guide's, not the box's.

**B (settled), per machine until dismissed (settled), shown under W2**:
