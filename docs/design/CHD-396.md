# CHD-396 — a copied reply joins the lines chord wrapped

chord's markdown (`src/ui/transcript/markdown.ts`) lays a reply out to its
width through markdansi, so a paragraph or a list item reaches OpenTUI as
rows with real newlines. A drag over a wrapped item copies those newlines
and the hanging indent, and the copy differs between 80 and 120 columns.
The owner's case (comment #8154):

```
- package.json:3: пакет @chorded/chord версии 0.54.1, нужен Bun ≥ 1.4.2. check запускает
  check:static и затем тесты.
```

copied with a newline after «запускает» and two spaces. The owner chose
(a): markdansi no longer wraps a paragraph or a list item. Its text goes to
OpenTUI whole with `wrapMode: 'word'`. An item's indent is layout
(`paddingLeft`), and its marker is a text of its own that is not
selectable. The wrap is then soft, and OpenTUI joins it on copy, as it
already does for a prompt. Rewriting the copied text was declined.

Two units follow on the owner's later answers. A code box's border and
padding become OpenTUI layout, so a code block copies as bare code (Q150,
unit 3); a table keeps its drawn grid. The blank row between blocks becomes
a row a copy carries (Q151, unit 4). A list inside a quote stays as
markdansi draws it: its items wrap with no hang, and a copy keeps their
markers (Q160, the owner's option 1).

## What changes on screen

Almost nothing, only where lines break:

1. **A paragraph** wraps where OpenTUI's word wrap puts the break, and
   chord takes OpenTUI's break points as they are (Q157). OpenTUI breaks
   on spaces, as markdansi did, and also after `/`, `-`, `.`, `,`, `:` and
   `(`. So a path, a URL or a hyphenated word that reaches the edge can now
   break inside it on screen: `src/session/` at the end of one row and
   `session.ts` at the start of the next. The copy still joins it whole.
   Rows break at the width the text really has on screen. markdansi was
   given a narrower width than that (for a message, the width less 5), so a
   word can move up a row even where the break is at a space. A
   word wider than the row is cut at the edge and goes on below. Today
   markdansi lets it run past the edge. The mocks below break at spaces
   only. On the running screen a row may run further and end after one of
   those characters.
2. **A heading** already reaches OpenTUI unwrapped (markdansi does not wrap
   headings), so it does not change. It stays bold, and an H1 stays bold
   and underlined.
3. **A quote's paragraph** wraps inside the bar OpenTUI already draws (a
   left border). The bar runs the full height, as now. A code box inside a
   quote keeps today's rows, borders included (unit 3, under "A code box
   inside a quote").
4. **A list item's wrapped lines hang under its own text**, at the width of
   its own marker:
   - `- ` hangs 2, as now.
   - `2. ` hangs 3. Today it hangs 2, one left of the text.
   - `10. ` hangs 4. Today it hangs 2.
5. **A nested list sits under its parent item's text**, and its wrapped
   lines hang under its own text. markdansi's limit goes away: a nested
   item's wrapped lines no longer fall back to the outer item's indent, and
   a third level no longer sits at the second level's indent.
6. **A code box inside an item** starts at the item's text column (3 under
   `1. `, where today it is 2) and is as wide as what is left beside it.
   It is drawn as unit 3 draws a box.

The rest is kept as it is:

- The markers keep their look: bullets `-`, numbers as written (`8.`,
  `9.`, `10.`, left-aligned at each item's own width), dim (`listMarker`).
  A task item's `[ ]` or `[x]` is its marker, as markdansi draws it today
  (no bullet).
- A loose list keeps its blank row between items.
- Emphasis, inline code (`inlineCode`), links with their address after
  them (`link`, underlined) and the quote's dim italic keep their roles
  from `src/ui/theme/theme.ts`.
- A soft line break in the source joins with a space, as markdown says. A
  hard break (two trailing spaces, or `\`) stays a new row and copies as a
  newline.

## What a copy is

A drag that covers the whole case, released, copies:

| Case | Copy |
| --- | --- |
| A wrapped paragraph | One line, its soft wraps joined with the space that was there. The same at 80 and 120. |
| A heading | Its text, one line. |
| A quote's paragraph | Its text, one line; the bar is a border and does not copy. |
| A list | One line per item, each item's text whole, with no marker and no indent, at any depth: `package.json:3: … check runs check:static and then the tests.` and then `a nested item long enough … under its own text`. A drag out of a nested item to the next outer item needs one motion event per nesting level: a single event and then a release copies the nested item alone (Q163). |
| A hard break | A newline where the source had one. |
| A code box, alone or in an item | Its code alone, line for line (unit 3). |
| A code box in a quote, or a table | Today's rows, borders included. |
| Two blocks | Joined with a blank line where the screen shows a blank row (unit 4). |

The marker does not copy, because it is a text of its own that is not
selectable, like the gutter and the `⏺`. A list copied with its markers is
not in this slice. If the owner wants one, that would be markdown source,
not the screen.

## States

- **Streaming.** The reply is rendered whole again on each chunk, as now. A
  paragraph growing at its end reflows within its own text. An item that
  is still arriving is a list item already, as markdansi has it now.
- **Waiting on the person, error.** Not touched: a reply has no such state
  of its own.
- **Narrow.** At 80 the cases read as above. At the width of a pane in the
  background view, the same rules apply at that width. A row too narrow for
  a marker and one word still shows the marker, and the word is cut at the
  edge.
- **Resize.** A paragraph and an item reflow as OpenTUI lays them out
  again. Tables are still re-rendered at the new width, as now; a code box
  is laid out again by OpenTUI (unit 3).
- **Selection.** The highlight (`selection` role) covers the item's text
  cells and never the marker or the indent, as it already leaves the gutter
  out. A drag that starts on a marker starts nothing, as one on the gutter
  does (CHD-172).

## Unit 3 — a code block copies as bare code (Q150)

The owner chose (2): the box's border and padding are OpenTUI layout, a
`<box>` with `border`, `borderStyle='single'` and `paddingLeft` and
`paddingRight` of 1, and the code is a `<text>` inside it. A drag over it
copies the code alone. A table keeps its drawn grid, and copies it.

### The box

As today, but for the label, which sits one cell further right:

```
before                              after
┌ sh ─────────────┐                 ┌─ sh ────────────┐
│ deno task check │                 │ deno task check │
└─────────────────┘                 └─────────────────┘
```

- **Border.** OpenTUI's single line, the same characters as today. Its
  colour is `DIM_BORDER` (`src/ui/theme/text.ts`), the quote's bar's, where
  today the box is the terminal's faint text. On a dark theme both read as
  the same grey. A table's grid stays faint, so a box and a table beside
  each other may differ by a shade. With no colour (`NO_COLOR`, or not a
  terminal) the box is drawn as the quote's bar is then.
- **Label.** The fence's language, its first word, without markdansi's
  brackets, as today. It is the box's `title`, ` sh ` with a space each
  side, left-aligned, in `DIM_BORDER`. OpenTUI draws a title one `─` after
  the corner and has no setting to move it, so `┌─ sh ──┐` where today is
  `┌ sh ───┐`. Nothing is drawn by chord around OpenTUI's border. A fence
  with no language has no title: `┌────┐`. The label is part of the border,
  so it is not selectable and does not copy.
- **Width.** The widest code line and 4 cells (2 borders, 2 padding), at
  least the label and 6, so the title fits (OpenTUI leaves out a title wider
  than the box less 4): a one-letter `typescript` block is
  `┌─ typescript ─┐`, 16 cells, as today. Never wider than the column it is
  in. Where the column is narrower than the label and 6, the box takes the
  column and OpenTUI leaves the label out; today the top row would run past
  the edge.
- **Code.** Highlighted as today, by highlight.js, whole and then laid out.
  Blank lines at either end of the code are the agent's and stay.
- **A line too long for the box** is cut at the box's inner edge and goes on
  below at the same column, as today (`wrapMode: 'char'`, no word breaks).
  The cut is now soft: a copy gives the line whole, as the agent sent it.
  Today's copy breaks it with a newline and the border.
- **Padding.** Today each line is padded with spaces to the box's width,
  and the spaces copy. Now the space beside the code is layout: a line
  copies with no spaces after it but the ones the agent sent.

### What a copy is

| Drag | Copy |
| --- | --- |
| A whole box, top border to bottom | Its code, line for line, joined with newlines; no label, no `│`, no padding. |
| Part of a box | The characters dragged over; a line cut at the edge joins with its rest. |
| From a paragraph into a box and on out of it | The paragraph, the code's lines and the next paragraph, each block on its own line, with a blank line between where the screen shows a blank row (unit 4). |
| A drag that starts on the border or the label | Starts nothing, as one on the gutter (CHD-172). |

The highlight (`selection` role) covers the code's cells, never the border,
the label or the padding.

## Unit 4 — a copy keeps the blank row between blocks (Q151)

The owner chose (2) and (3): the gap between blocks becomes a row a drag
selects, so a copy across two blocks carries the blank line the screen
shows. It is layout only; the copied text is not rewritten. OpenTUI is
asked upstream to copy an empty selected row as an empty line: the gap's
repro is a comment on OpenTUI PR #1403, and the wrap ask is OpenTUI issue
#1749.

Nothing moves on screen: every blank row is where it is today, and no new
one appears. What changes is that a copy carries it.

### Which gaps

| Gap | On screen | Copy across it |
| --- | --- | --- |
| Between two top-level blocks of a reply (paragraph, heading, list, quote, code box, table, link definitions), any pair | One blank row, as today | A blank line |
| Between two items of a loose list, and between two blocks of a loose list's item | One blank row, as today | A blank line |
| Between two items of a tight list, between an item's text and its nested list or its code box | No row, as today | A newline, no blank line |
| Inside a quote (between its paragraphs, or a paragraph and its code box) | What markdansi draws, as today: no blank row | A newline, no blank line (Q160: a quote stays one text) |
| Before the first block and after the last | None | Nothing |
| Between a reply and what follows it in the transcript (a tool call, the next prompt) | The transcript's own spacing | Not this unit: as CHD-172 copies it |

So a copy has a blank line exactly where the screen shows a blank row
inside a reply, and nowhere else.

### What a copy is

The fake's `markdown` reply, dragged from `That is the whole loop.` to the
end, copies:

```
That is the whole loop. To land a change:

Run the checks:
deno task check
Commit on main once every check has passed and the tree is clean, so whoever picks the work up next starts from a build that runs.

Then build the binary with:

deno task compile --all
for bin in dist/*/chord; do echo "built $bin"; done
```

(Units 3 and 4 together; markers do not copy, per unit 2. Each blank line
here holds one space, under "The blank row".)

A drag that starts or ends on a blank row starts or ends the selection
there, as on any row of text.

### The blank row

Each gap above is a selectable `<text>` one row high holding one space, in
place of `gap={1}` (Q186, the owner's option 1). OpenTUI 0.6.6 leaves an
empty `<text>` out of a selection, so an empty row would copy as nothing,
as `gap` does now. A row of one space copies as a line holding that space:
`first\n \nsecond`. The copied text is not rewritten to drop it.

- On screen the row is blank, as today; the space takes no colour.
- Under a selection that crosses it, the highlight (`selection` role) covers
  that one cell, at the row's first column in the block's column (the
  reply's text column at the top level, the item's text column in a list).
- A tight list and a quote get no such row, as they have no blank row.
- The space goes once OpenTUI copies an empty selected row as an empty line
  (the comment on OpenTUI PR #1403, OpenTUI issue #1749); then the row holds
  nothing and a copy's blank line is empty.

### States

- **Streaming.** A block that arrives adds its blank row before it, as the
  gap does today.
- **Narrow, resize.** Unchanged: a blank row is one row at any width.
