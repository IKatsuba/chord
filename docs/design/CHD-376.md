# CHD-376: the effort in the status line

Since CHD-354 the agent list and the `Open`/task headlines name each agent's
effort. The status line under the prompt still names only the model and the
context. It reads `Fake Small · 1% context used` while the list beneath it says
`tuner … · high`. Claude Code puts the effort on its prompt's footer
(`◐ medium · /effort`). chord's status line is the matching place: its right
side is already "what the agent says about itself".

Taken with `bun run chord:fake` and the prompt `agenteffort`. Main is on
`medium` and the child `tuner` is on `high`. Every "before" capture and every
mock is under `evidence/CHD-376/`, and each mock is its capture with only the
status line changed.

## The shape

The effort goes on the right, between the model and the context, in the order
the agent list uses (`model · effort`):

```
Fake Large with a 1M context window · medium effort · 1% context used
```

- **Wide, the word `effort` follows it.** Away from the list, a bare `high`
  beside `1% context used` could be read as the context running high. Once the
  line is short, the word goes along with `context`. It reads
  `… · medium · 1% used`, the way the list says it.
- **The effort's id, as the list shows it.** Whatever the agent reports as
  current (`medium`, `xhigh`, `minimal`), unchanged. The same word appears in
  the list, the headline and the status line.
- **No glyph.** Claude Code's `◐` stands for a fixed scale of its own levels.
  An ACP agent names its efforts freely (Codex has `minimal` … `xhigh`), and
  giving each one a fill would mean guessing.
- **No key hint.** Claude Code adds `· /effort`. chord changes effort through
  `/config`, which `/help` lists. On this line the hint would take the room the
  model needs and add nothing the help does not already say.
- **Plain tone**, the same dim as the model and the context. It is a fact
  about the agent, not a warning, so a dark and a light terminal show it the
  way they show the model.

### Main and a selected child

The line already follows the selection: with `tuner` selected, the model and
the context are `tuner`'s. The effort follows it too. Main's line says
`medium`, `tuner`'s line says `high`, and nothing on the line names whose it
is. The list right below does that with `❯`, as it does for the model now.

### When the runtime offers no efforts

The line says nothing about effort. It is the line from today, with no `—`,
no `default` and no blank slot. That matches the list, which shows no effort
for a runtime that has none. If an agent reports an effort but no model yet,
the effort shows by itself: `high effort · 1% context used`.

### What gives way

One step is added to the ladder the line already has. Fullest first:

1. `model · E effort · N% context used`
2. `model · E · N% used`: the effort loses `effort` at the same step the
   context loses `context`
3. `model · N% used`: **the effort goes**
4. `Fake Large with a 1M… · N% used`: the model is cut, as today
5. the model goes, as today

The effort goes before the model is cut, the same order the agent list
follows (CHD-354). The model is what names the agent, and the effort is
always on the list below whenever the list is open. The left side does not
change. The hint, a mode with its `(shift+tab to cycle)`, the waits notice and
vim's mark keep the room they keep today.

## For the build

- `StatusFacts` gets the front agent's effort, the main agent's or the selected
  child's, from the same place the list's row reads it. It is undefined when
  the runtime offers none.
- `rightParts` puts it between the model and the context. The ladder in
  `statusLine` and `shortened` gains step 3 before the model is cut.
- Tests: wide with the word, short without it, dropped before the model is
  cut, absent with no efforts, and a child's effort while it is selected. All
  of them run on the fake.
