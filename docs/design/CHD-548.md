# CHD-548 — get_budgets just reads the limits

The owner's 2026-10-28 answers on the task decide the shape: `get_budgets`
reads each provider when called, in parallel, about 10 s each, and returns

```text
{ readAt, providers: [
    { agent, windows: [ { name, usedPercent|null, windowSeconds|null,
                          resetsAt|null, models|null } ] }
  | { agent, unavailable: reason } ] }
```

`run_team` no longer reads or records a budget snapshot. This design changes
only what loses fields; every line that keeps its data keeps its words. No new
key, fold, control or colour role.

## 1. The `⏺ Resources` block

The block stays where it is: `⏺ Resources`, the completed-tool body under
`⎿`, ordinary wrapping and scrollback, ctrl+o as today.

Lines, in order:

1. `Read: <readAt> · advisory snapshot` — unchanged (`HH:MM:SS UTC`).
2. One line per window, in the answer's order, provider by provider:
   `<agent> · <label>: <usage> · reset <reset> · <models>`.
   - `<label>`: the window's duration as today (`5h`, `7d`, `90m`); when
     `windowSeconds` is null, the window's `name`.
   - `<usage>`: `12.345% used`, precision as given; null says `usage unknown`.
   - `<reset>`: `18:00 UTC`, with its UTC date in front when it is not the
     read's day; null says `unknown`.
   - `<models>`: `models opus, sonnet`; an empty list says `models none`;
     null says `models unknown`. Unchanged from today.
3. A provider read with no windows: `<agent>: no windows reported`.
4. A provider not read: `<agent>: unavailable · <reason>`, the reason as the
   answer gives it. A timeout is one of these, e.g.
   `codex: unavailable · no answer within 10s`; the words come from the
   answer, the screen does not invent them.
5. An empty answer (`providers: []`, e.g. a filter naming no supported
   provider): `No providers read.`

Gone, because the answer no longer carries them: `Preferences`, `Allowed …`,
the per-provider billing/identity line, `Source: …`, `Received … before read`,
provider freshness, `Warning: …` lines, the pending line and
`Active work: …`.

Why the agent goes on each window line rather than a header line of its own:
with billing, identity and source gone, a header would be a bare word; one
line per window reads as a table and greps by agent. The `<agent>:` form of
lines 3–4 stays as today's unavailable line, so a provider's state reads the
same whether it has numbers or not.

### States

| State | Screen |
| --- | --- |
| Running | `⏺ Resources` with the existing running accent marker and no body. The call may now take up to ~10 s; the existing turn progress is the only sign. No spinner of its own, no partial lines. |
| Read | Lines 1–2 as above. |
| Partial | Window lines for the providers read, `<agent>: unavailable · <reason>` for the rest, in the answer's order. A successful call: done marker, dim body, not red. |
| All unavailable | `Read:` and one `unavailable` line per provider. Still a successful call. |
| Empty | `Read:` then `No providers read.` |
| Error | The MCP call itself failed: the existing failed-tool style (`error` role) and its safe message. Unchanged. |
| Narrow | Ordinary wrapping (80×24 above); nothing is cut or hidden. |

Colour roles (`src/ui/theme/theme.ts`): unchanged. Running marker `accent`,
done marker as every completed tool, body in the existing dim result text,
failed call `error`. An unavailable provider is ordinary body text, not
`warning` or `error`: it is an answer, not a failure of the call.

## 2. Answers recorded in older sessions

A resumed session can hold a `get_budgets` answer in the old snapshot shape.
It does not parse as the new answer, and today's fallback
`No usable quota observations; capacity unknown.` would claim something about
quota that the record does not say. Any answer that does not parse shows one
line:

```text
 ⏺ Resources
   ⎿  Recorded in an older format; not shown.
```

Dim body text like every result line; no warning colour. ctrl+o keeps its
existing raw detail, so the record is still reachable.

## 3. The `run_team` receipt

New receipts record `decisionRead: null` and no budget warnings. Today a null
read shows `Read: none recorded · capacity unknown · advisory`, which on every
new run would announce a read that is no longer part of `run_team` at all.

- `decisionRead: null`: **no `Read` line.** The receipt ends at the role
  lines, then `ctrl+o for saved definition and changes` (collapsed) or the
  saved-definition lines (expanded), as today.
- A receipt recorded with a read: unchanged,
  `Read 2026-10-27 13:40:00 UTC · advisory`, and its `Warning:` lines stay
  (owner decision: receipts already recorded display as they were).
- Everything else — `Selection`, `Reason`, `Billing: unknown · advisory`,
  `Planned for this run`, the `Actual` lines — is unchanged. The same lines
  feed `/team show` and recorded receipts, so they change together.

A receipt recorded before this change with a null read loses the
`none recorded` line too. That line said only that nothing was read; dropping
it there removes no recorded fact.
