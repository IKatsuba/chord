# CHD-608: auto review permission screens

This refines [CHD-485](CHD-485.md#permission-prompts), its owner decisions
A3–A5 and its five-minute timeout comment. CHD-605 Q351 settled that the
shared permission box draws proposed diffs for every agent sending one.
Use that box, the existing transcript and existing colour roles.

Main's provisional CHD-608 decision supersedes CHD-485's headless wording:
`chord acp` forwards the review ask to its client like any other permission
ask; riff withdraws it into a denial after five minutes. `-p` denies a
review ask even with `--dangerously-skip-permissions`.

## Generic metadata contract

The shared window reads the following optional object on
`session/request_permission`, for any agent supplying it:

```json
{
  "_meta": {
    "chord/permission": {
      "review": {
        "outcome": "caution",
        "reason": "Force-pushing main rewrites published history and cannot be undone from here."
      },
      "deadlineAt": 1794326700000
    }
  }
}
```

Use these exact keys. `review.outcome` is `caution`, `incomplete` or
`failed`; `review.reason` is the rationale or plain reason review was
unavailable. `deadlineAt` is an absolute Unix timestamp in milliseconds,
five minutes after the agent raises the ask; the example is illustrative.
The window does not branch on riff, provider or mode. Render agent text
through the existing safe text treatment. Missing or invalid fields do
not invent a reason, outcome or deadline. Ordinary asks retain their
existing UI and no timer without this metadata.

The agent owns the authoritative deadline and denial. Repainting,
changing conversation or mode must not renew it. Withdrawn or answered
asks disappear; an expired choice must never authorize execution. The
normal request fields still provide title, locations, arguments, content
and options. Reviewed asks supply exactly `Allow once` (`allow_once`)
and `Deny` (`reject_once`), with no session grant. The request's normal
`toolCallId` associates the review outcome with the transcript call.

## Layout, states and wording

Under the tool title, draw `Reviewed: caution`, `Reviewed: incomplete`
or `Reviewed: failed` before its result; retain it after the box closes.
Admission without review must not claim it was reviewed. Clear reviews
run without a permission box.

The box contains its normal title and location/content, then a gap,
review explanation, a gap, the two choices, a gap and footer. Caution
and incomplete put `The safety review held this:` in `warning` on its
own line, then the plain rationale/reason underneath. An incomplete
review explains the cap or budget, without claiming a model found risk.
For example: `The proposed action exceeded the review input limit.`

Failed review replaces those lines with the following sentence, wrapped
in `error`: `The safety review could not run (the reviewer did not answer
in 30 s). Allow it yourself, or deny it.` Use the actual plain reason in
parentheses, not a fabricated rationale.

The working line reads `Waiting for permission… (4s · denied in 4m 56s)`.
Elapsed starts with this ask; remaining time comes from `deadlineAt`, in
minutes and seconds, never below zero. The fixed footer is
`Esc to reject · denied by itself in 5 minutes`. Only the working line
counts down; the footer states the original limit.

Timeout closes the box and waiting line. Preserve the review line and
add `Denied: no answer within 5 minutes.` with the normal failed-tool
treatment. The model receives that denial. No shell output, successful
exit or applied diff is invented. If the model continues, restore the
normal Working line. Manual Deny/Esc use ordinary denial wording;
Allow once permits this call only and creates no session grant.

A5's automatic auto-to-ask switch and notice wait on a documented libfx
permanent-failure signal. libfx documents none, so in this slice every
review failure is unavailable and raises the failed-review ask with its
5-minute timeout; auto never switches itself to ask (main's provisional
CHD-608 decision). There is no auto-off notice or automatic status change.
The status remains `auto` unless the person changes mode. Ordinary
ask-mode permissions retain their normal choices and no review timer.

Empty: normal riff header and rounded prompt, default `auto`, no review
line or countdown. Streaming/reviewing: normal running marker and Working
line, no invented review progress or provider retry state. Waiting:
the screens below. A tool error after Allow once retains the review line
and draws its actual error normally.

## Colours and keys

| Element | Existing role |
| --- | --- |
| Box border, title, selected `❯` | `permission` |
| Working indicator and running marker | `accent` |
| `The safety review held this:` | `warning` |
| Rationale/reason after heading | terminal foreground |
| Failed-review explanation | `error` |
| `Reviewed: caution` / `incomplete` | `warning`, dim connector |
| `Reviewed: failed` and timeout denial | `error`, dim connector |
| Auto status | `auto`; ask uses its existing mode treatment |
| Timer, footer, normal connectors | existing dim text |
| Proposed diff | existing diff/code roles and tints |

No new theme role; words and signs retain meaning without colour.

`1` allows once, `2` denies; Enter accepts the highlighted choice and
Esc rejects. Retain existing permission navigation and scrolling keys.
The existing `1–9` choice convention applies; absent options add no action.
Shift+Tab cycles ask/auto through the existing mode action without
approving or renewing a pending ask. `?` on an empty prompt lists existing
permission choices, Esc and mode-cycle entries. No new shortcut is needed.

## Why and acceptance evidence

Keep the action, reason, answers and deadline together. A separate heading
lets the rationale scan at both widths. An absolute deadline survives
repaint and refocus. The review line remains with its eventual result.
The shared window draws generic metadata; riff owns review policy.

After the U5 handoff, run `bun dev chord --fake --qa chd608 riff` in an
owned tmux session at 120x40 and 80x24. Reach caution, incomplete, failed,
timeout and unavailable failure with fake scenarios. Check that a failed
review retains `auto` without an auto-off notice, and that a
proposed diff keeps answers reachable. Save text and colour PNG captures
under `evidence/CHD-608/`, naming the exact handed-over commit, and kill
the session. Run `bun test ./tests/privacy_test.ts` before committing
captures. Runtime evidence awaits that handoff; these mocks are no pass.
