# CHD-264: a child whose turn failed, still open

A long-lived child whose turn failed is still open, and `send_message`
reaches it, as main's `← from chord` row says. Yet the agents list reads
`✗ failed`, the word it also uses for an agent that never came up. The
owner (2026-10-15): the list should show the child open with its turn failed;
the wording is the designer's. This page settles it. It is a small fix, and
nothing here is the owner's policy.

## Today

Captured on the fake agent (`evidence/CHD-264/today/`). Tab 1 ran
`agentfail` (parser's turn fails); tab 2 ran `agentexit` (parser's agent
exits mid-turn).

| State | File |
| --- | --- |
| agentfail: the list and the status line | `agentfail-120x40.txt` (`.ansi`), `agentfail-80x24.txt` |
| agentfail: the sessions picker, its own tab in front | `agentfail-picker-120x40.txt` |
| A second tab opened: tab 1's glyph in the strip | `strip-tab-behind-120x40.txt` |
| agentexit in tab 2: the list and the status line | `agentexit-120x40.txt` |
| The sessions picker with both tabs | `picker-both-120x40.txt` |

What reads wrong:

- **agentfail:** the list says `parser … ✗ failed` and the status line says
  `✗ parser failed · ctrl+x a to go`. Both read as if parser were gone, while
  the transcript says `It is still open; send_message reaches it.`
- **agentexit:** the list also says `✗ failed`, not `✗ exited`. The gone
  process's own word loses to the failed turn it cut short, so the two cases
  read the same.
- **The status line's count:** with tab 1's open child and tab 2's exited
  one, it reads `✗ 2 sessions ended`. One of them has not ended, and both
  are agents, not sessions.
- **The sessions picker:** it says tab 1 is `✗ failed`, not whose turn or
  that the agent is open.
- **The tab strip:** it marks tab 1 `✗`. That is right: something there
  wants a look.

## The three states and their words

| What happened | List row, folded lead | Status line, one | Sessions picker |
| --- | --- | --- | --- |
| The turn failed; the agent is open | `✗ turn failed 12s ago`; folded `✗ tester: turn failed 12s ago` | `✗ parser's turn failed` | `✗ parser: turn failed 1m` |
| The agent never came up | `✗ failed to start`; folded `✗ tester: failed to start` | `✗ parser failed to start` | `✗ parser: failed to start` |
| The agent's process exited | `✗ exited`; folded `✗ tester: exited` | `✗ parser exited` | `✗ parser: exited` |

- **Turn failed, agent open:** the word says what failed, the turn, so the
  agent reads as still there. It counts its time like `✓ replied 2m ago`,
  since it is the same kind of news: the latest turn's end, not yet seen.
  Once the person has looked at the child, the state clears as `replied`
  does, and the row shows the agent idle and open, with no state words.
- **Never came up:** `failed` alone was the word both cases shared. `failed
  to start` keeps it for the agent that has nothing open, and says why it
  never worked. It stays until the agent is closed, as today.
- **Exited:** unchanged words, `✗ exited`, until closed. It now wins over
  the failed turn the exit cut short, so a gone process always reads
  `exited`. The order is: asking, exited, failed to start, turn failed,
  message, replied, working.

**Colour:** all three keep today's error colour on `✗` and the words, as
`src/ui/theme/theme.ts`'s `error` role. A failed turn wants a look as much as
the others. The words, not the colour, say the agent is open.

## Each place

### The agents list (`mock/turn-failed-120x40.txt`, `mock/turn-failed-80x24.txt`)

```
    main    fake · Fake Large with a 1M context window · medium
    parser  fake · Fake Small · medium                           ✗ turn failed 12s ago
```

At 80 columns the list's fallbacks apply as they do today: effort goes first,
then the model, and then the state keeps its glyph and drops its words
(`agentsLayout`'s `FITS`). `turn failed 12s ago` is four cells longer than
`replied 12s ago`, and both fit at 80 beside a model.

### A folded team's lead

As a folded lead names the member whose state it shows today:
`✗ tester: turn failed 12s ago`, `✗ tester: exited`.

### The status line

- **One, in front or behind:** `✗ parser's turn failed · ctrl+x a to go`,
  `✗ parser exited · …`, `✗ parser failed to start · …`. A tab behind is
  named as today (`1 fake`): `✗ 1 fake's turn failed`.
- **More than one:** one count per state, joined by ` · `, in the order
  above: `✗ 1 exited · 1 turn failed · ctrl+x a to go`. Each part is a number
  and the state's words (`2 turns failed`, `2 exited`, `2 failed to
  start`). That leaves out a noun (agents or sessions), so the count is never
  wrong about which it is (`mock/exited-120x40.txt`).
- **At 80 columns** the key shortens to `ctrl+x a`, as today:
  `✗ parser's turn failed · ctrl+x a`.

- **Only unseen news**, as today: a failure the person has already seen
  leaves the status line. The list row keeps `✗ exited` or `✗ failed to
  start` until the agent is closed.
- **One failure and a reply** read as the failure, named:
  `✗ parser's turn failed · ctrl+x a to go`. **Replies alone** keep
  today's `✓ N sessions replied`.

The notice's tone stays `ended`, its error colour.

### The sessions picker (`ctrl+x w`, `mock/picker-120x40.txt`)

A tab's state names the agent whose it is when it is a child's or member's,
as the folded lead does, with the picker's own short time:
`✗ parser: turn failed 1m`. When it is the tab's own
main session, the state stands alone: `✗ turn failed 1m`. The same words are
used for exited and for failed to start.

### The tab strip

Unchanged: `✗` on a tab with any of the three. The glyph says "look here",
and the words are one key away in the status line.

### Main's `← from chord` row

Unchanged. It already reads `parser's turn failed: … It is still open;
send_message reaches it.`

## Keys

None change. `ctrl+x a` still goes to the oldest failure. `x` in the agents
list still closes a child, in any of the three states.
