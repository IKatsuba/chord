# The registry refresh of 2026-10-17 (CHD-432)

The owner (2026-10-17): adapters move all at once, through `bun dev registry`.
The refetch is committed alone as d27e225f. This page is what the team found
between the old pins and the new ones, what that means for a person using
chord and for the fake agent, which open tasks and owner questions it
changes, and a plan in order. It gives options and a plan for the owner, not
decisions. Nothing beyond the registry commit is built, and the refresh is
not merged, until the owner has seen this.

What each agent can do at the new pins, and what chord uses of it, is no
longer here: the capability tables moved to
[`../agent-capabilities.md`](../agent-capabilities.md) (CHD-433). This page
keeps only what the refresh changes.

Everything here was read from the packages' `dist/` and release notes, read
only. No live agent was run. Paths in the findings point into each new
package's `dist/` unless they name `src/` or `tests/`.

### claude-agent-acp 0.87.0 → 0.93.0

Read by developer.

**Breaks in chord:**

- **C1. Subagents now come in the ACP subagents RFD's form** (0.90, #1320).
  A client that is not AIR, as chord is, gets `subagent_update {sessionId,
  title, description, capabilities: {cancel: {}}, state: {state:
  'running'}}` in place of `subagent_spawned` (`native-subagents.js:930-952`).
  A subagent ends with `{state: 'idle', stopReason: 'end_turn' | 'cancelled'
  | 'error'}`, or `{state: 'unknown'}`. chord maps `idle` to completed
  whatever the stopReason, and maps `unknown` to nothing
  (`src/session/transcript/subagents.ts:232-249`). So a failed or cancelled
  Claude subagent reads `✓`, and a lost one runs on screen for good.
- **C2. Background subagents outlive a parent's cancel** (0.91 #1348, 0.93).
  chord marks every running subagent cancelled on Esc, "as the adapters do"
  (`src/session/transcript/turn.ts:139-151`). After Esc, an agent that is
  still alive shows as cancelled, and its later requests are refused
  silently (CHD-158), now in the common case.
- **C3. The fake agent's subagent scenarios play the draft
  `subagent_spawned`**, which only codex still sends. The `subagentupdate`
  scenario lacks `capabilities.cancel`, `requires_action`, `idle` with a
  stopReason, and `session_message`.

**Changes a person sees:**

- **C4.** A subagent's title is now `name (role)`, and its description is
  the short task. The full prompt comes in a new `session_message` update,
  which chord drops, so `ctrl+o` no longer shows a subagent's whole task.
- **C5.** `requires_action` while a subagent asks reads as running. This is
  harmless.
- **C6.** A tool call the turn ends without a result is now `failed`, with
  one line: "Claude stopped this tool call before it ran.", "The turn was
  cancelled before this tool call returned a result.", or "Claude ended the
  turn without returning a result for this tool." A terminal exit comes with
  a null code. After Esc, a grey `Waiting…` becomes `✗ failed`. To be
  checked against CHD-417's cut path and CHD-422's "an unfinished call waits
  on nothing".
- **C7.** After a cancel, Claude Code's follow-up text comes after the
  prompt has answered `cancelled`. chord folds it under the last turn.
- **C8.** An approved ExitPlanMode also becomes a markdown `plan_update`,
  since chord declares `plan`, so the plan is shown twice.
- **C9.** A new `/remote-control` slash command (CHD-428).
- **C10.** Claude now predicts a follow-up prompt every turn but publishes
  it only to AIR clients, so chord pays for a prediction it never shows. It
  can be turned off with `_meta.claudeCode.options.promptSuggestions: false`
  in `session/new`, or `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false`.

**Fixed upstream:**

- **C11.** The Agent call's hook result now goes through the routed client
  and is dropped (0.90 #1324), so the lone `Tool` rows of CHD-409 should be
  gone. This is from code, not run.
- **C12.** A question that is withdrawn is no longer waited on (#1338).
- **C13.** Cancel handling is cleaner.
- **C14.** Settings survive resume and load, and `session/delete` works
  without a transcript.

**New capability:**

- **C15. Per-subagent cancel without AIR** (0.91 #1347): `session/cancel`
  on a subagent's session id stops that one subagent, announced by
  `capabilities.cancel`.
- **C16. Subagent persistence:** a subagent keeps one id across
  SendMessage, has its live id on replay, and is restored after a reload or
  restart (#1321, #1328, #1332, #1364).
- **C17.** Custom instructions can be given through `session/new` `_meta`;
  use by a client that is not AIR is unchecked.

**Hidden behind chord:**

- **C21.** Claude's own `/mcp` is hidden behind chord's `/mcp`.

C18–C20 are left out of this page: what claude sends every client (session
titles, its own usage), its fork point without AIR and what declaring AIR
switches are in claude-acp's part of
[`agent-capabilities.md`](../agent-capabilities.md).

**Unchanged:**

- `asyncTasks` is still AIR-only.
- Bash statuses: still `pending` until done.
- The held turn.
- `usage_update`.

### gemini 0.63.0 → 0.64.0

Read by reviewer, source-proven.

- It sends the standard `PromptResponse.usage` (input, output, total,
  cachedRead and thought tokens) and `usage_update` used/size, with no cost.
- `session/load` validates the id and resolves the exact saved id, and a
  replaced session is cleaned up (PRs #29389, #29549, #29580).
- No change to tool or permission shapes, modes and models, capabilities,
  subagents or steering.
- chord's `usage.ts` already reads these fields, and `enrichers.ts:49-115`
  estimates a cost from them. So the refresh gives chord a context meter for
  Gemini: `used` is per model call, and `size` is the token limit, 1,048,576
  by default.
- **Cost:** `PromptResponse.usage` gets an estimate only for concrete model
  ids. The default `auto` is not in genai-prices, so it gets no cost.
- **Thinking tokens:** the adapter sends `totalTokens = input + output`, with
  thinking tokens outside it. chord's `priced()`
  (`src/session/prices.ts:48-66`) reads `total === input + output` as
  "thoughts already inside output", so Gemini's thinking tokens go unpriced.
  How to price them is an owner question (section 5), not a unit.
- Exact-id load fits chord's reopen (`src/session/session.ts:709-727`).

### qwen-code 0.25.0 → 0.25.2

Read by reviewer and a subagent. Nothing breaks.

- The person's cancel is kept across a session recovery (a46aee28, #13436),
  so chord's cancels go on meaning cancel.
- **QW1.** Each call gets a new `tool_call_update` with only
  `_meta.toolLifecycle` (no status, no title). chord's `mergeToolCall`
  keeps the status. For a skipped call the "ended" update comes before its
  `tool_call`, so a bare row shows for a moment until the `tool_call`
  fills it.
- **QW2.** An empty `agent_message_chunk` per model request
  (`_meta.executionLifecycle`), which chord drops.
- **QW3.** After a cancel, subagent lifecycle updates keep coming for up to
  30 s. Each resets chord's quiet timer (`src/session/conversation.ts:2058`),
  so a queued prompt can wait up to `SETTLE_LIMIT_MS`, 5 s.
- **QW4.** With qwen hooks set, PreToolUse can rewrite a call's input before
  the permission, so the box shows the rewritten rawInput.
- **Unchanged:** `qwenQuestions`, the background scheme
  (`_qwencode/start_turn`, `end_turn`), subagent meta, usage, models,
  modes, permission options and capabilities. Its events after a cancel stay
  inside chord's settle. Its own turns, which bring permissions with no turn
  running, are not new; see qwen-code in agent-capabilities.md.

### bob 2.0.8 (new)

Read by reviewer, from `@ibm/bob` 2.0.8's bundle as plain text, for its ACP
contract only, and its form path checked against chord's. What it
advertises and the shapes it sends are in bob's part of
[`agent-capabilities.md`](../agent-capabilities.md).

**Works in chord as it is:**

- Chunks, thoughts, tool calls with rawInput, `rawOutput {result}` and
  diffs, plans, modes, `available_commands`, history replay, permissions and
  cancel.
- Both forms, its question and its license consent, through chord's
  existing form path. The license-consent form is sent at the start of each
  prompt until it is accepted, so it comes inside a turn.

**Breaks in chord:**

- **B1. chord never calls `authenticate`.** Without an SSO login,
  `session/new` and `session/load` fail with `authRequired`. The person has
  to log in by running bob in a terminal; an API key skips it.
- **B2. A folder marked untrusted is refused** unless `--trust` is passed,
  and the registry's args are only `acp`. Nothing is to be added silently.

**Reads oddly on screen:**

- **B3.** Command output comes as `tool_call_update` content chunks that
  replace each other, so a running command shows only its latest chunk.
- **B4.** A cancelled permission leaves its call `pending` for good.
- **B5.** A subagent shows only as its parent's tool call; nothing of its
  own work is sent.
- **B6.** A prompt sent while a turn runs is refused ("already running"), and
  bob has no steering. After `session/cancel`, the next prompt waits for the
  cancelled turn to end rather than being refused. chord queues a person's
  prompt until the turn ends, but how a message from another agent to a bob
  child fares is to be checked.
- **B7.** `session_info_update` (a title) is ignored.
- **B8.** A single `sse` entry among the MCP servers fails the whole
  `session/new`, load or resume; bob does not drop that server, and chord
  passes the person's servers as they are.

### dirac 0.5.18 → 0.5.21

Read by a subagent, from source.

- **Subagent approvals** (0.5.20) now come as an ordinary
  `session/request_permission` under the parent's session id, with
  `rawInput.commands`, and only inside a running prompt. Parallel

### sigit 1.6.4 → 1.7.0

- The registry's empty args still start ACP.

### codebuddy-code 2.162.0 → 2.168.2

Read by a subagent, from the bundle. Nothing breaks.

- **The background-task extension is not new on the wire.** Its only wire
  method is still `_codebuddy.ai/session/cancelBackgroundTask`
  `{sessionId, terminalId}`, answering `cancelled`, `already_exited`,
  `not_found` or `cancel_failed`. It is present in both versions; a task
  must now belong to the calling session. List, status and result belong to
  its JS server library, not to ACP.
- **Terminal updates** (`terminal_update`, `terminal_output_chunk`) come
  only to a client that declares `_meta["codebuddy.ai"].terminalOutput`,
  which chord does not. The `terminalId` a stop needs comes without it, on
  the backgrounded call's terminal block; only the task's state and output
  need that opt-in. So for CHD-2, a stop through that cancel is an owner
  option, not a unit.
- After a compaction, `usage_update.used` drops to the compacted estimate.
- Code Mode safety approvals are ordinary permissions (Allow and Reject
  only).
- Lite subagents follow the chosen model.
- **Fixes:** an invalid Read location no longer breaks the connection or a
  replay; diffs up to 2 MiB; a new cancel reason in
  `_meta["codebuddy.ai/cancelReason"]`.
- **Unchanged:** its subagents send no `subagent_update`. Their traffic
  stays in the parent session with `_meta["codebuddy.ai/parentToolCallId"]`,
  which chord ignores, so they show flat, as before.
- **Outside ACP:** under `--acp` it now keeps all history by default.

### nova 1.1.51 → 1.1.55

Read by a subagent, from its bundle as plain text only. Its 1.1.55 README's
licence forbids reverse-engineering its obfuscated bundle, so nothing was
decoded, and no copy of it is kept in the repository. Nothing breaks.

- **Launch is unchanged in effect.** `@compass-ai/nova` 1.1.55 has no
  native optional dependency, so `acp` always starts a Node process, with
  argv passed through and stdio inherited. chord's process-group stop still
  reaches it. A child killed by a signal now exits 1.
- **Its tool approval loses "Always allow"**: only Allow once and Reject are
  left. Approvals carry `_meta.compass.permissionScope`, which chord ignores.
- **New behind client opt-ins chord does not send:** peer-identity `_meta`
  and methods.
- **Unchanged:** the session updates, still with no usage, config options or
  `session_info`; `requestUserInput` (CHD-383 unaffected).
- **A possible older problem, in both versions and unproven.** nova's
  plain text names both `session/request_permission` and
  `permission/request`, and it may send the second under protocol version 1.
  chord negotiates version 1 (`src/acp/connection.ts:357`), so nova's
  approvals may never reach chord at all. Only a live check can tell
  (section 5).

## 3. What breaks or changes for a person

### In chord

1. **Claude subagents read wrong at their end** (C1). A failed or cancelled
   one shows `✓`, and a lost one never ends. This applies to everyone on
   Claude.
2. **Esc mislabels Claude background agents** (C2). They show cancelled
   while they keep working, and anything they ask is refused unseen.
3. **A subagent's full task is gone from `ctrl+o`** (C4).
4. **A Claude plan approved through ExitPlanMode shows twice** (C8).
5. **Unfinished calls now read `✗ failed` with a line** (C6), where they were
   a grey `Waiting…` after Esc. This is probably better, but it is a change.
6. **Claude spends a hidden prompt prediction every turn** (C10).
7. **codex's own `/mcp` and `/status`, and claude's own `/mcp`, are
   hidden behind chord's** (X2, C21).
8. **Copilot is named `Copilot`** in `chord agents`' title column. README
   still says `GitHub Copilot`.
9. **bob does not start without an SSO login** (B1), or in an untrusted
   folder (B2). chord shows a bare start failure, as in CHD-55. Once
   started, a running command shows only its latest chunk (B3).

Unchanged for a person: the Claude and Codex question boxes, efforts,
models, modes, usage and cost, Bash statuses, steering.

### In the fake agent's catalogue

- **Subagents** (C3) need the RFD form for Claude: `subagent_update` with
  `capabilities.cancel`, `requires_action`, `idle` with each stopReason,
  `unknown`, and `session_message`. `subagent_spawned` stays for codex.
- **Version names** move in `tests/fixtures/questions.ts`,
  `scenarios/forms.ts` and `efforts_test.ts`. AskUserQuestion,
  request_user_input and codex's thought_level are byte-identical.
- **bob** gets scenarios: `authRequired` on `session/new`, output chunks
  that replace each other, a cancelled permission with no later update, and
  the license form at a prompt's start.
- **Gemini-shaped usage** (tokens, no cost) as a scenario is an
  opportunity, not a need; so are sigit's `messageId`, `reject_always` and
  `session_info_update`, and qwen's lifecycle update ahead of its
  `tool_call` (QW1).

### U1: how a subagent's end reads

Claude 0.93 ends a subagent four ways (`rfdEndState`,
`native-subagents.js:1043-1065`), and chord draws each as one of the
endings it already has, or one new one:

| Wire | Means | Ending | Marker | Header count |
| --- | --- | --- | --- | --- |
| `idle`, `end_turn` | finished | `Done` | `done` | — |
| `idle`, `cancelled` | the person's or the agent's cancel | `Cancelled` | `pending` (dim) | `n cancelled` |
| `idle`, `error` | failed; `error.message` when the SDK gave one | `Failed` | `failed` | `n failed` |
| `idle`, no stopReason | ended, cause not seen: a worker restart, or the stream ended | `Ended` | `pending` (dim) | `n ended` |
| `unknown` | the adapter can no longer observe it | `Untracked` | `pending` (dim) | `n untracked` |

An `idle` with a stopReason chord does not know reads as `Ended`, not
`Done`: only `end_turn` earns the green marker.

**Why these words.** `Done`, `Failed` and `Cancelled` are what chord already
says for the same ends, so a Claude subagent reads as a codex one.
`Ended` claims nothing the adapter did not: it says its work stopped, and
the RFD forbids the adapter calling that a cancel or a failure, so chord
does not call it one either. `Untracked` is not `Disconnected`: that word
is chord's own, for a subagent whose agent chord lost; here chord's agent
is alive and says it lost sight of the child, which may still be at work.
Neither is red: nothing says it failed. The word carries the difference,
never the colour alone.

**Untracked is not final.** A later `running`, `requires_action` or `idle`
for the same id takes the block back to that state, its time running again
from its first start. While it is untracked, its time stands at the
`unknown` update, it counts as ended in a group header, it is not among the
subagents the status line says outlive their turn, and Esc leaves it as it
is (U2).

**Folded**, a lone block, as today with the new words:

 ⏺ Agent(Run the whole test suite)
   ⎿  Ended (1 tool use · 2s)

   ⎿  Failed (1 tool use · 2s)
```

A group, its header counting each end that is not `Done` in the order
failed, disconnected, untracked, ended, cancelled; the header is red only

```

### U4: a subagent's full task

Folded, a block is unchanged: its title, then its work or its ending.

In ctrl+o's view, the subagent's first `session_message` (its launching
Agent call's prompt, `messageId` the call's id) takes the description's
place under `⎿`, drawn and folded as a `spawn_task` task's prompt is in the
same view, through `theme/Ansi.tsx`. Each later `session_message`, a
SendMessage to the same subagent, is a row among its work where it came,
drawn as chord's incoming message already is: `← from <sender>`, `from`
dim and the sender bold, then its text whole.

```
   ├─ Agent(explorer (Explore)) · 3 tool uses · 10s
   │  ⎿  Find the session layer: where sessionUpdate is routed by
   │     sessionId, and what happens to an id chord did not open.
   │
   │     ⏺ Search(sessionUpdate in src)
   │       ⎿  Found 14 files
   │
   │     ← from main
   │     Also check what a subagent's own id does there.
   │
   │     ⏺ Read(src/acp/connection.ts)
   │  ⎿  Done
```

- **The sender** is `senderSessionId`'s name: a subagent's
  `Agent(<title>)`, else the owning agent's name (`main`, a child's name).
  With no `senderSessionId`, the parent.
- **An upsert by `messageId`** shows the latest content in place. A cleared
  message leaves no row; a cleared first message gives the description its
  place back.
- **Why** the first message under `⎿` and the rest as rows: the first is
  the task, as the description was; a later one is a turn in the subagent's
  work, and reads where it came, as any message to an agent does.
