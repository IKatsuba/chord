# CHD-394: a code block's buttons, copy and put into the prompt

The owner decided (2026-10-15, revised 2026-10-25): every code block in a
reply gets a copy button; a block labelled `sh`, `bash` or `console` also
gets one that puts its command into the prompt box in bash mode (`!`),
not run; an unlabelled block gets copy only. A copy gives the selection
copy's feedback (CHD-172). Icons, their place, the copy wording and the
keys are this design's; what "put into the prompt" puts in for several
lines, `$ ` prompts and `console` output is the owner's open question, with
options in §5.

Captures are in `evidence/CHD-394/`: `today-*` is chord at fdc2df86 on the fake
agent's `markdown` scenario at 120×40 and 80×24, and every other picture is
that capture with only this design's changes edited in. Each is a
whole-window colour PNG with its text beside it.

## 1. The icons

Two glyphs at the right end of the box's top border, each with a space on
either side, then the border's last `─┐` (`icons-*`):

```
   ┌─ ts ───────────────────────────────────────────────────── □ ─┐
   │ const session = await openSession({ agent: 'claude', cwd }); │

      ┌─ sh ────── □ ! ─┐
      │ deno task check │
      └─────────────────┘
```

- **`□` copies, `!` puts into the prompt.** `!` is the key that starts bash
  mode and what the bash-mode box shows in its gutter, so the button says
  where the command goes. `□` (U+25A1, WHITE SQUARE) stands for the copy.
- **Why these glyphs.** Both are one cell and in every font checked here
  with `fc-list`: Menlo, JetBrains Mono, Monaco, Andale Mono, Courier New,
  FiraCode Nerd Font. The usual copy icons are not: `⧉` and `⎘` are in none
  of them, and `❐`, `▣` and `⬚` only in Menlo, so another font would fall
  back to a wider or different glyph and shift the border.
- **Where.** On the top border, right-aligned, so the language label keeps
  its place on the left (as today) and the code's rows are untouched: a
  copy over the code reads as it does now, and nothing is added inside the
  box. Right, not after the label, because a label and two icons side by
  side read as one word (`sh □ !`).
- **Width.** A box is at least wide enough for its label and its icons, as
  it already grows for a label wider than its code (`markdowncode`): the
  border stays one row.
- **Which boxes.** `□` on every code box, the one in a quote and in a list
  too. `!` only on `sh`, `bash` and `console`. An unlabelled box gets
  `┌──────── □ ─┐`. A table is not a code block and gets nothing.
- **Look.** The icons are in the text's own colour, the border stays dim,
  so they read as something to press. There is **no hover look**: chord
  reads the mouse without motion reports (CHD-172 turned 1003 off), so
  nothing on screen can follow the pointer. A picked box is drawn in the
  accent colour (§3).
- **Streaming.** A box whose fence is still open gets no icons until it
  closes: its text is not final.

### Clicks

A press and a release on the same icon cell is a click; the icon's cell and
the space on each side of it answer, three cells, so a click a cell off
still lands. A click copies or puts into the prompt, as the keys do.

- **The wheel** is unchanged: it is its own button, and an icon never
  answers it.
- **The selection.** The border is chord's furniture and starts no
  selection today (CHD-172); an icon is part of it, so a press on one starts
  none either. A press there clears a selection shown, as any press
  elsewhere does. A drag that starts in the code and ends on an icon is a
  selection, not a click.
- **The drag hint** (`shift + drag`, where the terminal's own selection is
  wanted) is untouched: a shift-held press goes to the terminal, never to
  chord.

## 2. The copy feedback

The selection copy's note, word for word, alone on the status line for 3 s
(`COPIED_NOTE_MS`, `copied-*`):

```
╭──────────────────────────────────────────────────────────────────────────────╮
│ ›                                                                            │
╰──────────────────────────────────────────────────────────────────────────────╯
  copied 75 chars to clipboard
```

and `sent N chars to the terminal's clipboard` when only OSC 52 went, as
CHD-172. N counts the block's graphemes. What is copied is the block's text
as the agent wrote it, its lines joined with newlines: no border, no label,
no wrapping of chord's, no trailing newline. The copy goes through the
selection copy's clipboard path (`createClipboard`), with its failure note.

## 3. The keys

A leader, then a picking mode, so nothing takes a key the prompt, the
selection or the wheel already uses.

- **`ctrl+x b`** picks a code block (`b` for block). `ctrl+x` is chord's
  leader (`ctrl+x a` for what waits on the person), so the leader line names
  it (`leader-*`):

  ```
    ctrl+x …  b a code block · a the one that waits · esc never mind
  ```

- **Picking.** The newest code box on screen is picked; if none is on
  screen, the newest in the transcript, and the view scrolls to show it
  whole. The picked box's border, label and icons turn to the accent colour,
  and the status line names the keys (`picked-*`):

  ```
   ┌─ sh ────────────────────────────────────────── □ ! ─┐   (accent)
   │ deno task compile --all                             │
   │ for bin in dist/*/chord; do echo "built $bin"; done │
   └─────────────────────────────────────────────────────┘

    ↑ ↓ another block · c copy · ! into the prompt · esc done
  ```

  - **↑ ↓** move to the block above or below, across replies, scrolling the
    transcript so it is whole in view (`picked-up-120x40`).
  - **c** copies it (§2) and ends picking.
  - **!** puts it into the prompt (§4) and ends picking. On a block without
    the `!` icon it does nothing, and the status line leaves it out
    (`picked-ts-120x40`).
  - **esc** ends picking with nothing done.
  - Any other key ends picking and then does what it does today; the wheel
    and pgup/pgdn scroll as usual and keep the pick.
- **Why not plain keys.** Tab is `chat:steer` during a turn and the lists'
  completion; ↑ ↓ are history; letters are text. A mode reached through the
  leader owns its keys only while it lasts, as the agents list does.
- **No code block in the transcript:** `ctrl+x b` leaves the note `No code
  block to pick` for 3 s.
- **Rebindable**, in `bindings.ts`, in a `CodeBlock` context:
  `codeBlock:pick` (`ctrl+x b`, Global), `codeBlock:copy` (`c`),
  `codeBlock:prompt` (`!`), `codeBlock:previous` (`up`), `codeBlock:next`
  (`down`), `codeBlock:cancel` (`escape`).
- **The shortcuts panel**, two lines, after `ctrl + x a for what waits on
  you`:

  ```
    ctrl + x b to pick a code block
    c ! to copy a block or put it in the prompt
  ```

  The panel scrolls at 80×24 since CHD-378, so two more lines cost nothing
  but a row of scroll.

## 4. After "put into the prompt"

The prompt box in bash mode holding the command, the cursor at its end,
nothing run (`prompt-*`):

```
╭──────────────────────────────────────────────────────────────────────────────╮
│ ! deno task check                                                            │
╰──────────────────────────────────────────────────────────────────────────────╯
  ! for bash mode
```

It is today's bash mode exactly, as if the person had typed `!` and the
command: Enter runs it in the session's directory, its output held for the
agent ahead of the next prompt; backspace on an empty draft leaves bash
mode; esc and ctrl+c behave as in bash mode today.

- **A draft already in the box** is never replaced: nothing is put in, the
  draft stays, and the status line says `The prompt holds a draft · ctrl+c
  clears it` for 3 s, in the warning tone of a notice whose ask did not
  happen.
- **During a turn** it goes in all the same; bash mode during a turn works
  as today.

## 5. Open for the owner: what goes into the prompt

Three cases, each with options, each mocked as the prompt box after `!`
(`q-*`, at both sizes).

### a. A block of several lines

```sh
deno task compile --all
for bin in dist/*/chord; do echo "built $bin"; done
```

- **A. The whole block, as its lines** (`q-multi-a-whole-*`). The box holds
  both lines; Enter runs them as one script, in order. What the agent wrote
  runs as written. *Recommended.*

  ```
  │ ! deno task compile --all                                    │
  │   for bin in dist/*/chord; do echo "built $bin"; done        │
  ```

- **B. The first line only** (`q-multi-b-first-*`). The rest is left to a
  copy. Safe, but a `for` loop or a heredoc split over lines is cut.
- **C. The lines joined with ` && `** (`q-multi-c-and-*`). One line that stops
  at the first failure; breaks any construct that spans lines.

### b. Lines that start with a `$ ` prompt

```sh
$ bun install
$ bun test tests/parse
```

- **A. The `$ ` taken off each line that starts with it**
  (`q-dollar-a-stripped-*`). *Recommended:* `$ bun install` would try to run
  a command named `$`.
- **B. Kept as written** (`q-dollar-b-kept-*`), the person edits it.

### c. A `console` block with commands and output

```console
$ bun test tests/parse
bun test v1.4.3

 12 pass
 0 fail
```

- **A. Only the `$ ` lines, the prompt taken off** (`q-console-a-commands-*`);
  a `console` block with no `$ ` line gets copy only, no `!`.
  *Recommended.*
- **B. Every line, output too** (`q-console-b-all-*`), the person deletes what
  is not a command.
- **C. Copy only for `console`** (`q-console-c-copy-only-*`): `!` stays on
  `sh` and `bash`.

## Colour roles

- Icons: the text's own colour; border and label dim, as today.
- A picked box: `accent` for its border, label and icons.
- The copy note: as CHD-172's. The draft notice: `warning` (the `failed`
  tone).
- The prompt after `!`: bash mode's `bash` colour, as today.

## Why

The owner wants a block one press from the clipboard or the shell. The icons
sit on the border so the code a person reads and copies is unchanged, in
glyphs every terminal draws in one cell. A key path that goes through
chord's leader and a short picking mode reaches every block without taking
a key the prompt already owns, and it reads on screen as the box lighting
up with its keys under the prompt. Putting the command into bash mode rather
than running it keeps the person's Enter between an agent's text and their
shell.
