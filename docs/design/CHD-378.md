# CHD-378: what a team run, a task agent and the window have spent

**Board task CHD-373** (this page keeps quarry CHD-378's name). Written
2026-10-13, brought up to date on 2026-10-19 for claude-agent-acp 0.93,
codex-acp 2.2.2, the agents studied in CHD-433, and the background view
(CHD-424, CHD-2, CHD-462). Each passage that changed is marked
**Changed 2026-10-19**.

What changed, in short:

- **Codex's estimate is whole.** CHD-374 is closed. At 2.2.2 the answer to
  `session/prompt` carries the whole turn's tokens, and chord prices that.
  The "may undercount" caveat is gone.
- **More agents, and more ways of reporting nothing.** dimcode sends a
  session total, dirac's answer is a session total read as a turn's, and
  several agents report spend only off the standard path, or not at all.
  Any total needs the "not reported" rule, now for most agents.
- **A task's spend is still dropped.** Checked again on 0.55.2: main's
  `/cost` after a task reads its own three turns, and the task's block
  reads `Done (5 tool uses · 2s)`.
- **Tasks have left the agents list** for the background view (CHD-424),
  so option D now has two places: the task's block and its row there.
  CHD-2's `agent` items have no figure of their own (below).
- **The options stay A–F.** None is moot. Only D grew, by its background
  row.

The owner asked (2026-10-13) whether chord can say how much money a run or a
team spent. Today it says this for one session at a time: `/cost` reports
the session in front. This document covers what each kind of agent reports,
what chord does with it today, and the options for showing spend per team
run, per task agent and per window. **Nothing here is built.** The owner
picks among the options.

Every capture was taken with `bun chord:fake` in a `/tmp` directory, with
the fake `bugfix` team copied into `.chord/teams/`. The captures of today
are in `evidence/CHD-378/today/`, and the mocks are in
`evidence/CHD-378/mock/`. Each mock is laid out to exact width (120×40 and
80×24) from those captures, and only the part the option changes is
different. The fake spends $0.0125 and 2,000 tokens a turn, so the sums in
the mocks are the fake's figures, added by hand.

Some of this matters for any total:

- **Claude's figure already includes Claude's own subagents.** The Task
  tool's subagents run inside the same SDK query, so `total_cost_usd` counts
  them. chord's own `spawn_task` agents and long-lived children are separate
  sessions on separate adapter processes. No other session's figure includes
  theirs, so adding them up never counts the same money twice.
- **Claude's figure is per adapter process.** It is cumulative for the
  process. After `--resume` a new process starts. Today chord shows the
  record's last cost until the agent sends a new one. I have not checked
  live whether the new process starts from zero or carries the old total.
  That decides whether "the window's spend" can be told apart from "the
  session's whole life" for claude.
- **Codex's estimate covers the whole turn** (Changed 2026-10-19). The
  2026-10-13 concern that it priced only the last request is settled: at
  2.2.2 the answer's usage is the whole turn's, and `usage_update.used`,
  still the last request's, only sets the context shown (CHD-374).
- **`_meta.quota` is not money** (Changed 2026-10-19). claude and codex
  send a per-model quota to every client. It says how much of a plan's
  allowance is left, not what was spent, so no option adds it up.
- **dirac's tokens would count twice** (Changed 2026-10-19). Its answer is
  a session total, so a sum of turns grows faster than it spent. That is a
  defect of chord's reading, apart from this question. A total over dirac
  takes its `cost`, not its tokens.
- **Claude's background agents (CHD-2) have no figure of their own**
  (Changed 2026-10-19). They run inside the parent's query, so their spend
  is already in the parent's `total_cost_usd`. Their rows in the background
  view show none, and no total adds them again.
- **An estimate exists only for a model the price data knows.** On an
  unknown model the codex row shows tokens and no cost.
- **Every figure is in USD**, as each agent and the price data report it.
  ACP lets a cost carry another currency, and two currencies cannot be
  added. Nothing seen so far uses one.

## What any option has to decide

These come up in every option below, so they are listed once. Each is the
owner's to answer.

1. **What a sum says when one part is chord's estimate.** `/cost` already
   writes `$0.4120 (chord's estimate)`. That suffix doesn't fit in a list
   column, a tab bar or a `Done (…)` line. The mocks use `~$0.4120` there.
   In a total, `~` means at least one part of it is an estimate.
2. **What a sum says when one part reported nothing.** Leaving it out
   understates the total, and counting it as zero claims to know it was
   zero. The mocks show the known sum and say beside it how many reported
   nothing (`Total ~$0.4370 … 1 not reported`).
3. **Whether a closed agent still counts.** A member closed by its lead, a
   task that has ended, and a team run that has finished all spent money.
   If their rows leave the list, the only place left to show it is a report
   such as `/cost`.
4. **"This window" or "this session's whole life".** For a resumed
   session, the record holds what it spent before this window. Main's
   `/cost` already shows the record's figure. Should a window total count
   from when the window opened, or include everything the resumed sessions
   spent before?
5. **Tokens beside money.** Tokens from different models add up to a
   number, but it means little. Claude Code's task block says tokens and
   not money. Money is the only figure that adds up across models.

## The options

There are three needs: a team run, a task agent and the window. Each option
below meets one or more of them. They can be combined, since none rules
out another.

## A session's whole spend (Q58, for CHD-373)

The owner (Q58, 2026-10-19): `/cost` shows the cost of the whole session,
not only since this window opened; the spend the session's record holds
from before a resume or a restart counts too. With Q59 (closed agents stay)
and Q60 (the table shows once there is more than one session).

### What the agents give

From `docs/agent-capabilities.md` and claude-agent-acp's source. An agent's
cost is cumulative in every case; what differs is what it counts from.

| Agent | Cost it sends | Counts from | Sent again on load |
| --- | --- | --- | --- |
| claude (0.93) | at each turn's end, the SDK's `total_cost_usd` | **this opening**, as read in source: the adapter keeps it per query and does not restore it on load (`dist/acp-agent.js:4996-5011`); not checked live | no |
| codex | none | — (chord prices each turn's tokens) | — |
| dimcode | after each turn, 0 when unpriced | **the session**, read from its own store (dm20) | no on resume (dm5) |
| kilo, opencode | at the turn's end | **the session**: "the session's sum" (ki17, op15) | not stated |
| dirac | when the provider gives one | not stated | yes, after replaying its journal (di5, di20) |
| goose | when goose knows it | not stated | yes, after new and load (go4, go21) |
| minimax | after each prompt | not stated | not stated |
| the rest | none | — | — |

chord's own estimate, for an agent that sends no cost, already carries
across a resume (the enricher's wire is rebuilt from the record).

### What the record keeps

Two additions, and nothing else (checked against `src/session/record.ts`
with developer).

**An `opened` line at every opening**, first and later, with its time:

```
{"type":"opened","at":1760900000000}
```

**Why:** today a first opening writes a `session` header, but a resumed one
writes only a `state` line, which chord also writes whenever the model or
mode moves, and `disconnected` is written only when chord saw the process
go. Nothing in the record says where one opening ends and the next starts,
and a turn's own cost (below) is only defined within one. In records
written before this change, a resume is unknown and is not guessed.

**The turn's own figures at its end:** the `usage` line a turn already
writes (its tokens) also carries **that turn's own cost**, whether it is
**chord's estimate**, and **the model** it ran on, written when the turn
ends rather than read back from the last `state` line, since a switch
mid-turn or a model never reported would make that a guess:

```
{"type":"usage","turnId":"…","usage":{…tokens…},"cost":{"amount":0.0125,"currency":"USD"},"estimated":true,"model":"gpt-6.1-sol"}
```

An agent's own cycle (CHD-426) gets a line of its own the same way, under
the cycle's id, since its spend lands outside any turn. A turn with no cost
from anyone writes no `cost`.

### How a turn's own cost is found

Never from the agent's figure alone, which counts from different places:

- **Within one opening** of the session (from `session/new`, load or resume
  to its close), a turn's cost is the agent's last cost after the turn
  less the last cost it sent before the turn in the same opening. Every
  agent above is cumulative within an opening, whatever it counts from.
- **A cost sent on load** (dirac, goose) is the opening's starting point
  and is not a turn's.
- **chord's estimate** is the turn's tokens priced, as today; it is a
  turn's cost already.
- **A cost that arrives after its turn's result** (Claude's order) still
  counts to that turn, since trailing updates fold under the last turn id.
- **A turn cancelled before its cost arrives** may get it late, or never.
  A cost that comes after the next prompt has started counts to the new
  turn. **The split between those two turns is approximate; the session's
  total stays right**, since every cost is still counted once.
- **An agent's own cycle** is a turn by its own id: its cost is the
  difference at the autonomous `usage_update` that ends it, and a cycle
  with no usage adds nothing.

### How `/cost` adds it

**The whole session's cost is the sum of its turns' costs:** the record's
turns from before this window and this window's, each counted once by its
turn id, as tokens already are (`addTurn`). **Sums are per session:** turn
ids are unique within a conversation, not across sessions, and a task or a
child has a record of its own, so the window's table adds each session's
total, never turn ids across sessions. chord never adds an agent's
cumulative figure itself, so nothing is counted twice across a resume.
`Total cost` keeps its label; `(chord's estimate)` when every turn's cost
was chord's, `(part chord's estimate)` when some were, as C's table says.

### Not settled by Q58, for the lead

- **The first turn after a resume, for an agent that counts from the
  session and sends nothing on load** (dimcode; kilo and opencode as far as
  the study says). Its first cost after a resume is the whole session's, so
  the rule above would count every earlier turn again. Nothing on the wire
  tells this from Claude, whose first cost after a resume is that turn's
  alone. Options:
  1. **chord keeps what each agent counts from**, beside its registry
     entry: claude per opening; dimcode, kilo, opencode per session;
     unknown for the rest. For a per-session agent the first turn's cost
     is its figure less the record's total. For an unknown one, that one
     turn is left out and `/cost` says `1 turn not counted`. Never wrong,
     at the price of a list to keep true.
  2. **Leave out the first turn after a resume for every agent that sent
     nothing on load,** and say so. No list, but Claude loses one turn's
     cost at every resume.
  3. **Take the first cost after a resume as the session's when it is at
     least the record's total, else as the turn's.** No list, but it is a
     guess, and wrong when a turn costs more than everything before it.

  Recommended: 1. Claude is the agent this matters for most, and only 1
  counts it right. It is the only option that never guesses or drops a
  turn the agent did report.
- **Records written before this change** have tokens per turn but no
  turn's cost. Options:
  1. **Count their last recorded cost as one sum** for the time before
     this change, marked in `/cost` as `as last reported`. Exact for
     chord's estimate and for per-session agents; for Claude it is the
     last opening's cost only.
  2. **Count nothing from them** and say `spend before <date> not
     recorded`.

  Recommended: 1. It is exact in most cases, and the mark says where it
  may be short.

## Keys

`/cost` and `/team show` are commands, so C and B need no new key. A, D, E
and F add no action. If the owner wants A or E to be switched on and off,
that is a setting or a new key, and it goes into the shortcuts panel.

## Colour

No option adds a colour. In A and E the figures take the dim colour of the
list's state column and the tab bar's directory, which already read in
both a dark and a light theme. In C and D the figures inherit the report's
and the block's text. `~` and `not reported` are words, not colour, so they
survive a capture and a terminal without colour.
