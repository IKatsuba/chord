# CHD-468: chord's crash screen

When chord's tree throws while drawing, OpenTUI's root ErrorBoundary
replaces the whole tree with its own fallback: the error in red and its
stack. In the compiled binary that fallback first threw `jsxDEV is not a
function` (fixed by the jsx-dev-runtime alias, U1); once it painted, it had
no way out, since chord's key handlers went with the tree it replaced
(Q78). The owner chose (Q78, option 1): a boundary of chord's own around
`<App>` that shows the error, and any key quits.

## Today

`evidence/CHD-468/after-*.txt` from a74ffb71: OpenTUI's fallback through
the CHD-466 route (a refused `agents.codex.command` on `--resume`), at
120×40 and 80×24. What reads well there is kept: the two-column indent,
the message on top in the error colour, the stack under it with its
frames indented, the message word-wrapped at 80 with the indent kept, a
blank top row. What is missing is a way out and the words for it.

Top to bottom, at two columns' indent:

1. **A blank row.**
2. **The message**: `String(error)`, so `Error: <message>` with the error's
   own name (`TypeError: …`). A thrown value that is not an Error is
   written as `String(value)`. It word-wraps at the window's width, every
   wrapped row at the same two columns; a word longer than the row breaks
   inside. A message with newlines keeps them.
3. **The stack**: the frames of `error.stack`, the lines after the
   message, each as the stack writes it (`    at …`, so six columns in
   from the window's edge). All the frames the error carries are shown
   (Bun keeps ten), as far as the height allows (below). A frame wider
   than the window is cut at its right edge with `…`, not wrapped: a
   wrapped frame's path no longer reads as one. No stack, no rows.
4. **A blank row.**
5. **The hint**: `any key to quit · chord prints the error to stderr as it
   exits`. Claude Code's hint form (`esc to interrupt`): the key, then
   what it does. It is the only place the screen says what to do, so it is
   the last row to go (below).

The block sits at the top, as OpenTUI's did; the rows under it stay empty.
There is no title or frame: the message is already the headline, and a box
would cost two columns at 80.

## Colours

The palette of the theme chord is drawing in (`src/ui/theme/theme.ts`):

| Part | Role |
| --- | --- |
| the message, every wrapped row of it | `error` |
| the stack's frames, the `… 7 more frames` row | dim |
| the hint | dim |

OpenTUI painted the frames white; dim keeps them under the message, as
chord's status and error lines draw a detail under a headline. Under
`NO_COLOR` nothing is painted, so the screen is the terminal's own text and
dim. If chord fails before its theme is settled, the screen takes the
`dark-ansi` palette, whose `error` is the terminal's own red and reads on a
light or a dark background.

## The key

- **Any key quits**: a printable key, Enter, Esc, Tab, Backspace, an arrow,
  a function key, and every Ctrl, Alt or Cmd chord, Ctrl+C and Ctrl+D
  included. A press of Shift, Ctrl, Alt or Cmd alone (the kitty protocol
  reports it) is not a key and does nothing; nor does a click, a scroll or
  a paste, so a stray wheel turn does not close what the person is
  reading.
- **What it does**: the same as chord's crash path for an uncaught
  exception (`src/ui/app/renderer.tsx`, `giveBackOnEveryExit`): the window
  closes and the terminal is given back (the alternate screen left, the
  cursor shown, raw keys and the mouse off), then the error is written to
  stderr and chord exits 1. The key itself reaches nothing, the shell
  included.
- A signal (SIGTERM, SIGHUP, …) still ends chord as it does today.
- No delay before a key counts. A key the person was typing as chord broke
  may close the screen unread; the error is on stderr after, so nothing is
  lost.
- **The shortcuts panel** lists it, last, as `any key` · `to quit the
  crash screen` (32 columns). The panel cannot be opened from the crash
  screen; the entry is there so the key is named where every key is. The
  panel stays at 40 lines, 20 rows at 80×24 (Q80, option 3): the two
  newline lines, `\ + enter` · `for a newline` and `shift + enter` ·
  `for a newline`, become one, `shift or \ + enter` · `for a newline`,
  both presses kept, as `ctrl + d or ctrl + c` · `twice to quit` keeps its
  two.

## stderr after exit

chord writes it after the terminal is given back. While the screen is up,
React logs the caught error through console.error; a narrow filter of
chord's on console.error, put in place before the root is made, drops that
one log, so it never reaches the window, not even for a moment (Q82,
option 1). Nothing but the crash screen is on the
window. After exit chord writes the error:

```
Error: codex not started: agents.codex.command in .chord/settings.json: expected a string, got a number
    at <anonymous> (/$bunfs/root/chord:216192:24)
    …
```

As the uncaught-exception path writes it: `error.stack`, or `String(error)`
when there is none, then a newline. The whole stack, uncut, whatever the
screen showed. No React component stack, no hint, no colour.

## Too small

There is no separate too-small screen: the same block gives up rows in
this order as the window shrinks, and lays out again on a resize.

1. **Frames**, from the bottom. The last frame shown is followed by
   `      … 7 more frames` (dim, at the frames' indent). The first cut is two frames, since the row a last frame frees is the one this row takes.
2. **The `… more frames` row**, last of the stack: with every frame gone it
   stands alone (`      … 10 more frames`), saying there is a stack and
   that it is on stderr after, and goes only when the next row is needed.
3. **The blank rows**, the top one first, then the one over the hint.
4. **The message's rows**, from the bottom; the last one kept ends in `…`.
5. **The hint** is the last row standing: a window one row high shows
   only it.

Narrower than the hint, the hint is cut with `…` at the right edge like a
frame. The message never is: it wraps.

## States

The screen has one state: it shows the error until a key. It does not
stream, wait on an agent or change; a second error while it is up is not
drawn (the first is the one that broke chord) and goes to stderr after the
first.

## Why

- **Keep OpenTUI's look.** The captures read well at both sizes; only the
  way out was missing. A new layout would make a person who saw the old
  one in 0.56 read it again for nothing.
- **Any key, not one.** A person who has never seen this screen should not
  have to find the right key: whatever they press does what they want,
  which is their terminal back.
- **The error again on stderr.** The alternate screen takes the window
  with it when it closes; on stderr the error stays in the scrollback for
  a bug report.
