### Steps

The step depends on the window, never on the list. The list's length only sets
how many rows it gets. `step` and the rows are the result of one pure function,
below; each step's parts are:

| Step | When | Art | Words | Art + words rows |
| --- | --- | --- | --- | --- |
| `full` | rows ≥ 32 and columns ≥ 60 | `SPLASH_MARK` (9×8), 3 blank columns, `block` (45×6): 57 wide, 8 tall | 1 blank row, the tagline, the version line | 11 |
| `compact` | else rows ≥ 18 and columns ≥ 40 | `MARK` (4×4), 2 blank columns, `tiny` (19×2): 25 wide, 4 tall | the version line | 5 |
| `line` | else the list keeps 3 rows or more with this line | none | the bold-and-dim line | 1 |
| `none` | else | none | none, and no gap above the agents' picker | 0 |

In both art steps the mark and the word are centred on each other vertically:
`block` has 1 blank row above and below it, `tiny` the same.

The words:

| Part | Text | Style |
| --- | --- | --- |
| Tagline | `One terminal for every coding agent.`, the README's own, as a constant | plain |
| Version line, agents | `v0.65.0 · ~/src/app` | dim |
| Version line, resume | `v0.65.0 · claude · ~/src/app` | dim |
| `line`, agents | `chord v0.65.0 · ~/src/app` | `chord` bold, the rest dim |
| `line`, resume | `chord v0.65.0 · claude · ~/src/app` | `chord` bold, the rest dim |

The version is the manifest's, as `--version` prints it. `Start` takes it as a
prop from `main.tsx`.

### Rows

```ts
const ART = { full: 11, compact: 5, line: 1, none: 0 };
const LIST_CAP = 14; // `full` only

function startLayout({ columns, rows, lines, framed, hintRows }) {
  // The picker around its list: the agents' title, gap, gap and hint; the
  // frame's two borders, title, sentence, gap and gap, and its hint.
  const around = (framed ? 6 : 3) + hintRows;
  // One gap above the picker, one row left as a margin.
  const room = (art) => rows - art - 1 - around - 1;
  const step =
    rows >= 32 && columns >= 60 ? 'full'
    : rows >= 18 && columns >= 40 ? 'compact'
    : room(ART.line) >= 3 ? 'line'
    : 'none';
  const cap = step === 'full' ? LIST_CAP : Infinity;
  // `none` gives up the margin too; the frame keeps its row above.
  const fits = step === 'none' ? rows - (framed ? 1 : 0) - around : room(ART[step]);
  const whole = lines <= Math.min(fits, cap);
  // Where it is not whole, `… +N more` takes a row of its own.
  const listRows = whole ? Math.max(lines, 1) : Math.max(1, Math.min(cap, fits - 1));
  const pageRows =
    ART[step] + (step === 'none' && !framed ? 0 : 1) + around + listRows + (whole ? 0 : 1);

  return {
    step,
    listRows,
    top: Math.max(0, Math.floor((rows - pageRows) / 2)),
    column: Math.max(1, Math.min(columns - 2, framed ? 84 : 62)),
  };
}
```

`lines` is what the whole list takes: the number of agents (1 for `No agents
available`'s row), or for resume the sum of its choices' lines, as a session's
label wraps (below). `hintRows` is the hint wrapped by `wrap-ansi` at the
column's inner width, `column − 2` for the agents and `column − 4` for the frame,
from the same words the picker draws, so a rebound or unbound Esc counts right.

This lives in a pure module, `src/ui/app/start_layout.ts`, with its tests in
`tests/ui/app/start_layout_test.ts`. The prototype runs this function, and this
is what it returns; the captures show the same:

### The list is the last thing to give way

Art gives way first, then the tagline, the words, the gap and the margin; the
list never falls under one row. The cap of 14 belongs to `full` alone: past it
the page stops being a title page, so a long list scrolls in a 14-row window
under `… +N more`. `compact`, `line` and `none` have no cap and take every row
they have. So a taller `compact` window (19 rows of 28 at 31 rows) can show more
than `full` at 32 (14): this is accepted, and a long list never moves a window to
another step.

The list's window scrolls as `PickerList` does today, and `… +N more` counts
every hidden row, above and below, so it stays until the whole list shows. The
page's height does not change on a move, and neither art nor hint shifts.

### Columns

| Part | Width | Place |
| --- | --- | --- |
| Art | its own, 57 or 25 | centred on the window |
| Tagline and version line | their own, at most `columns − 2` | centred on the window |
| Agents' column | `min(columns − 2, 62)`, its 1-column padding as today | centred on the window; its text left-aligned inside |
| Resume's frame | `min(columns − 2, 84)` | centred on the window |

The column's width comes from the window alone, never from the labels. So a
longer or shorter list, a long agent name or a move of the highlight moves
nothing: the art stays centred on the window, and the column's left edge stays
where it is, with its right side empty where labels are short. Art and column
are centred apart, not aligned with each other: at 120 columns the art starts at
32, the column at 29. Odd leftovers fall where Yoga's centring puts them.

### Too wide for its place

- **A row of the list** does not wrap: an agent's label is cut by OpenTUI's
  `truncate`, a `...` in its middle, exactly as `CUT` does today (39×24 shows it).
  Labels are not rewritten. No agent's name and title in today's catalog is cut at
  a column of 62.
- **A session's label** wraps under its own start and is never cut, as
  `docs/guide.md` says (below).
- **A hint** wraps at its spaces, as today's `TEXT` does, and `hintRows` counts
  its rows. At a column of 62 or a frame of 84 neither wraps.
- **The version line** cuts its directory from the left with `cutPath`
  (`src/ui/pickers/mcp.ts`), to what `columns − 2` leaves beside the rest:
  `v0.65.0 · claude · …/services/billing/acme-api`. If the rest alone is too wide,
  `CUT` cuts it.
- **The frame's sentence** stays `CUT`, as today.

## Colours

By role, in every theme; plain and dim are the terminal's own.

| Part | Role |
| --- | --- |
| Mark | `mark`, through `markColour(tones, chalk.level)` and `markRows`, as the header |
| Wordmark's solid letters (`c1`) | `mark`: the gradient at its middle stop, else `tone` |
| Wordmark's shadow lines (`c2`; `block` only) | `mark`: the gradient's last stop, else `tone` |
| Tagline | plain |
| Version line | dim; `chord` bold in `line` |
| Agents' title, rows, hint | as today: plain, plain and dim, dim |
| `❯`, highlighted row | `permission`, as today |
| Resume's frame and title | `permission`, as today; the dim border's grey and plain bold without it |

The wordmark's two colours come from `markColour`'s result, so they follow the
terminal's depth as the mark does: `markPaint(stops, level)` at `MIDDLE` and at 1
for `truecolor` and `256` (an `ansi256(n)` then, read by `colour()`), `tone` for
both at `16`. On a truecolor terminal:

| Theme | `c1` | `c2` | Mark |
| --- | --- | --- | --- |
| `dark`, `dark-daltonized` | `#47e7a5` | `#15c7a2` | `#89f5b3` → `#47e7a5` → `#15c7a2` |
| `light`, `light-daltonized` | `#147d55` | `#0a5e57` | `#1e9a5e` → `#147d55` → `#0a5e57` |
| `dark-ansi` | `greenBright` | `greenBright` | `greenBright` |
| `light-ansi` | `green` | `green` | `green` |
| `NO_COLOR` (`PLAIN`), or no colour from the terminal | no wordmark | no wordmark | the terminal's foreground |

The daltonized themes change only the diff, so the page is the same.

**No `mark`, no wordmark.** `<ascii-font>` takes a real colour only: an undefined
one crashes it at construction (`rgba.buffer`, seen under `NO_COLOR` in the
prototype), and its default of white would vanish on a light terminal. So where
`markColour` says `none`, draw bold `chord` as plain text in the wordmark's place
instead, one row, centred beside the mark; the step's rows do not change. A test
draws `Start` with `PLAIN` at `full` and at `compact`.

`<ascii-font>` is OpenTUI's own and takes `selectable={false}`, as `TEXT` does.
Its fonts are capitals only, which is the owner's choice (Q321): `CHORD`. The mark
is the header's: share one `Mark` component in `src/ui/header/` rather than draw
it twice.
