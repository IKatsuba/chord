# CHD-565: a setting for the list of agents chord offers

The questions for the owner, before any code. The task's seven open questions
come down to five, as one decision settles two pairs: the key's shape with how
the files combine it, and what the list governs with what happens to a name
outside it. A line marked **Recommendation** is the designer's, with its reason;
every choice here is the owner's.

Held whatever the answers: with the setting absent, chord behaves as it does now.

## Question 1: where it is set

Screen-only is not an option: every key in the settings file is read from the
file, so the file is always a way to set it.

| Option | What it means | Trade-off |
| --- | --- | --- |
| **File only** | One new key. No screen, no key, no change to `src/AGENTS.md`. `chord agents` gives the names to copy | The smallest. The person edits JSON, as for `agents.<name>.command` today |
| **File and `/agents`** | A framed picker over the transcript, as `/theme`, ticks and orders the list, saved to the user's file | `src/AGENTS.md:5` changes, and `saveSetting` takes a key beyond the user-only ones. A new widget: `PickerList` has neither ticks nor reordering. A project's list may then outrank what the screen writes (question 2), which the screen must say |
| **File, `/agents`, and `e` on the title page** | As above, and reachable where the long list is seen | All of the above, and the page's hint grows. The page has no session and no write path today, and it would need the editor before the first paint is left |

New keys for a screen, all in the shortcuts panel: `/agents`; ↑/↓ or j/k to move,
Space to tick, J/K to reorder, Enter to save, Esc to cancel; `e` on the page in the
third option. Numbers show the order; unticked rows have none. Colours: frame,
title and highlighted row in `permission`, the rest plain and dim, as `/theme`.

**Recommendation: file only.** A list like this is set once and rarely changes,
which does not pay for a new multi-select widget and a third writer. A screen can
come later without changing the key.

## Question 2: the key's shape, its order, and how the files combine it

These are one decision: a per-agent flag merges by the rule `agents` already has,
and only an array needs a rule of its own.

| Option | Example | Order on screen | User and project |
| --- | --- | --- | --- |
| **Array, the later file replaces** | `"offeredAgents": ["claude", "codex"]` | The array's | A project's list replaces the user's whole, as `agent` does. One sentence of documentation. A committed project list can hide the person's own agent from the menu |
| **Array, user's file only** | same | The array's | Joins `theme` and `editorMode`: in a project's file, reported and left out. It is about a person, and it fits a screen best, as nothing can outrank what is written. A project's own agent is offered only if the user's list names it, and then counts as unknown in every other directory (question 5) |
| **Array, lists joined** | same | User's, then the project's new names | Concatenated and deduplicated, as Claude Code's `availableModels`. A project can add and never shorten |
| **Flag on each agent** | `"agents": { "claude": { "listed": true } }` | The catalog's: none of its own | Merges agent by agent with no new rule, and a project can set `false`. Any `true` means only those, an implicit switch. Number keys follow the catalog, not the person |

A list of what to hide (`hiddenAgents`) is not offered: the owner asks for the list
they want, and each `bun dev registry` would add agents to a hide-list's result.

The name follows question 3. `offeredAgents` says what a menu does. `availableAgents`,
after `availableModels`, says what an allowlist does, and would promise too much of a
menu. `agentList` is one slip from the existing `agents`, which sits beside it.

**Recommendation: an array whose order is the screen's, the later file replacing,
named `offeredAgents`.** Order is half of what a short list is for, as 1–9 picks by
it. Replacing is the rule every other single value has. With an allowlist in question
3 the recommendation moves to the user's file only, as a committed list could then
lock a person out of their agent.

## Question 3: what the list governs, and a name outside it

This is one question: is the list a menu or an allowlist? It settles the task's
"what it governs" and "named directly" together.

| Option | Start screen | `/new` completion | `list_agents` | `chord <agent>`, `/new <agent>`, `open_agent`, team files |
| --- | --- | --- | --- | --- |
| **Start screen only** | the list | everything | everything | work |
| **What a person is offered** | the list | the list, in its order | everything | work |
| **What anyone is offered** | the list | the list, in its order | the list | work, though an agent is no longer told of the others |
| **Allowlist** | the list | the list, in its order | the list | refused: `No agent named x; chord knows …`, and a saved team naming another runtime fails its check until the list grows |

In every option:

- **`chord agents` stays whole.** It is where a person reads the names to put in the
  list, and the refusal for an unknown name points at it.
- **`@@` does not change.** It lists open recipients, not the catalog.
- **`--agent-command` still works.** A flag beats the files everywhere in chord.
- **`--resume` of a session still opens,** with an agent outside the list. Refusing
  would strand a person's own transcript.
- **The window's own agent stays in `runtimes`,** however it was named, so `/new`
  with no name still opens it.
- **The `agent` key is unchanged:** outside the list, the first row is highlighted,
  as today's rule says. `-p` and every route that skips the picker do not read the
  list.

**Recommendation: what a person is offered.** The owner's complaint is the list a
person reads; it covers both places one appears, and refuses nothing. An allowlist
would break a saved team, such as one whose members run on `codex`, for a setting
meant to shorten a menu.

## Question 4: an agent on the list that is not installed

This settles "whether the PATH filter still applies" and "names only agents that are
not installed". npx and uvx entries and settings commands have no `found`, so all of
this concerns own CLIs alone.

| Option | What shows | Trade-off |
| --- | --- | --- |
| **The list wins: shown, with a note** | `cursor · Cursor · not on PATH`, the words `/new` already uses. Picking it gives today's refusal with where to install it, and exit 1 | A name the person wrote never vanishes. No special state: a list of only those shows them all. A row can fail when picked, which CHD-544 removed from the whole catalog |
| **The filter stays: hidden** | Not shown. If none is left: `No agents available`, and a sentence saying the list's agents are not installed | Picking cannot fail, and one settings file can serve several machines. A name in the file disappears with no word |
| **Shown, not pickable** | The row is dim and Enter does nothing; the note says where to install | Picking cannot fail and nothing vanishes. `PickerList` has no disabled row, and 1–9 and the highlight would need rules for it |

**Recommendation: the list wins.** It is the person's own word, and the refusal
already says exactly what to do. CHD-544's filter was right for a catalog the person
did not choose.

## Question 5: an empty list and an unknown name

A name is unknown when the catalog and this directory's settings commands do not
have it. A name defined only in one project's file is therefore unknown elsewhere,
if the user's list names it: any report repeats in every other directory.

| Option | Unknown name | Trade-off |
| --- | --- | --- |
| **Dropped, reported as a settings problem** | stderr, then a transcript note after a pick | The existing channel, no new drawing. The title page, where the effect is seen, says nothing: a typo looks like a missing row |
| **Dropped, and named on the page** | As above, and one dim row under the hint: `Not an agent chord knows: cdex (settings.json)` | Seen at once. One more row in `startLayout`, and one more thing on a title page |
| **Shown as a row** | `cdex · not a known agent`; picking it gives `Unknown agent "cdex"` | Seen in its place. A typo's row can be picked, only to fail |
| **The whole key ignored** | A settings problem; the whole catalog is back | The simplest, and hard to miss. One typo costs the whole list |

For `[]`, whichever is chosen:

- **Refused as invalid (recommended):** `min(1)` in the schema, so the existing
  `"offeredAgents": …, ignored` problem is said and the setting counts as absent. The
  whole catalog shows. A project cannot hide every agent by accident.
- **Taken literally:** today's `No agents available` and only `Esc to cancel`, with
  named starts still working. Offered only if the owner wants a page that picks
  nothing; say so with the answer.

A list whose names are all unknown has nothing left, and does not fall back to the
catalog: `No agents available`, and a sentence naming the setting.

**Recommendation: dropped, and named on the page.** The stderr line goes under the
alternate screen, so the person looking at a short list would get no word of why a
row is missing.
