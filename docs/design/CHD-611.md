# CHD-611: riff's screenshots

The riff images `bun dev screenshots` takes for the guide's riff sections.
They follow the existing shots (`scripts/dev/screenshots.ts`): one shot per
image, chord from source in its own tmux session, a home of its own under
`/tmp/chord-shot.<name>`, the dark theme, every shot `COLUMNS` × `ROWS`
(120 × 37), drawn in the Chorded pane and saved as
`docs/images/<name>.png`. Every riff shot runs on riff's fake provider and
fake sign-in (`CHORD_RIFF_QA_*`), with in-memory secrets: never a live
provider, sign-in or keychain.

## The images

| Image | Scene | State shown | Guide section |
| --- | --- | --- | --- |
| `riff-sign-in` | `chord riff` signed out (`CHORD_RIFF_QA_STATE=signed-out`, sign-in `waiting`); choose ChatGPT, then device code | The sign-in box on the device-code step: the example address, the code, its expiry countdown and the copy and open choices | riff sign-in and sign-out |
| `riff-session` | auto mode; one prompt that edits a file and runs its test | `Update(<file>)` with its diff, `Bash(<command>)` with output and `… +N lines`, the reply; header `riff · ChatGPT · <model>`, the auto status line | riff's tools (the paragraph on `edit`, `write`, `shell`) |
| `riff-ask` | ask mode (shift+tab once); a prompt whose turn runs a shell command | The permission box: `Bash <command>`, `in <dir>`, `1. Allow`, `2. Allow this exact command for this session`, `3. Deny`; the working line `Waiting for permission…` | ask and auto |
| `riff-review` | auto; a prompt whose turn runs a command the fake reviewer cautions on | CHD-608's reviewed box: `Reviewed: caution` on the call, `The safety review held this:` and the rationale, `Allow once` / `Deny`, the countdown | ask and auto (the review) |
| `riff-skill` | a project skill under `.agents/skills/` and one MCP server from the fixture in the shot's settings; one prompt | `Skill(<name>)` with `⎿  Loaded skill <name> (N lines)`, then an MCP call `<server> - <tool> (MCP)(…)` with its result, then the reply | riff instructions and skills |
| `riff-model` | `/model` on riff | The model picker with the provider's list (several models, the current one ✔) | the live model list's paragraph |

No `riff-start`: `start.png` already shows riff as the picker's first row,
and the guide's riff sections start once riff is chosen. No image of a
skipped skill or server note: the guide quotes the sentence, and a picture
of a failure says no more than the text.

## What each shot needs to read as a person's session

- **A person's words in the prompt.** The existing shots type a person's
  sentence and pick the fake agent's scenario by `CHORD_FAKE_SCENARIO`. The
  riff fake provider picks its scenario from the prompt's start (`call
  shell {…}`), which would print that syntax in the image. The riff shots
  need the same: the scenario chosen outside the typed text, the prompt a
  sentence (`Rename greeting to welcome and run the tests`).
- **A model name, not `fake`.** The header, status line and `/model` show
  the provider's model. The existing shots give the fake agent real model
  names through settings (Claude Opus 5.5, GPT-6.1 Sol); riff's fake
  provider should offer the shot a list of plausible names the same way,
  and `riff-model` shows that list.
- **Neutral paths.** The shot's own `/tmp/chord-shot.<name>` home and
  `src/app` directory, as now; the sign-in fixture's example address and
  code.

## Sizes and states

One size, as every shot: 120 × 37, dark. A shot waits for its state
(`until`) before the capture: the device code drawn, the box open, the
reply's last line, the picker's list. Nothing is captured mid-stream except
`riff-ask` and `riff-review`, which are taken while the box waits.

## Paths in riff's rows (S0)

riff's edit summary names the file relative to the session directory
(`Updated greet.ts with 1 addition and 1 removal`), falling back to a
`~`-shortened path, then the absolute one, for a file outside it. A shell
call's permission and review boxes carry the `in <dir>` line under the
title, `~`-shortened (`in ~/src/app`), as CHD-485 draws them. No real or
temporary path (`/private/tmp/…`, `/Users/<name>/…`) is drawn where the
header shows `~/…`. The shots are retaken after this.
