# CHD-471: an agent's state, and what is not yet seen beside it

The owner (2026-10-19): they want to see that an agent is idle, and
`replied` must not stand in for the state, since behind it the real state
cannot be seen. Decided on this example:

```
  parser  codex · 6.1 Sol   ◦ idle 3m      ✓ new reply
  tester  codex · 6.1 Sol   ✻ working 41s
```

- **The state** is always what the agent is doing now: working, asking
  (permission, form or link), failed, or idle with how long.
- **Something not yet seen** (a reply, a message to it, a failure) is a
  separate mark beside the state. It never replaces the state, and goes
  when the person opens that agent.

## Today

Captured on the fake agent with `agents` then `team`
(`evidence/CHD-471/today/`). Each row has one slot, which holds either the
state or the unseen thing, most urgent first (`src/ui/agents/agents.ts`,

`← message from @main`, `✓ replied 13s ago`, `✻ working 8s`, and nothing
while idle and seen. So `parser` reads `✓ replied 13s ago` whether it is
idle or working again on another agent's message.

## The state slot

Exactly one, on every row, the session in front included:

| State | Glyph and words | Colour role |
| --- | --- | --- |
| asking | `● permission 17s`, `● input 17s` | warning |
| working | `✻ working 41s` | dim |
| idle | `◦ idle 3m` | dim |
| gone | `✗ exited`, `✗ failed to start` | error |

- **Idle** counts from when the agent last stopped working (its turn's end,
  or when it opened if it has not worked yet), in its first unit as the
  other states' times are written in a row (`41s`, `3m`, `1h`).
- **A failed turn is no longer a state.** The agent is still open and, once
  the turn has failed, idle; the failure is something not yet seen (below).
  `exited` and `failed to start` stay states, since the agent is gone.
- **Why `◦`:** a hollow dot beside the asking `●` reads as "nothing
  pending", and it is no glyph the list uses for anything else.

## The unseen mark

At most one, in a column of its own after the state, aligned across rows,
and gone once the person opens that agent (as today's unseen reply goes):

| Not yet seen | Mark | Colour role |
| --- | --- | --- |
| a failed turn | `✗ turn failed` | error |
| a reply | `✓ new reply` | success |
| a message to it | `← new message` | dim |

- **No time on a mark.** The state's time says how long ago the agent
  stopped, which is what `replied 13s ago` was standing in for.
- **No sender on `← new message`.** The row is short at 80 columns; the
  message names its sender once the agent is opened.
- **When several are unseen** (only on a folded team's row, as one agent
  has one), the first in the table above shows: a failure, then a reply,
  then a message.

## A team

- **A member's row** has its own state and mark, as any agent's.
- **The lead's row**, unfolded, has the lead's own state and mark.
- **A folded team's row** keeps today's rule for the state, the most urgent
  among its lead and members with the member named
  (`● tester: permission 8s`, `✻ coder: working 3s`). When all of them are
  idle, it reads `◦ idle 3m` from the one that stopped last. Its mark is
  the first unseen among them, by the table's order, unnamed
  (`✓ new reply`); unfolding shows whose it is.

## What gives way first

**The name and the state's words never drop and are never cut** (the lead,
2026-10-20, by the owner's standing rule that text wraps, CHD-473).

**First, at every width:** the name column is never wider than a third of
the list's width. A longer name wraps inside it, its next lines under its
first letter (and under the tree's `│` for a member). This comes before
anything gives way, since wrapping loses no word.

Then, when a row still does not fit:

1. the effort goes;
2. then the model, leaving the runtime;
3. then the mark's words, leaving its glyph (`✓`, `←`, `✗`, each its own
   colour);
4. then **the state goes whole onto the next line**, when it still does
   not fit beside the detail.

   - **Where:** the state column's place is set by the rows whose state
     fits beside their detail. A row whose detail is too wide for that
     puts its state on the next line **under its detail**, where the
     runtime starts, as `/team show` does (rule 3 there).
   - **Its mark goes with it**, after the state, as on any row.
   - A state still wider than that line wraps at its spaces; its words
     are never dropped. Its mark follows it on the same line where it
     fits, else on a line of its own.
   - **A detail wider than the line on its own** (a long runtime name)
     wraps at its spaces under its own start, and inside a word only when
     that word alone is wider; nothing is clipped at the edge.

   At 43 columns (39 inside the list's padding), a team folded under three
   agents:

   ```
       main       fake  ◦ idle 4s
       parser     fake  ◦ idle 13s        ✓
       docs       fake  ● permission 17s  ←
       bugfix     team · fake · 3 agents
                  ● tester: permission 8s  ✓
   ```

**Pending, on the board for the owner:** whether steps 1–3 may drop those
words at all, or whether they too must wrap. Recommended: they may. The
runtime stays, the model and effort show in the status line once the agent
is picked, and each mark's glyph and colour already say which kind it is.

**A wrapped row counts as many rows as it has lines** toward the list's
limit (4 at 24 rows, 6 at 40), so `… +N more` and a team's folding see the
height it really takes. Since a row's height depends on the width, whether a
team folds may change when the window is resized; that is expected.

**A row taller than the list's whole budget** (settled 2026-10-20, from
L1b's review): the list never takes more than its budget of lines (4 at
24 rows, 6 at 40), so the prompt and the status line always stay on
screen. Such a row, a long session title (CHD-445) for one, is read by
line, as CHD-430 reads a background row taller than its frame, with the
list's own keys and no new one:

- **While the prompt has the keys,** the list shows from its top. The tall
  row shows as many of its lines as fit, the gutter's `↓` on its last line
  in sight, and `… +N more` counts the rows after it, as today.
- **Once `↓` from an empty prompt gives the list the keys,** `↑ ↓` move
  through a tall row's lines first, one line a press, then on to the next
  row. The `❯` stays on the row's first line; while that line is out of
  sight, the gutter's `↑` stands in its place, and `↓` marks lines or
  rows below. `enter`, `x` and the rest act on the row wherever in it the
  view is.
- **The picked row is kept in sight** from its first line, as the list
  keeps it today; a resize shows it from its first line again. The view
  scrolls only as far as it must, as CHD-462's frame does: picking a
  tall row brings its first line into sight with the least move, so rows
  above stay while they fit (`main` in the mock below), and moving off it
  brings the next row whole into sight the same way.
- The row's other columns (its detail, state and mark) are on its first
  line, so they scroll out with it; the agent's state also stays in the
  status line's hint and the picker.

## The sessions picker and the tab strip

They read the same waits (`src/session/tabs.ts`), so they follow:

- **`ctrl+x w`** words each session as the list does: its state, then its
  mark, `◦ idle 3m  ✓ new reply`, `✻ working 41s`, `● permission 12s`. It
  already writes `idle`; that becomes `◦ idle 3m`. `here` for the session
  in front stays, and a failed turn becomes the `✗ turn failed` mark.
- **The tab strip** keeps one glyph per tab for the state, then the mark's
  glyph after it, both in their colours: `2 codex ✻✓` for a tab working
  with a reply not yet seen, `3 fake ✓` for an idle one. **Idle has no
  glyph on the strip:** a strip of `◦` on every quiet tab says nothing the
  person acts on, and the strip is for what calls them.
- **`/team show`** gives each agent its state, then its mark, before the
  last column (what it is doing or last said). Showing the mark there does
  not clear it. **Nothing on it is cut** (CHD-473):
  - the first line's quote of the job is the whole job, wrapping under the
    line's start;
  - the last column wraps inside itself while it has at least 20 columns;
  - with less, it moves to its own lines under the row, starting under the
    runtime column, and wraps there.
  - **when the row's own columns are still wider than the width** (a long
    model id, a long name), they wrap too, in this order, and nothing is
    hidden:
    1. the runtime and model cell wraps inside a column of at most a third
       of the width, at its spaces, and inside the model id only when the
       id alone is wider than the column;
    2. the name wraps inside its column the same way;
    3. if the row is still too wide, its state and mark go whole onto the
       next line, under the runtime column (`● permission 8s  ← new
       message`), above the last column's lines;
    4. the mode column (`default`, `acceptEdits`, `plan`) never wraps;
    5. **an effort**, where an agent has one, is the last part of the
       runtime and model cell (`fake · fake-large · high`) at every
       width, as the agents list writes it; there is no effort column and
       no `—` for an agent without one. It wraps with that cell and is never
       dropped;
    6. **on a screen so narrow** that the name, that cell and the mode
       still do not fit (below about 50 columns), the mode moves onto the
       state's line, before the state (`acceptEdits  ● permission 8s  ←
       new message`), and that line wraps at its spaces. Nothing is clipped
       at the edge.

    **Where a line breaks** (settled 2026-10-20): at a space, as the table
    library breaks, so a wrapped line may start with `· ` (`claude · opus`
    / `· high`). Nothing is cut, and the `·` still reads as the list's
    separator. Breaking only after a `·` would mean rewriting the
    library's input, for no gain to the person.
