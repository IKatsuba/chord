# CHD-607: riff's sign-in and sign-out

CHD-485's "The picker", A–G, "Signing out and switching", "Keys" and
"Colour roles" remain the specification. This adds only the window states
left open there and replaces CHD-606's interim start-failure surface.
Use the existing rounded prompt, framed choices, transcript rows and theme
roles. The provider, way, browser, code, failure and logout boxes keep
CHD-485's words.

## Browser callback clarification

The owner, through main as delegate, narrowed CHD-485 C: an older tab's
redirect leaves the box waiting only when it carries a code with another
sign-in's state. libfx refuses that mismatch. A stale redirect carrying
an error ends the attempt as denied because libfx reads the error before
the state; the failure box offers `Try again`. Section C now records this
behavior. No state check is added ahead of libfx's error handling.

## The window around the box

The box floats above the prompt as other pickers do. Opening and closing
it preserves the transcript, its scroll position, the draft, the prompt's
gap and permanent rows. At 80x24 a tall box may cover the header and old
transcript; its choices, hint, rounded prompt and status remain reachable.
Do not repeat the header inside the box.

| State | Header's agent line | Prompt | Status line |
| --- | --- | --- | --- |
| No signed-in session, including store recovery | `riff · not signed in` | Existing rounded prompt, unfocused while the box owns keys | `? for shortcuts`; no stale model, effort, mode or context |
| `/login` from a signed-in session | Existing `riff · ChatGPT · <model>` (or Grok), until success | Existing draft visible, unfocused | Existing session's model, effort, mode and context remain |
| `/logout` confirmation | Existing signed-in header | Existing draft visible, unfocused | Existing signed-in status |
| Successful sign-in or switch | `riff · <provider> · <model>` once the fresh session is ready | Ready prompt after the box closes | Fresh session's actual config and usage, as for any agent |
| Completed logout or lost credential | `riff · not signed in` | Chord's own commands only | `? for shortcuts`, then any ordinary transient notice |

While a box owns keys, typing does not edit or submit the draft. Esc has
that step's printed action; it never also interrupts a turn behind the
box. Working lines describe sign-in work, not a model turn. In particular,
waiting on the browser or code must not say `Working…` or count model
context. The waiting and finishing words remain C and E's.

Esc from the first provider step closes the box. With no signed-in
session, retain F's row verbatim:

```text
   ⎿  Not signed in. /login to sign in, or /new for another agent.
```

The header stays `riff · not signed in`; the prompt accepts chord's own
commands. A submitted model prompt gets the status note
`riff is not signed in: /login`. No prompt is silently retried after a
later sign-in. With an existing signed-in session, cancelling `/login`
returns to that session and its draft; it must not claim `Not signed in.`
or remove its credential. Cancelling `/logout` likewise leaves it ready.

## No store: G replaces part 4's failure

On riff's store-unavailable or store-timeout start refusal, show G's box,
not `riff did not start: it refused session/new:`. The transcript begins
with `⏺ riff needs a sign-in to a ChatGPT or Grok plan`, as in A and G.
Before a provider has been chosen the title is `Sign in to riff`; after
choosing one it is `Sign in to ChatGPT` or `Sign in to Grok`. This avoids
implying a ChatGPT choice before the person makes it.

Use CHD-606's platform-supplied store explanation and recovery instruction
verbatim inside G's box, with G's `Try the store again` choice and
`Enter to choose · Esc to cancel` hint. A timeout instead says exactly
`The macOS Keychain did not answer in 20 s.`, substituting the store name
supplied by the platform. No file, environment or memory-only fallback.

Retry keeps the same box and explanation visible, temporarily without
active choices. The line immediately above it says
`››› Reading the sign-in from the macOS Keychain… (4s)` (the actual
elapsed time and platform store name). Its hint is `Esc to cancel` while
pending. Ignore acceptance and navigation until the read settles; Esc
cancels the attempt. Success continues the original sign-in step or starts
the already signed-in session. Another failure restores the retry choice
with the latest readable cause. Never stack another failure row or box.
The initial slow store read uses the same working line.

## Signed-in provider and the new session

`/login` acts on the session in view. On a riff session, the box opens in
place; success starts a new session in place as `/clear` does. On any
other agent, `/login` does what `/new riff` does: it opens an idle riff
child and goes to it. When no sign-in is held, the box opens there. The
other agent's session remains in place.

On riff, `/login` uses A's provider box. Append ` ✔` to the current provider's
whole label, as `/model` marks its current value. Selection remains the
separate `❯`; moving it does not move the check. The mark names the active
provider, not every credential retained in the store. A normal picker
never reads the credential store to add a mark.

```text
│ Sign in to riff                                                              │
│                                                                              │
│ ❯ 1. ChatGPT · a ChatGPT plan ✔                                               │
│   2. Grok · a Grok plan                                                       │
│                                                                              │
│ Enter to choose · Esc to cancel                                              │
```

After successful switching, keep the old transcript above the new session
and add the row `⏺ New riff session · Grok` (or ChatGPT). Follow it with
F's success receipt: `Signed in to Grok with a code. Kept in the macOS
Keychain.`, substituting the actual provider, way and store. Same-provider
account replacement also starts a fresh session and names that provider;
never display an account address or token to distinguish the accounts.
The header changes only when the new session has its actual config.

```text
 ⏺ New riff session · Grok
   ⎿  Signed in to Grok with a code. Kept in the macOS Keychain.
```

An initial sign-in keeps F's receipt beneath the original needs-sign-in
row; it does not need the extra new-session row. Logout success and Grok
revocation failure keep CHD-485's exact receipts. When Grok revocation
gets no HTTP answer, use the settled fixed reason in place of the status.
These are the HTTP-status form and its two no-answer forms:

```text
Signed out of Grok here, but xAI did not revoke the sign-in (HTTP 503). This session has ended; /login to sign in again.
Signed out of Grok here, but xAI did not revoke the sign-in (no refresh token was stored). This session has ended; /login to sign in again.
Signed out of Grok here, but xAI did not revoke the sign-in (the revocation request failed). This session has ended; /login to sign in again.
```

Wrap each receipt beneath its existing `⎿` gutter to the available width.
The first uses the actual HTTP status; the second means no stored refresh
token, and the third means the revocation request failed without an HTTP
answer. All three report the completed local sign-out and ended session.

While deleting or revoking, retain the confirmation box with inactive
choices, the hint
`Esc to close`, and the working line `››› Signing out of Grok… (2s)`.
Closing that pending box does not undo a deletion already started. Once
local deletion succeeds, the header and status are signed out even if
revocation is still pending or fails. If local deletion fails, show the
readable store error in the confirmation box with `Try again` and
`Keep the sign-in`; do not claim successful logout.

When a prompt discovers a removed or replaced credential, keep the
submitted prompt and prior transcript, show CHD-485's signed-out row and
open A. The header and status become signed out. An account change says
`The account changed, here or in another chord. Sign in again to go on;
this transcript stays above.` beneath `⏺ riff is signed out of ChatGPT`
(or Grok), so removal and replacement remain distinguishable. Neither
case resends the failed prompt after sign-in.

## States, colours and keys

Empty signed-out, browser/code waiting, finishing, expired, denied and
port-taken states are A–G unchanged. Streaming before `/login` retains
its transcript; a successful switch starts a fresh session as `/clear`
does. Failure leaves recovery choices in the one box. At 80x24 long error
sentences wrap and addresses fold as C/E specify; choices and the prompt
stay reachable. Store retry and sign-out pending states are specified
above rather than falsely showing a ready prompt.

Use `permission` for borders, titles and selected `❯`, `accent` for
working lines, `link` for addresses, `warning` for no-store and port-taken
explanations, and `error` for failures. The code is bold foreground;
provider notes and receipt connectors are dim. The current `✔` keeps the
existing picker's current-value treatment. No new theme role.

CHD-485's keys and shortcut entries apply unchanged: `1–9`, arrows/`j k`
and Enter choose; Esc uses the printed step action; `/login` signs in or
switches and `/logout` confirms sign-out. Open/copy/retry are numbered
choices. Pending states accept only their displayed Esc action and normal
window exit. `?` lists the sign-in keys after the box closes.
