# CHD-389: who a question box says is asking

A question box is headed `<runtime> asks you 2 questions` (`fake asks you…`
on the fake agent, `claude asks you…` on Claude). This is the same for
`main`, a `spawn_task` task, a long-lived child and a team member, so the
person cannot tell from the box which of them asks. The owner (2026-10-15):
look at what the heading says today for each before deciding what changes.

This page gave the owner options; the decisions are below.

## Decided

The owner (Q33–Q37, 2026-10-18; Q45, 2026-10-19):

- **main:** M1, the runtime stays: `claude asks you 2 questions`.
- **A task:** T1, `Agent(Fix the tokenizer) · fake asks you 2 questions`.
- **A long-lived child:** C1, `docs asks you 2 questions`, the name bold in
  its agent colour.
- **A team member:** E2, name and team: `tester · bugfix asks you 2
  questions`. **Why:** the owner runs one team several times at once.
- **The form and link boxes:** F1, the same rule as the question box.
- **The permission box's asker row names a member the same way** (Q45):
  `tester · bugfix asks`, in a turn, and `tester · bugfix asks · between
  turns` between turns (CHD-158 §2). The name is bold in its agent colour,
  ` · bugfix` dim. A child's row stays `docs asks`, a task's
  `Agent(Fix the tokenizer) · fake asks`, and main's has none in a turn.
  **Why:** every box names a member the same way, for the reason E2 gives.

The options below are kept as they were asked.

## The naming everything shares

The permission box's asker row, and CHD-158's between-turns row built on it,
already name each asker:

- the session's own agent by its name (`main asks`, `docs asks`), and,
  since Q45, a member with its team (`tester · bugfix asks`);
- a Claude or Codex subagent and a task as their call is headed
  (`Agent(Fix the tokenizer) · fake asks`);
- a child's name bold in its agent colour, a subagent's row in the accent
  colour.

The options below either take that naming into the question box or keep the
runtime. Whatever the heading says, it wraps and is never cut
(`mock/task-wraps-80x24.txt`).

## Q1. main

**M1. Keep the runtime: `claude asks you 2 questions`.** No change. With
every other asker named differently (Q2–Q4), a bare runtime can only mean
the session the person prompted.

**M2. Its name: `main asks you 2 questions`.** As the agents list and
CHD-158's `main asks · between turns` name it. It reads as jargon when no
child is open and `main` appears nowhere else on screen.

**M3. Name and runtime: `main · claude asks you 2 questions`.** Says both,
and is the longest.

**Recommendation: M1.** The heading already says something true for main,
and the owner's note asks to change only what does not. Main's permission box
also names nobody; the missing name is how main's requests differ, in both
boxes.

## Q2. A `spawn_task` task

**T1. As its permission row: `Agent(Fix the tokenizer) · fake asks you 2
questions`.** The same words as its call in the transcript and its
permission box. (`mock/task-120x40.txt`, `mock/task-80x24.txt`)

**T2. Its name only: `Fix the tokenizer asks you 2 questions`.** As the
background view's row names it. Shorter, but a title reads oddly as the
subject of "asks".

**T3. Its kind and name: `task Fix the tokenizer · fake asks you 2
questions`.** Says it is a task, a word nothing else on screen uses for it.

**Recommendation: T1.** One name for the task in every place it asks, and the
`Agent(…)` heading is the one the person can find in the transcript.

## Q3. A long-lived child

**C1. Its name, as its permission row: `docs asks you 2 questions`**, the
name bold in its agent colour. (`mock/child-120x40.txt`,
`mock/child-80x24.txt`)

**C2. Name and runtime: `docs · fake asks you 2 questions`.** Adds what the
agents list row already says beside it.

**C3. Keep `fake asks you 2 questions`** and leave it to the agents list row.
That row is not always drawn, and it is not in the box.

**Recommendation: C1.** It is how the permission box already says it, and
the child's colour carries over from its name in the list and transcript.

## Q4. A team member

**E1. Its name, as its permission row: `tester asks you 2 questions`**, bold
in its agent colour. (`mock/member-120x40.txt`, `mock/member-80x24.txt`)

**E2. Name and team: `tester · bugfix asks you 2 questions`.** As the prompt
box's title, which the question box hides, names it. Two runs of the same
team have members of the same name.

**E3. Name and runtime: `tester · fake asks you 2 questions`.**

**Recommendation: E1.** It matches the permission box. The front session is
already the member, so its team is one step away in the agents list.
Recommend E2 instead if the owner runs one team many times at once.

## Q5. The form and link boxes

**F1. The same rule as the question box**, for `asks for input` and `asks
you to open a link`: one heading rule for every box that asks.

**F2. Only the question box changes.**

**Recommendation: F1.** The form and link boxes have the same defect, with
the same cause (`agent` passed in as the runtime name).
