# CHD-437 and CHD-457: one box for an agent's plan, cursor's and grok's

Decided by the owner (2026-10-18): chord answers cursor's
`cursor/create_plan` (CHD-437) and grok's `x.ai/exit_plan_mode` (CHD-457) by
showing the plan and asking the person, never with method-not-found, which
today accepts cursor's plan on the person's behalf and leaves grok stuck in
plan mode. Both share one box. This doc draws the four open points, each
with its options at 120×40 and 80×24, and recommends one per point.

What each agent sends and takes (developer's findings on the two tasks,
protocol facts only):

| | cursor `cursor/create_plan` | grok `x.ai/exit_plan_mode` |
| --- | --- | --- |
| The plan | `plan` markdown, `name?`, `overview?`, `todos` (`pending`, `in_progress`, `completed`, `cancelled`), `phases?` grouping them | `planContent?` markdown, absent when grok wrote none |
| Yes | `accepted` | `approved`: leaves plan mode and implements |
| No | `rejected`, `reason?` | `revise`, `feedback?`: stays in plan mode and revises |
| Out | — | `abandoned`: leaves plan mode, does not implement |
| Turn cancelled, chord closing | `cancelled` | `cancelled`, read as revise |

Every answer that is not the person's is `cancelled`, never a yes.

## Point 2: free text for the reason or feedback, or none

### 2A: a Note row, as the question box has (recommended)

Under the choices, the question box's Note row:
`Note  Tell <agent> what to change, sent with 2 (optional)`. `↓` past the
last choice reaches it; typing fills it, wrapped, never cut; `Enter` there
answers **2** with the text as cursor's `reason` or grok's `feedback`; `↑`
goes back to the choices. Typed text stays if the person moves back to the
choices, and picking 2 then sends it too; picking 1 or 3 sends none, as
neither agent reads it there. At 80×24 with a note typed
(`mock/cursor-note-typed-80x24.txt`):

```
│ cursor has a plan. Do you want to proceed?                                   │
│   1. Yes, accept the plan                                                    │
│   2. No, keep planning                                                       │
│                                                                              │
│ ❯ Note    Keep the routing in connection.ts; only add a test for it.▌        │
│                                                                              │
│ Enter to keep planning with this note · ↑ to the options · Esc to keep       │
│ planning                                                                     │
```

- **For it:** "no" without a why leaves the agent guessing; both agents
  take a text, and grok's own TUI asks for one. It is a row the person
  already knows from the question box, its keys included.
- **Against it:** one more row in the box.

### 2B: none

The box has its choices alone (`mock/cursor-no-note-*.txt`); 2 sends no
reason. The person tells the agent what to change in their next prompt.

- **For it:** the smallest box.
- **Against it:** for grok, a revise with no feedback has the model guess,
  and the person's next prompt only reaches it after that guess.

## Point 3: grok's abandon, offered or not

### 3A: offered, as a third choice (recommended)

`3. No, and leave plan mode` (`mock/grok-recommended-*.txt`):

```
│ grok has a plan. Do you want to proceed?                                     │
│ ❯ 1. Yes, start implementing                                                 │
│   2. No, keep planning                                                       │
│   3. No, and leave plan mode                                                 │
│                                                                              │
│   Note  Tell grok what to change, sent with 2 (optional)                     │
│                                                                              │
│ Enter to pick · 1–3 · ↑↓ to move · Esc to keep planning                      │
```

- **For it:** it is the only way out of plan mode that grok offers here
  without implementing, and its own TUI offers it; it is a choice like any
  other, numbered, no new key.
- **Against it:** cursor's box has two choices and grok's three; the box is
  the same, its choices the agent's.

### 3B: not offered

grok's box has 1 and 2, as cursor's (`mock/grok-no-abandon-*.txt`). To
leave plan mode the person changes the mode with `shift + tab`.

- **Against it:** that takes plan mode off but leaves grok's pending plan
  to be revised first; the person cannot say "drop it" in one answer.

## Point 4: cursor's todos and phases, drawn or ignored

### 4A: drawn under the plan, as chord's plan list (recommended)

After the markdown, `Todos` and each todo in the ACP plan list's glyphs:
`☐` pending, `◐` in progress, `☒` completed, and `cancelled` dim with its
`☐` struck through. With `phases`, each phase's name is a heading over its
todos, the todos outside any phase under `Todos`. (The 120×40 mock above.)

- **For it:** the todos are what cursor will then track
  (`cursor/update_todos`); the person approves the steps it will be held
  to, and they look as every other plan in chord does.
- **Against it:** a plan whose markdown already lists the same steps
  shows them twice, as in the mock.

### 4B: ignored

Only the overview and the markdown are drawn
(`mock/cursor-no-todos-*.txt`).

- **For it:** no repetition when the markdown has the steps.
- **Against it:** a plan whose markdown is prose loses its steps; the
  answer approves a list the person never saw.

## The box, as recommended

- **Title:** `Approve Plan`, as ExitPlanMode's; **question:**
  `<agent> has a plan. Do you want to proceed?`, the agent named as the
  agents list names it, since the box can be a child's or a member's.
- **Choices:** cursor `1. Yes, accept the plan` → `accepted`;
  `2. No, keep planning` → `rejected` with the note as `reason`. grok
  `1. Yes, start implementing` → `approved`; `2. No, keep planning` →
  `revise` with the note as `feedback`; `3. No, and leave plan mode` →
  `abandoned`.
- **grok with no `planContent`:** the transcript says
  `grok has written no plan.` under `⏺ Plan`, and the box asks the same.
- **Waiting line:** `››› Waiting for your answer to the plan… (Ns)`, in the
  permission's place and colour.
- **After the answer:** the call's `Waiting…` turns to its outcome, dim:
  `Accepted`, `Kept planning: <note>`, `Left plan mode`; the plan stays.
- **Cancelled, withdrawn, chord closing:** chord answers `cancelled`; the
  box goes as a withdrawn permission's does, the call reads `Cancelled`.
- **Hidden and shown** as every permission box: a picker gives way to it,
  CHD-462's rules hold.

## Keys

The permission box's and the question box's, nothing new:

| Key | Does |
| --- | --- |
| `↑ ↓`, `j k` | move between the choices and onto the Note row |
| `1`–`3` | pick that choice |
| `enter` | pick the choice under `❯`; on the Note row, answer 2 with the note |
| `esc` | answer 2 with no note: keep planning (cursor `rejected`, grok `revise`) |
| `pageup pagedown` | scroll a plan in the box (1B only) |

On the Note row, digits and `j k` type. The shortcuts panel's existing
lines cover them: `1–9 to pick a choice`, `↑ ↓ or j k to move between
choices`, `enter to pick the highlighted choice`, `esc to reject a
permission`, `pgup pgdn or wheel to scroll`.

**Esc keeps planning, never accepts and never leaves.** Its hint word is
`Esc to keep planning`, not ExitPlanMode's `Esc to reject`, since for grok
it is a revise.

## Colour roles

No new role: the box's border, title and `❯` are `permission`; the plan in
the transcript is message text; the todo glyphs as the plan list's; the
Note row as the question box's; the waiting line as a permission's.

## Recommendation

1. **1A**, the permission box with the plan in the transcript: one look for
   a plan from any agent, and the plan stays where the answer is read back.
2. **2A**, a Note row sent with 2: both agents read it, and the row is the
   question box's.
3. **3A**, grok's abandon as its third choice: the only one-answer way out.
4. **4A**, cursor's todos and phases drawn under the plan as chord's plan
   list: the person approves the list the agent will hold itself to.
