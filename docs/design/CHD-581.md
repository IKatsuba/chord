# CHD-581: chord's commands in `chord acp`, their words

`docs/design/CHD-573.md`, "chord's commands (CHD-581)", decides what the commands
do. This is what they say. There is no screen of chord's: a result or a refusal
is one `agent_message_chunk` text in a client's own interface, then `end_turn`,
with `_meta["chord/command"]` naming the command and `failed`. Plain text, no
escapes, no theme.

## How the text is laid out

- **No columns.** A client's font may be proportional, so nothing is padded or
  aligned. One thing per line, its parts joined by ` · `, the window's separator.
- **A list is `- ` lines, and blocks have a blank line between them.** Many
  clients render an agent's text as markdown, where a lone newline joins two
  lines. These two rules read the same raw and rendered.
- **No angle brackets in what chord says.** A renderer can take `<id>` for HTML
  and drop it. A refusal describes the missing word instead, as the window's
  already do.
- **No glyphs for state:** the picker's `✻` and `✗` go, and their words stay.

## `/team list`, `/team`

The picker's row as a line, in its order, then the runs, then where teams are
saved and what to type:

```
Teams:

- architects · 4 agents · claude, codex · this project · Designs a large feature before it is built
- broken · not read: description is required
- bugfix · 3 agents · claude, codex · every project · working 6m · Fixes a reported bug

Runs open:

- bugfix · team bugfix · working 6m

Saved for this project in .chord/teams, and for every project in ~/.config/chord/teams.

/team show and a name shows a team; /team run, a name and a job starts one.
```

A team with several runs says `2 runs` where one says `working 6m`, as the picker
does. A project's file hiding the user's says `this project · hides every
project's`. With no home there is no user directory: `Saved for this project in
.chord/teams.` A broken file gives its first problem, without its path; `/team
show` gives the path.

No run open, in place of the "Runs open" block, as `whichRun` sends people here:

```
No run is open.
```

No team saved, in place of the "Teams" block. `NO_TEAMS` is the window's line and
is true here. Open runs, where to save and the last line stay as above, except
that the last line goes while no team exists:

```
No teams yet. /team new and a few words about the work makes one.
```

Main closed: `This session has closed`, failed, as the other forms say it.

## `/team show`

A team not running: its name and file, its description, its agents. The body and
each agent's instructions stay in the file, which the first line names; there is
no ctrl+o here to unfold them.

```
bugfix · .chord/teams/bugfix.md

Fixes a reported bug from reproduction to a tested commit.

Agents:

- lead · claude · opus · high · auto · Splits the job, says who edits which files, reports to main
- developer · claude · opus · auto · Builds the fix
- tester · codex · gpt-6.1-sol · agent · Tests the fix
```

A row is the name, runtime, model, effort, mode and role. An unset value is left
out, where the window's table holds its place with `—`. The lead's role is
`LEAD_ROLE`.

A running one: the window's header line, whole and with the job on one line, the
description, then the same rows with the lead's run name and which are open.

```
bugfix 2 · .chord/teams/bugfix.md · working 6m on "the login test fails on CI"

Fixes a reported bug from reproduction to a tested commit.

Agents:

- lead (bugfix 2) · open · claude · opus · high · auto · Splits the job, says who edits which files, reports to main
- developer · open · claude · opus · auto · Builds the fix
- tester · not open · codex · gpt-6.1-sol · agent · Tests the fix
```

`not open`, not the window's `not opened`: a member that opened and closed is
absent too, and the window's word would be false of it. No state, unseen mark or
headline, as CHD-573 says: those read window state.

Which run it finds is the window's: `/team show bugfix` is its first open run,
and a run's id finds that run.

**A selected run is refused**, failed. That is every case where the window would
draw a receipt: a recorded run by its id, and an open run with `run.selected`,
however it was named. `<typed>` is the word typed, `<run id>` the receipt's
`runId`, because a team's name finds no receipt once its run has closed:

```
<typed> is a selected run, and only chord's window shows its receipt: chord -r with this session's id, then /team show <run id> there
```

```
bugfix is a selected run, and only chord's window shows its receipt: chord -r with this session's id, then /team show 7f3a9c21 there
```

`/team stop` works on a selected run as on any other.

## `/team run`

Started, in CHD-573's shape, the lead named by its run:

```
Team bugfix started. Its lead is bugfix; /team stop bugfix ends it.
Team bugfix started. Its lead is bugfix 2; /team stop bugfix 2 ends it.
```

No `@`: the lead's name can hold a space, and `/team stop` takes it bare. What
main hears through `ranNote` keeps its `@`, as that is for the agent. An effort
`note` from the start follows as a block of its own, unchanged. The reply does
not say the run ended or succeeded, as a run has no defined end.

Refused, failed, in the window's words from `teamCommand`, `teamRefusal` and
`runTeamAt`, all true here:

```
/team run bugfix takes the job after the name
Which team? /team lists them
No team named bugfx · /team lists them
.chord/teams/broken.md is not a team chord can run:
description is required
This launch was cancelled; no run started.
This session has closed
```

`startRefusal`'s and `fullRefusal`'s words stand too. "close_agent one first" is
main's tool, and a person reaches it by asking main.

## `/new`

The child is idle and the reply says so. It names what starts it, main's
`send_message`, as a client has no way of its own until CHD-575:

```
Opened codex (codex). It is idle, with no prompt yet; main's send_message starts it, so ask main to send it the work.
Opened codex 2 (codex). It is idle, with no prompt yet; main's send_message starts it, so ask main to send it the work.
```

`/new` with no agent opens main's runtime, as in the window; the hint still says
`<agent>`. An effort `note` follows as under `/team run`. Refused, failed, in
`startRefusal`'s and `fullRefusal`'s words:

```
No agent named nope; chord knows claude, codex
This session has 8 agents open; close_agent one first
This session has closed
```

## A prompt with other blocks beside a command

Refused, failed, and nothing runs. The command's own name comes from the text
block:

```
/team takes text alone, and this prompt had other blocks beside it. Nothing ran; send the command by itself.
/new takes text alone, and this prompt had other blocks beside it. Nothing ran; send the command by itself.
```

## `TeamWords`

Three fields stay, with `chord acp`'s words. A fourth takes the hard-coded tail of
`stopTyped`'s "No run named" line, so that the window's line stays as it is:

| Field | Window | `chord acp` |
| --- | --- | --- |
| `whichRun` | `Which run? The list under the prompt names them` | `Which run? /team lists them` |
| `closedLead` | `/resume lists it` | `chord -r with its id or session/load reopens it` |
| `closedRun` | `/resume lists them` | `chord -r with an id or session/load reopens each` |
| `noRun` (new) | `the list under the prompt names them` | `/team lists them` |

`chord -r <id>` uses the record's agent when none is named, by the guide, so the
words need no agent. Nothing above says `chord <agent> -r <id>`, whose brackets a
renderer can drop. `/resume` and the list under the prompt appear in no answer of
`chord acp`.

`/team new`'s and `/team`'s other refusals from `teamCommand` stay as they are:
each is true here, and `/team new <words>` itself is a normal turn.

## Keys

None. This is text a client shows, and it adds no action to chord's window.
