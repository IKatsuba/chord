# CHD-158: a request that comes between turns

An agent may ask the person something when no turn of chord's is running:

- On Claude, a background Bash's follow-up cycle asks permission with no
  prompt in flight; a subagent spawned in that cycle asks; a background
  agent that outlived a cancel asks.
- On Codex, a subagent thread outlives the root turn and asks for approval.

Today chord refuses each such permission request (`Conversation#asked`) and
cancels each such form or link (`Conversation#elicited`). The person sees
nothing: no box, no note, no record. The owner (2026-10-15) gave the designer
the call on how such a request is shown.

This page is the design. Where a point is the owner's policy rather than
layout, it is listed at the end for the lead, with options. The layout below
assumes chord takes the request; nothing else on this page depends on how
those policy points are answered, except the queued prompt (part 5).

What today's in-turn request does, which this design keeps where it can:

- The box is drawn over the prompt box, under the `››› Waiting for
  permission… (2s)` line, with the asker row `Agent(Find the session layer)
  asks` in the accent colour when a subagent asks. When the session's own
  agent asks, there is no asker row.
- The box takes the keys at once: typed letters go nowhere, `1`–`9` and
  `enter` choose, and `esc` rejects.
- The answer is recorded under the call that asked (`⎿ Allowed …`), inside
  the subagent's block when a subagent asked.

chord already has one request that arrives between turns: a `spawn_task`
task that asks after its parent's turn has ended
(`src/session/transcript/permissions.ts`, `between`). It is drawn as an
in-turn request is. This design gives it the same shape as the rest.

## 1. Where the box goes

**In the same place as in a turn: over the prompt box, at the bottom of the
asking session's view, under the `››› Waiting for permission… (4s)` line.**
The transcript gets no turn of its own for it. The call that asked is drawn
where the agent's updates already land: under the last turn, or inside its
subagent's block.

**Why:** the person already knows the box and where it sits. A box anywhere
else would be a second shape for the same question. The waiting line shows
how long the agent has waited, as in a turn. It has no `esc to interrupt`,
since there is no turn to interrupt, which is also true of the in-turn line
today.

## 2. Whose request it is

The box always has an asker row between turns, ending in a dim
` · between turns`:

| Who asks | Asker row |
| --- | --- |
| the session's own agent (`main`, or a child in its own view) | `main asks · between turns`, `tester asks · between turns` |
| a subagent chord has a block for | `Agent(Run the whole test suite) asks · between turns`, its path down from the session as today (`Agent(A) › Agent(B) asks`) |
| a subagent chord has no block for (spawned in a cycle chord drew nothing of) | `a subagent of main asks · between turns` |
| a `spawn_task` task | `Agent(Fix the tokenizer) · fake asks · between turns` |

The names keep today's colours: a subagent's row in the accent colour, a
child's name bold in its agent colour. ` · between turns` is dim.

**The row wraps and is never cut.** Today's in-turn asker row is cut from the
left with `…`. Between turns it wraps onto a second line instead
(`mock/main-asker-wraps-44x24.txt`). This changes the shared row
(`askerRow`) for in-turn requests too, in line with the owner's standing
rule.

**Why a row for the session's own agent too:** in a turn, the missing row
means "the agent you just prompted". Between turns the person prompted
nothing, so the box has to say who is asking. ` · between turns` says why it
came with nothing running.

## 3. The keys: the box does not take them on its own

**Between turns the box is drawn without the keys.** No `❯` is in its
choices, and its hint line reads `ctrl+x a to answer` in place of `Esc to
reject`. The prompt box keeps the keys and the draft. **`ctrl+x a`** moves
the keys into the box: the `❯` comes onto `1. Allow`, the hint becomes `Esc
to reject`, and from there it works exactly as in a turn. Once answered, the
keys go back to the prompt with the draft as it was.

**Why:** in a turn, the person has just sent a prompt and is waiting, so a
box that takes the keys at once is expected. Between turns, the person may
be in the middle of typing. A box that took the keys then would turn a typed
`2` into "Always allow" and a typed `enter` into "Allow": the agent would get
an answer the person never gave. The owner's standing priority is permission
safety, and one key press to answer costs little for a case this rare.

`ctrl+x a` is the existing `session:attention` key, "go to what needs you".
Today it goes to another session that asks. With this design, when the front
session is the one asking between turns, it goes into that box. No new key
and no new binding. The shortcuts panel's `ctrl + x then a key for sessions`
line already covers it.

A form or a link that comes between turns follows the same rule: drawn
without the keys, `ctrl+x a` to answer it, then its own keys as today.

## 4. The status line and the tab

- **In front**, while the box waits without the keys, the status line's
  left part reads `● permission asked between turns · ctrl+x a to answer`
  (the warning colour on `●`), and `● permission · ctrl+x a to answer` where
  the width is short. A form or a link between turns reads
  `● input asked between turns · ctrl+x a to answer`, and
  `● input · ctrl+x a to answer` where the width is short: `input` is the
  word the agents list row (`● input 9s`) and the form's `asks for input`
  already use for both. Once the box has the keys, the status line is as in
  a turn.
- **Not in front** (a child or member not picked, or another tab): exactly
  as for a request in a turn. That means the status line's
  `● tester needs your permission · ctrl+x a to go`, the agents list row's
  `● permission 9s`, and the tab's asking glyph (`mock/member-120x40.txt`).
  These come from the session's wait, which a between-turns request sets as
  an in-turn one does.

## 5. While it is open: typing, and a prompt sent

- **Typing** goes to the prompt box, as part 3 says. The draft wraps in the
  box as always (`mock/typing-120x40.txt`, `mock/typing-80x24.txt`).
- **A message from another agent** that arrives while the request is open
  waits in the queue with `· after your answer`, as CHD-385 and CHD-423
  already do for a message that comes while the person is asked something.
- **A prompt the person sends** (`enter` on a draft) while the request is
  open: what happens to it, and what the agent gets as an answer, is the
  owner's call (P3 below). The mock for the recommended option is
  `mock/queued-optionA-80x24.txt`.

## 6. Once answered

The answer is recorded where it is today: under the call that asked
(`⎿ Allowed …`), inside its subagent's block when a subagent asked, or at the
transcript's end when the session's own agent asked. The waiting line and
the box go. The status line and the agents list row go back to what the
session is doing.

## Colour roles

All from `src/ui/theme/theme.ts`; no new role.

- **permission:** the box's border, as today.
- **accent:** a subagent's asker row; a child's name in its agent colour.
- **dim:** ` · between turns`, and the hint line.
- **warning:** the status line's `●`.

## Keys

- `ctrl+x a`: into the box when the front session asks between turns; to
  the asking session otherwise, as today. It is rebindable as
  `session:attention`.
- In the box, once it has the keys: `1`–`9`, `↑ ↓`, `enter` and `esc`, as
  today.

No new panel line.

## For the lead: policy, not chosen here

- **P1. Whether chord takes these requests at all.** The owner's comment
  reads as yes. Options:
  - (a) take permissions and forms or links alike;
  - (b) take permissions, and keep cancelling forms and links;
  - (c) keep refusing, but say so in the transcript (`⏺ Agent(…) asked to
    write notes/test-report.md between turns · refused`).

  I recommend (a): the question is the same, and so is the box.
- **P2. Whether a request between turns ever expires.** One left unanswered
  holds the agent for good, which is why `#asked` refuses it today. Options:
  - (a) it waits until answered, as in a turn;
  - (b) it is rejected after a time, recorded `⎿ Rejected · not answered in
    10m`;
  - (c) it is rejected when the person closes the tab or quits, as an
    in-turn one is.

  I recommend (a), with (c) as today's behaviour on close.
- **P3. A prompt sent while it is open, and the agent's answer.** Options:
  - (a) the prompt waits in the queue with `· after your answer` and goes
    once the request is answered; the agent gets the person's answer and
    nothing else (`mock/queued-optionA-80x24.txt`);
  - (b) sending the prompt rejects the request, recorded `⎿ Rejected · you
    sent a prompt`, and the prompt goes at once;
  - (c) the prompt goes at once as a new turn and the request stays open
    beside it.

  I recommend (a): nothing is answered on the person's behalf, and the queue
  already has the shape. (c) depends on what each adapter does with a
  prompt while its own cycle is running, which nobody has tried.
- **P4. The in-turn box and typing.** Part 3 keeps the in-turn box as it is,
  taking the keys at once. A person typing while the agent works can still
  answer one by accident there. Whether the in-turn box should also wait for
  `ctrl+x a` is a wider change than this task.
