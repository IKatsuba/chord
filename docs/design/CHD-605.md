# CHD-605: riff's edit, write and shell

CHD-485's 'The session', 'Permission prompts' and 'Tools' settle the
renderer and admission contract. This follows CHD-604b's asks and path
spelling. Use the existing transcript renderer and permission box, with
no new widgets or colour roles in `theme.ts`.

## Titles and results

Each title is verb-first so `VERB_FIRST` in
`src/ui/transcript/tools/tools.ts` draws the intended name.

| Tool | ACP kind | Title | Row |
| --- | --- | --- | --- |
| `edit` | `edit` | `Update src/greeting.ts` | `⏺ Update(src/greeting.ts)` |
| `write` | `edit` | `Write src/welcome.ts` | `⏺ Write(src/welcome.ts)` |
| `shell` | `execute` | `Bash bun test tests/greeting_test.ts` | `⏺ Bash(bun test tests/greeting_test.ts)` |

Tool arguments remain structured input, not a new interface: edit names
its path and old/new strings, write its path and whole content, shell its
exact command. The title carries the path or command; the existing renderer
draws diffs and terminal output from the call's structured content.

An edit's `⎿` is the existing diff summary, followed by numbered removal
and addition rows. Write uses the same diff rendering: a new file has
only additions; an overwritten file shows removals and additions. Do not
invent a separate 'Created' renderer or repeat the summary as text. The
summary uses the agent-supplied ACP diff path unchanged; riff supplies the
absolute path as the SDK specifies. The short paths below illustrate the
summary's form, not a new path-shortening rule.

```text
 ⏺ Update(src/greeting.ts)
   ⎿  Updated src/greeting.ts with 1 addition and 1 removal
       1 - export const greeting = 'Hello';
       1 + export const welcome = 'Hello';

 ⏺ Write(src/welcome.ts)
   ⎿  Updated src/welcome.ts with 1 addition and 0 removals
       1 + export const welcome = 'Hello';
```

Shell output streams under `⎿` in the existing terminal rendering. A
running call without output says `Running…`; a completed silent call says
`(No output)`. Folded output keeps the last three lines and its hidden-line
count; ctrl+o expands it. A failing exit says `Exit code 1` (the actual code)
or `Killed by SIGTERM` (the actual signal). A successful exit adds no error
line; its completed marker and output are the existing success treatment.

## Grants and asks

| Tool | Option 2 |
| --- | --- |
| edit | `Allow edits to src/greeting.ts for this session` |
| write | `Allow edits to src/welcome.ts for this session` |
| shell | `Allow this exact command for this session` |

Edit and write share one grant for one real file path, including when the
file does not yet exist. Either session choice permits both operations on
that file; it grants neither a directory nor a prefix. Both asks keep CHD-485's
words: "edits" covers edit and write, every change to that file. A shell grant covers the
exact command string, never its first word or a prefix.

Option 1 is `Allow`, option 3 `Deny`; Esc rejects. In ask mode, calls ask
unless covered by a session grant. In auto until part 6, edit and write
inside the session directory on ordinary paths run without asking; outside
that directory or on a sensitive path they ask with these same three
options, unless already granted. Every ungranted shell call asks in both
modes. No reviewer rationale, review timer or two-option safety-review box
is introduced in this slice.

Paths follow CHD-604b: relative inside the session directory, `~`-shortened
outside when possible, absolute otherwise. If a path goes through a link,
the title and transcript row show `<asked path> → <real path>`, with option
2 naming the real path. A new file uses the resolved parent and filename.
The person must see the destination before choosing plain Allow.

## States

- **Empty:** unchanged riff header and rounded empty prompt, no tool row.
- **Streaming:** a running marker, the normal Working line with Esc, and
  shell output arriving under its existing call rather than new calls.
- **Waiting on the person:** pending row with `Waiting…`, the normal
  `Waiting for permission…` line and the inline box above the prompt.
- **Denied:** the failed call says it was denied under `⎿`; no success diff
  is published and no shell output is invented. The ask closes.
- **Changed file:** an approved edit or write that became stale fails with
  `the file changed since this edit was proposed; read it again` under
  `⎿`. Keep the original title; do not show the proposed diff as applied.
- **String not found or not unique:** edit fails under `⎿` with a plain
  explanation naming which condition failed. It performs no replacement;
  it must not imply the nearest match was edited.
- **Refused symlink swap:** the call fails under `⎿` explaining that the
  file's identity or link target changed and the operation was refused.
  Keep the requested and resolved destination visible in its title.
- **Shell stopped with Esc:** preserve output already received; show the
  existing interrupted/terminated call treatment, including the actual
  killing signal when available. Stop the Working line and return the
  prompt. Never label cancellation a successful exit.
- **Other errors:** readable error text under `⎿`, using the existing error
  treatment. A nonzero shell exit retains the output preceding its exit.
- **Narrow:** the wrapping above, both choices and destination readable;
  folded diffs and terminal output keep the prompt usable at 80x24.

## Colour roles and keys

Use `permission` for the box border, title and selected `❯`; `accent` for
the running marker and working line; existing `error` for failed calls and
nonzero exits. Result connectors and normal output are dim. Diff rows use
`diff.added`, `diff.removed`, their existing tints and code colours. Signs
and words retain meaning without colour. No new colour role.

No new keys: `1–9`, `↑ ↓` and Enter choose, Esc rejects an ask or interrupts
a running turn, shift+tab toggles ask/auto, ctrl+o expands tool output and
`?` on an empty prompt lists shortcuts. The existing permission box's
scrolling keys remain available for tall content.
