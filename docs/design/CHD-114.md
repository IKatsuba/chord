# CHD-114 — Several sessions in one window

chord can keep several agent sessions open in one window. Each session has its
own acpx runtime and its own agent process. Only one session is in front at a
time, and a person moves between them with keys. When a session that is not in
front needs the person, the window says so. It never switches to that session
by itself.

Claude Code has no equivalent, so there is no reference capture. The shapes
below extend chord's own screen: the header row, the status line, and the
picker box that `/model` and `/resume` already use. The mocks are in
`evidence/CHD-114/mock/`, at 120×40 and 80×24, one file per state. They were
laid out to exact widths from the real screen of `deno task chord:fake` (also
captured for this task), with the directory shown as `~/src/app`.

I looked for public material on Chorded's key habits and found nothing I could
cite. The pattern used here, a leader key followed by one letter, is the
public convention of Emacs (`ctrl+x`), tmux (`prefix c / n / p / 0–9 / w`) and
opencode (`ctrl+x` leader). The letters below are chord's own choice; each one
is explained in the key table.

## The decisions, in short

| Question | Answer |
| --- | --- |
| Where a new session starts | **In the window's directory only.** The same agent comes from `ctrl+x c`; `/new <agent>` starts any agent from the registry. |
| Where open sessions are shown | **In the header row, as a strip of tabs**, only when two or more are open. `ctrl+x w` opens a picker that has more detail. |
| Switching | `ctrl+x n` / `ctrl+x p` for next / previous, `ctrl+x 1`–`9` to go to one directly, `ctrl+x a` to go to the one that waits. |
| A session behind that needs the person | It gets a glyph on its tab and a notice on the status line, and the terminal is notified as CHD-83 does, with the session named. **The window never switches by itself.** |
| Closing | `ctrl+x k` closes the session in front. If that session is busy, it asks once more. Closing the last session quits. |
| Quit | Same as today when nothing is busy. If any session is busy, `ctrl+d` (and `/exit`) asks once more and names the busy sessions. A resume command is printed for each session. |
| `/resume`, `/clear`, `/model`… | Act on the session in front. `/resume` switches to a session that is already open instead of loading it a second time. |

## One window, one directory (CHD-101 kept)

A new session opens in the window's directory and nowhere else. The reasons in
CHD-101's entry in `decisions.md` still hold, and here they hold for every
session at once. The project's settings file, `.mcp.json`, the notification
channel, `@`'s files, bash mode's shell, `/status` and the header are all read
once, for one directory. Two directories in one window would mean either
reading all of that per session, or having sessions whose shell works
somewhere other than their agent. For another directory, a person opens chord
in another terminal tab.

Because there is one directory, the header shows it **once**, on the right,
for every session. The agent's name moves from the header's right side into
each tab.

**Different agents are allowed.** Comparing claude and codex on the same
repository is the main reason to have several sessions. The agent does not
change any of the things listed above. It only changes the starting model and
mode, and the settings files already set those per agent. `ctrl+x c` opens
the front session's agent, with no question asked. `/new codex` opens the
named agent. `/new` with no name is the same as `ctrl+x c`. An unknown name
is refused in the transcript: `No agent named codx · chord agents lists them`.
The session in front does not change.

**At most nine sessions** can be open, because `1`–`9` is the direct key. A
tenth `ctrl+x c` puts `Nine sessions are open; close one with ctrl+x k first`
on the status line.

A new session goes **to the end of the strip and comes to the front**, as a
tmux window does. It draws the usual connecting screen.

## The strip

There is no strip while only one session is open. The header looks as it does
today (` chord … fake · ~/src/app`), so a person who never opens a second
session sees nothing new.

With two or more sessions open, the header's left side holds one tab per
session after ` chord`, in the order they were opened. Tabs are separated by
four spaces.

```
 chord   1 fake    2 claude ●    3 fake ✓                                                                      ~/src/app
         ▔▔▔▔▔▔ in front: inverse, bold
```

- **A tab** shows its position, the agent's id, and a glyph for its state. The
  position is the number its direct key uses. When a session closes, the
  tabs to its right move down by one, so `ctrl+x 2` always means the second
  tab, as browser tabs do.
- **The tab in front** is drawn in inverse video and bold, with one space of
  padding on each side. Inverse swaps the foreground and background colours,
  so it reads the same in a dark and a light terminal and under `NO_COLOR`.
  The front tab never shows a glyph, because its own screen already shows its
  state. The other tabs are drawn in the theme's dim text.
- **The glyphs**, from the most to the least urgent:

  | Glyph | Colour (theme role) | Meaning | Cleared when |
  | --- | --- | --- | --- |
  | `●` | `warning` | waits for a person: a permission request or a form/link | it is answered |
  | `✗` | `error` | its turn failed, or its agent exited | the person goes to it |
  | `✓` | `success` | its turn ended since the person last looked | the person goes to it |
  | `✻` | dim | a turn is running | the turn ends |
  | none | | idle and already seen, or connecting | |

  `●` uses `warning`, not the `permission` colour. In the dark theme the
  permission colour is a pale lavender that does not stand out in a strip of
  dim text. Amber says "needs you" in both themes. The glyph does not
  animate: a spinner in a tab would redraw the whole window for something
  that the working line already shows.
- **When the strip runs out of room**, it shrinks in this order:
  1. The directory is cut at a `/` (`cutPath`), down to its last segment.
  2. The other tabs drop the agent's name and keep the number and glyph
     (`2 ●`). All of them drop it together, so the strip reads evenly.

  The tab in front always keeps its name. Nine tabs reduced to number and
  glyph take at most 45 columns, so the strip always fits at 80 columns and
  never has to scroll or hide a tab:

  ```
   chord   1 fake    2 ●   3 ✓   4 ✻   5   6 ✻                           ~/src/app
  ```

  (`80-narrow-many.txt`; the same six at 120 columns keep their names,
  `120-narrow-many.txt`.)

## Switching

Switching swaps the whole screen below the header to that session's state:

- the transcript and its scroll position
- the plan list, the working line and the queued `›` rows
- the draft in the prompt box, including its images and bash mode
- an open permission prompt or form
- on the status line: the mode, the model and the context left

Settings that belong to the person stay the same for the whole window: ctrl+o's
verbose view, the theme, vim mode, the keybindings, and **the prompt history**.
History is one list per directory, so ↑ can bring back a prompt that was sent
in another tab. That is what a person who sends the same prompt to claude and
codex wants.

Switching to a session clears its `✓` or `✗`. A `●` stays until the permission
or form is answered.

## A session behind that needs the person

A session that is not in front can ask for permission, ask for a form or a
link, or end its turn. When that happens, three things happen together:

1. **Its tab gets `●`** (permission, form, link) **or `✓` / `✗`** (turn
   ended or failed).
2. **The status line says so.** The notice goes on the left, ahead of the
   mode or the `? for shortcuts` hint. The usual rules cut it to the width:

   ```
     ● 2 claude needs your permission · ctrl+x a                   99% context left
   ```

   (`80-waits.txt`, `120-waits.txt`.) A form reads `● 2 claude asks for
   input`. When several sessions wait, the notice reads `● 3 sessions wait ·
   ctrl+x a`. A `●` notice is in `warning`. A turn that ended reads `✓ 3
   fake replied · ctrl+x a` and is dim, because nothing is blocked by it. The
   notice shows the most urgent one, and stays until there is nothing left to
   announce. The session in front never appears in this notice, because its
   own prompt is already on screen.
3. **The terminal is notified** through CHD-83's channel, once for each
   wait. The same events count (a turn that ends unless it was cancelled, a
   permission, a form or link), whether the session is in front or not. When
   more than one session is open, the message names the tab: `fake (2) needs
   your permission: Write notes.txt`.

**The window never switches by itself.** If it did, a person typing in tab 1
could have their next `1` land on tab 2's permission prompt and allow a
write they never read. The person moves with `ctrl+x a`, which goes to the
session that has waited the longest with a `●`. If none has a `●`, it goes to
the oldest `✓` or `✗`. If none has either, the status line says `No session
waits`. Pressing it again goes on to the next one, so a person can work
through a queue of requests.

A permission request in a session that is not in front stays parked in acpx's
`onPermissionRequest` until the person answers it. That session's turn waits;
the other sessions are not affected. When the person switches to it, the
prompt is there as it would have been in front, and the working line's
`Waiting for permission… (41s)` counts from when it arrived.

## Keys

All of these are in `Global`, so they work while a permission prompt, a form
or a picker is in front. `ctrl+x` is not used by the prompt's textarea
(react-ink-textarea uses ctrl+a/e/w/u/k/z/y/j), by chord's own keys, or by
tmux's default prefix. Each action is chord's own, under a `session:` name,
because Claude Code has no such actions. All of them can be rebound in
`keybindings.json`.

| Keys | Action | Does | Why this letter |
| --- | --- | --- | --- |
| `ctrl+x c` | `session:new` | a new session with the front one's agent, here | **c**reate, as tmux |
| `ctrl+x n`, `ctrl+x ctrl+n` | `session:next` | the next tab, wrapping round | **n**ext |
| `ctrl+x p`, `ctrl+x ctrl+p` | `session:previous` | the previous tab, wrapping round | **p**revious |
| `ctrl+x 1` … `ctrl+x 9` | `session:goto1` … `session:goto9` | that tab; a number with no tab does nothing | position |
| `ctrl+x a` | `session:attention` | the session that has waited longest (see above) | **a**ttention |
| `ctrl+x w` | `session:list` | the sessions picker | **w**hich, as tmux's choose-window |
| `ctrl+x k` | `session:close` | closes the front session; asks again if busy | **k**ill, as Emacs's buffer |
| `esc` (after `ctrl+x`) | — | drops the leader, does nothing else | |

The `ctrl+` forms of `n` and `p` are there so that a person who keeps ctrl
held down through the chord still gets what they meant. `ctrl+x ctrl+e`
(Claude Code's second key for the external editor) stays free to bind,
because no session action starts that way.

Chords are waited for with the matcher's 3 s timeout (`CHORD_WAIT_MS`), as
today. While a session key is pending, the digits, `n`, `p` and the rest go
to the leader and not to a permission prompt's list or a form, so `ctrl+x 2`
never answers "Always allow".

### The leader line

After `ctrl+x`, the status line shows the keys that can follow, until the next
key is pressed or the 3 s run out. chord's matcher already holds a chord's
first keys; nothing on screen shows them yet, so this line is new. It applies
to any chord whose first key is held, so a person's own `ctrl+k ctrl+e` also
shows its next keys:

```
  ctrl+x …  c new · n next · p previous · 1–9 go to · w list · a the one that waits · k close · esc never mind
```

At 80 columns:

```
  ctrl+x …  c new · n p next prev · 1–9 · w list · a waits · k close
```

(`120-leader.txt`, `80-leader.txt`.) The line is built from the bindings in
use, so a rebound or removed action shows up there correctly. Where a long
line has to be cut, actions are dropped from the end of the table above
rather than cut in the middle.

### The shortcuts panel

The `?` panel at 80×24 already fills its 19 rows (captured for this task). It
gets **one** new line, `ctrl + x then a key for sessions`, and the leader line
shows the rest. To keep the panel at 19 rows, two of its existing lines become
one: `ctrl + c twice to quit` and `ctrl + d to quit` become `ctrl + d or ctrl
+ c twice to quit`. Neither key can be rebound, so no hint depends on them.

If a person binds a session action to a key that does not start with the
leader, that action gets a line of its own in the panel (`ctrl + n for the
next session`), as rebound keys already do.

## The sessions picker (`ctrl+x w`)

It opens in the prompt box's place, in the same box and list as `/model` and
`/resume`. There is one row per session: position, agent, state, and its first
prompt (or nothing, for a session that has not had one).

```
╭──────────────────────────────────────────────────────────────────────────────╮
│ Sessions in ~/src/app                                                        │
│                                                                              │
│   1. fake    here              fix the failing test in…                      │
│ ❯ 2. claude  ● permission 41s  add a notes file                              │
│   3. fake    ✓ replied 2m ago  explain src/ui/state.ts                       │
│                                                                              │
│ Enter to go · 1–9 to pick · Esc to close                                     │
╰──────────────────────────────────────────────────────────────────────────────╯
```

(`80-picker.txt`, `120-picker.txt`.) The highlight starts on the session
`ctrl+x a` would go to, or else on the one after the session in front. The
state words are `here`, `working 12s`, `● permission 41s`, `● input 41s`,
`✓ replied 2m ago`, `✗ failed`, `idle`. The picker uses the list's keys
that `/resume` already uses (↑ ↓ j k, digits, Enter, `select:cancel`). It
does not close sessions: closing has one key, `ctrl+x k`, so that a slip in
the list cannot end a session.

## Closing (`ctrl+x k`)

- **Idle** session: it closes at once, and the tab to its left comes to the
  front (the one to its right, if it was the first). If the session had a
  prompt, the status line says `Closed 2 claude · /resume opens it again`. If
  it never had one, nothing is said.
- **Busy** session (a turn running, a permission or form open, or prompts
  queued): the first press only arms the close, as ctrl+c does for quit:

  ```
    1 fake is working · ctrl+x k again to stop it and close
  ```

  (`80-close-busy.txt`.) It reads `waits for your permission` or `has 2
  prompts queued` where that is the case. Pressing it a second time cancels
  the turn, refuses an open permission, cancels an open form, and closes the
  session. Any other key disarms it.
- **The last session**: closing it is a quit. It goes through the same check
  as `ctrl+d`.
- Closing an agent waits for its process to exit (`processes.ts`) in the
  background. The window does not wait for it.

## Quitting

- **With one session open**, quitting works exactly as it does today.
- **With several sessions open and none busy**, `ctrl+d`, `/exit` and ctrl+c
  twice quit at once.
- **With any session busy**, in front or not, `ctrl+d` and `/exit` arm first
  and name the busy sessions:

  ```
    2 sessions are busy: 2 claude waits for permission, 3 fake is working · ctrl+d again to quit
  ```

  At 80 columns this is `2 sessions busy · ctrl+d again to quit`
  (`quit-busy`). ctrl+c is already a double press. Its armed line adds the
  count: `Press ctrl+c again to quit · 2 sessions busy`.
- **On quit**, every session is closed in parallel, and chord waits for all of
  the agents to exit, as it does for one today. It then prints one resume
  command for each session that had a prompt, in tab order:

  ```
  Resume these sessions with:
  chord fake --resume 3f2a9c1e-…
  chord claude --resume 9b1c04d2-…
  ```

  With one resumable session, it prints today's `Resume this session with:`.

## Commands with several sessions

Every slash command acts on the **session in front**, and does what it does
today. That includes `/model`, `/config`, `/cost`, `/context`, `/status`,
shift+tab's mode, bash mode, `@`, ctrl+g and ctrl+v.

- **`/clear`** replaces the front session with a new session of the same
  agent, in the same tab. The other tabs are not touched.
- **`/resume`** opens the picked session in the front tab, replacing what was
  there, as today. To resume a session beside the current one, press
  `ctrl+x c` and then `/resume`. A session that is already open in a tab is
  marked `open in 2` in the list. Picking it goes to that tab and does not
  load it a second time, because two runtimes on one acpx record would write
  over each other. A session from another directory is still refused, with
  its command.
- **`/new [agent]`** is new: it is the slash command form of `ctrl+x c`.
- **The header's directory** is the window's directory, shown once. **The
  model and context left** on the status line belong to the front session,
  and change on switching.
- **`/status`** reports on the front session, and adds `Sessions: 3 open (1
  waits)` when more than one is open.

## How the build splits

CHD-115 builds this. It splits into parts that can each be checked on their
own.

**Session layer** (`src/session/`, no Ink):

1. **A set of conversations.** A pure module, `sessions` or `tabs`, holding
   the open sessions in tab order and the one in front. It handles open
   (with a cap of nine), close (with the next front chosen), next, previous,
   go to n, renumbering, and the attention order (oldest `●`, then oldest `✓`
   or `✗`). Each entry has its own `conversation.ts` and its own acpx
   runtime. Tests run it against the fake agent with two sessions at once.
2. **Each session's starting values.** The model and mode the settings set
   for a given agent, worked out for any agent name and not only the one
   `main.tsx` was given. `/new <agent>` needs this. The rest can land
   without it if it is cut.
3. **Per-session wait state.** Which tab waits, since when, and on what. This
   comes from the events `notify.ts` already classes as waits, and the
   message names the tab when more than one is open.
4. **Quit and close across sessions.** Close all of them in parallel and wait
   for every agent's exit, define busy, and print one resume command per
   session (`main.tsx`).
5. **`/resume` knows the open sessions.** It marks `open in n`, and picking
   one goes to that tab.

**Screen** (`src/ui/`):

6. **`state.ts` per session.** Today's window state splits into what belongs
   to a session (transcript, scroll, plan, queue, draft, images, bash mode,
   open permission or form, mode, model, usage) and what belongs to the
   window (verbose view, theme, vim, keymap, history, the open picker, the
   armed keys). This is the largest part, and the others need it.
7. **The strip.** The header row with tabs, inverse front, glyphs, and the
   shrinking order. A pure layout function with tests at 80 and 120 columns.
8. **The status line notice and the leader line**, in `status.ts`. Its
   priority sits ahead of the mode and hint, and each is cut to the width.
9. **Keys.** The `session:*` actions in `bindings.ts` (Global), entries in
   `keys.ts`, the panel's leader line and the merged quit line,
   `keys_test.tsx`, and the rule that a pending chord takes digits away from
   the permission list and forms.
10. **The sessions picker** on the existing picker list (`picker.ts`).
11. **The armed close and quit lines.**
12. **`/new`** in `commands.ts`, and `/status`'s line.

Order: 1 and 6 first, then 7 and 9, which make it usable. 3 and 8 come next,
which make it safe. The rest follow in any order.

## What to look at when it is built

- Open three sessions with the fake agent. Send `permission` in tab 2 and
  `slow` in tab 3, then switch to tab 1. The strip should read `2 claude ●`
  and `3 fake ✻`. The status line should carry the notice. There should be
  exactly one BEL. Typing `1` in tab 1 must not reach tab 2's prompt.
- `ctrl+x a` should land on tab 2's prompt, with `Waiting for permission…`
  counting from the start of the wait.
- Capture at 80×24 and 120×40 with `-e`, in a dark and a light theme. The
  front tab should be inverse in both, and `●` should be amber in both.
- Press ctrl+d with tab 3 working. It should arm, and a second ctrl+d should
  quit, print both resume commands, and leave no agent processes running.
