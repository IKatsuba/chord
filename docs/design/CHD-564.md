# CHD-564: a designed start screen

The owner, 2026-10-30: the start screen should be beautiful, not just a list.
Three questions are the owner's, and nothing is built until they are answered:

- **(a)** what the screen is made of besides the choice of agent, and how it is
  composed;
- **(b)** what it does in a window too short or too narrow for that composition;
- **(c)** whether `chord --resume`'s start changes with it or stays as it is.

This file puts four compositions and one recommendation to the owner. The
compositions are different answers to (a), each with its own (b). Question (c)
is drawn for all four, and is asked apart in [its own section](#c-chord---resume).

## What holds in every option

- **The choice works as `docs/guide.md` says.** The same `❯` and highlight in
  `permission`, the same ↑/↓, j/k, Enter and 1–9, the same Esc or ctrl+c quit
  with nothing started. The options keep the words of today's hint, except
  where a window too narrow for them is noted.
- **Routes that skip the picker still skip it:** a named agent,
  `--agent-command`, `-p`, `--continue`, any `--resume` form, and no terminal
  (`chooseAgentAtStart`, `src/ui/app/startup_choice.ts`, is not touched).
- **The list holds at any length.** Today 28 rows on this machine with one
  settings-defined agent (25 of the Registry's, the own CLIs on PATH, the
  settings' one), and few once CHD-565 gives it a setting; CHD-565 is not
  designed here. Each option is drawn at both lengths. The list is the one
  thing that never gives way: every art row goes before a list row falls under
  three.
- **Colours by role, in every theme.** `permission` for the choice; the mark's
  gradient (`mark.stops`, or `mark.tone` in 16 colours); dim and plain text
  stay the terminal's own. Under `NO_COLOR` the mark is the terminal's
  foreground and the wordmark is bold `chord`.
- **Logic in a pure module.** Whichever option wins, the tier a window gets is
  a pure function of its size and the list's length, with tests; the component
  only draws.

## What each thing shown really costs

Every value on these screens was checked against what the start path has before
any agent starts. The PNGs draw a fixture directory, fixture sessions and one
fixture settings agent (`local`); the list of agents and what starts each are
the real catalog.

| --- | --- | --- | --- |
| Directory | yes, `shownPath` is already passed in | nothing new | all |
| chord's version | yes, the manifest, as `--version` | nothing new | all |
| The mark | yes, `header/mark.ts`, generated | nothing new | all |
| The tagline | static words: the README's own first line | nothing | A |
| An agent's title, start line, source | yes, `listedAgents` already read them | nothing new | C |
| An agent's install page | yes, `findAgent(name).install`, compiled in | nothing new | C |

| Recent sessions, across agents | **not read on this route today**, and `earlierSessions` filters by one agent | `readRecords` reads every record whole: **5,038 records, 3.2 GB here, 6–7 s and over 1 GB of memory** at low priority, once per unnamed start. It would have to run after the first paint, and fill in late, or need an index first | D |

Login, readiness and an agent's models are not known before it starts, and no
option claims them. No option shows an update notice or a tip list: chord has
no such data.

## Libraries checked for the large wordmark

The one rule, so before anything drawn by hand:

- **OpenTUI's `<ascii-font>`, already a dependency.** Seven fonts: `tiny` 2
  rows (19 columns for this word), `slick` 6 (29), `block` 6 (45), `shade` 8
  (24), `huge` 11 (69), `grid`, `pallet`. It draws with a gradient-free colour
  per font layer. It fits, with two findings:
  - **Every font is capitals only.** `chord` is drawn `CHORD`; the name is
    written in lower case everywhere else.
  - **It needs a real colour.** A role left out, as `NO_COLOR`'s palette leaves
    it, crashes the renderable (`rgba.buffer` of undefined), and its own default
    is white, unreadable on a light terminal. So the wordmark is drawn only
    where the palette has `mark`; else bold text. This is choosing not to use
    it, not a workaround around it.
- **figlet (npm), not a dependency.** Lower case exists only in its thin
  line-art fonts (`Slant`, `Small`, `Standard`). Its solid ones (`ANSI Regular`,
  `Calvin S`) are capitals too. It would be a new dependency, whose fonts must
  be proved to survive `bun build --compile`; that was not tried, and is
  needed only if the owner picks Slant.
- **The mark** is `SPLASH_MARK`, 8 rows, generated by `bun dev mark`, and `MARK`,
  4 rows. Nothing new is drawn for it.

So the wordmark is a question of its own, under option A.

## (c) `chord --resume`

Today it is one line and the framed `Resume a session` picker. Its route knows the
agent, and has already read the records.

| Choice | What it means | For and against |
| --- | --- | --- |
| **Follows** the chosen option | The same page around the same `ResumePicker`, its words and keys as they are: A's art above it, B's header, C's panes, D's box | One start screen, and one `Start` component that stays one. It needs no new read. In C it costs a new list and detail pane rather than `ResumePicker`, and D's box has nothing of its own to say there. |
| **Stays** as it is | `main-resume-*` | No risk and no work. Two first screens that no longer look alike, chosen by a flag. |

Each option's `resume` picture draws the first choice. It is at its best in A and B,
which keep `ResumePicker` whole, and needs the most in C.

## Empty and error states

Today's stay, in the same place in the composition: `No agents available` with
only Esc in the hint, and `chord --resume` with no sessions refused on stderr
before anything draws. A refusal after the pick goes through `leaveStart` as
today. No option has a waiting state of its own: the catalog is read before the
first paint; only D's sessions would arrive late.

## Recommendation

**A, the title page, with `block`, and `chord --resume` following it.** The owner
asked for beautiful, and A is the only option where that is the first thing seen.
It is also the cheapest: nothing new read, no new key, no new action, a library's
font, and it falls back in tiers to a line like today's, so the hold on the choice
is not at risk. Its centred mark leads straight into the splash's. What it gives
up: fewer list rows at once than B or C, and capitals in the wordmark, which is
the sub-question above. B is the choice if chord should look on its first screen
exactly as it does on every other; C if showing what will run matters more than
how the screen looks. D should not be taken in this task: its data costs seconds
and gigabytes here, and it is a new feature rather than a new face.
