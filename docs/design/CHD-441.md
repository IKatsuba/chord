# CHD-441: telling the person which MCP servers an agent was not passed

Decided by the owner (2026-10-18): chord passes an agent only the MCP
servers whose transport its `initialize` `mcpCapabilities` advertises
(stdio always, per ACP; `http` and `sse` only when advertised), chord's own
server included, and tells the person which servers were held back from
that agent and why. This doc settles where and when the person is told,
and in which words. What chord does for an agent that advertises
transports but refuses any server (openclaw) is with the owner (Q90); the
words for it, should the owner want them, are drawn below.

## Today

Captured on the fake agent with `CHORD_FAKE_NO_HTTP=1` (it advertises no
HTTP) and a user settings file with a stdio, an http, an sse and a broken
server (`evidence/CHD-441/today/`, `start-` and `mcp-`, 120×40 and 80×24):

```
 ▀▄     chord v0.56.0
 ▀▀▀▄   fake · Fake Large with a 1M context window
 ▄▀▀▀   /tmp/chord-qa.des441
 ▀▀     ? for shortcuts · /help

 ⏺ /tmp/chord-qa-home.des441/chord/settings.json: "mcpServers.broken.url": missing; the server is ignored
```

What is there already, and what this design follows:

- **A server chord leaves out is said once, at the transcript's top, in
  the warning colour**: the broken server above. The `⏺` and its words
  are `warning` (#ffc107 dark), as every settings problem is. It is part
  of the transcript: it scrolls away with it, takes no key and needs no
  dismissing.
- **`/mcp` already says when a server was not passed**, for chord's own:
  its row reads `not passed` in the Command or URL column, and under the
  table `chord's server was not passed: fake does not take MCP servers over
  HTTP, so it cannot start other agents.` Today the person's own servers
  are always passed, so `/mcp` lists `docs` and `tracker` as passed to an
  agent that refuses them.
- **Nothing at the start says chord's own server was not passed**; only
  `/mcp` does.

At 80×24 (`mock/start-stdio-80x24.txt`), wrapped two in, never cut:

```
╰──────────────────────────────────────────────────────────────────────────────╯
```

- **For it:** it is where chord already says that a server was left out,
  in the same colour and form; it is seen before the first prompt, which is
  when it matters (an agent asked to use `docs` will not have it); it costs
  no key, no new widget and no new line on the status line.
- **Against it:** it scrolls away; `/mcp` keeps it (below).

### B: `/mcp` only

The table and its paragraph change as below, and nothing is said at the
start.

- **For it:** nothing new on screen.
- **Against it:** the person learns it only by opening `/mcp`, which they
  have no reason to do until a server they rely on is missing; the owner's
  "tells the person" is then a place to look, not a telling.

### C: the status line at startup

A transient line, `3 MCP servers not passed · /mcp`, in the status line's
left slot for some seconds.

- **Against it:** the status line holds no notices today, only the mode,
  the hints and the session; a transient text is missed by a person
  looking at the prompt, and one that stays needs a key to dismiss, a
  shortcuts-panel entry, and a rule for which of several notices wins.
  Nothing in `docs/design/` does this.

## The words

One template for the transcript line:

`N MCP server(s) was/were not passed to <agent>, which <why>: <names>. [Without chord's own, <agent> cannot start other agents or use chord's tools.] /mcp lists it/them.`

The bracketed sentence is there only when chord's own server is among them; `Without it,` when it is the only one.

`<why>` names exactly the transports the agent takes, stdio always first,
then HTTP, SSE and ACP in that order, from what its `initialize` advertises
(settled by the lead, 2026-10-21: an agent that takes stdio and ACP must not
read "stdio only"). The names carry their transport when the agent lacks
two or more of HTTP, SSE and ACP, so the person sees which is which; bare
when it lacks one, as every held-back server is then of that one.

| The agent takes | `<why>` | Names |
| --- | --- | --- |
| stdio | `takes them over stdio only` | with their transport: `chord (http, chord's own), docs (http), tracker (sse)` |
| stdio, HTTP | `takes them over stdio and HTTP only` | with their transport: `tracker (sse)` |
| stdio, SSE | `takes them over stdio and SSE only` | with their transport |
| stdio, ACP | `takes them over stdio and ACP only` | with their transport |
| stdio, HTTP, SSE | `takes them over stdio, HTTP and SSE only` | bare |
| stdio, HTTP, ACP | `takes them over stdio, HTTP and ACP only` | bare: `tracker` |
| stdio, SSE, ACP | `takes them over stdio, SSE and ACP only` | bare; chord's own as `chord (chord's own)` |
| stdio, HTTP, SSE, ACP | no line: nothing is held back for its transport | — |
| any, but refuses every server (openclaw, if Q90 says so) | `takes none` | bare, every one |

The transports are written as prose writes them, `HTTP`, `SSE`, `ACP`;
in a server's brackets as `/mcp`'s Transport column does, `http`, `sse`,
`acp`. `/mcp`'s paragraph takes the same `<why>`:
`tracker was not passed: fake takes MCP servers over stdio and HTTP only.`

```
 ⏺ 1 MCP server was not passed to fake, which takes them over stdio and HTTP only: tracker (sse). /mcp lists it.
 ⏺ 3 MCP servers were not passed to openclaw, which takes none: filesystem, docs, tracker. /mcp lists them.
 ⏺ 1 MCP server was not passed to fake, which takes them over stdio only: chord (http, chord's own). Without it, fake
   cannot start other agents or use chord's tools. /mcp lists it.
```

(`mock/start-sse-*.txt`, `mock/start-none-*.txt`, `mock/start-chord-*.txt`.) Every name is said,
however many, wrapped and never cut, as a settings problem is. `<agent>` is
the agent as `/mcp` names it, its runtime's name (`fake`, `codex`), since
the reason is the runtime's and the line is in that session's own
transcript.

**chord's own server is in the line** (settled by the lead, 2026-10-21, on
the owner's decision that chord's own follows the same rule): first, as
`/mcp` lists it first, by its name (`chord`, or `chord-2` where one of the
person's is `chord`) with `chord's own` beside its transport, then a
sentence for what losing it costs, since it takes chord's tools with it. It
is counted in `N`. Under openclaw's `takes none` (Q90) it is named the same
way.

## When, and how often

- **Per session, at its start.** Every session chord opens computes what it
  passes from that agent's `initialize`, so each says its own: main, a new
  tab, a resumed session, `/new`, a child opened with `open_agent`, a team
  member, each in its own transcript's top. A resumed session says it where
  its settings problems are said on resume, as servers are passed afresh on
  every resume.
- **A task agent** has no transcript of its own: its line goes into the
  parent's turn as a task's other notes before its start do (a refused
  effort), `<task name>: ` ahead of it, in the same colour, `<agent>`
  being the task's runtime.
- **No dedupe across sessions.** Each tab is read alone; a second codex
  tab that did not say it would read as if codex took every server there.
- **Nothing said** when every server was passed, or none is configured.

## Colour roles

`warning` for the `⏺` and the line, as the settings problems; no new role.
`/mcp`'s `not passed` and paragraph keep its existing dim text.

## Keys

None. The line is transcript text and is never dismissed; `/mcp` is opened
and closed with its existing keys (`/mcp`, `esc`).

## Recommendation

**A, the line at the session's start, with `/mcp` listing the held-back
servers as `not passed`.** It is how chord already says a server was left
out, at the moment the person can still act (fix the server's transport or
pick another agent), and `/mcp` keeps it for later. B does not tell; C
invents a notice slot and a dismiss key that nothing else uses.
