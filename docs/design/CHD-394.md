# CHD-394: a code block's buttons, copy and put into the prompt

The owner decided (2026-10-15, revised 2026-10-25): every code block in a
reply gets a copy button; a block labelled `sh`, `bash` or `console` also
gets a run button, which puts its command into the prompt box in bash mode
(`!`) and runs nothing; an unlabelled block gets copy only. A copy gives
the selection copy's feedback (CHD-172). The buttons are bracketed, on the
box's top border, right-aligned (owner, second round). Two variants are
drawn for the owner to pick from (§1). What the run button puts in for
several lines, `$ ` prompts and `console` output is the owner's open
question, with options in §5.

Captures are in `evidence/CHD-394/`: `today-*` is chord at fdc2df86 on the
fake agent's `markdown` scenario at 120×40 and 80×24. Every other picture is
that capture with only this design's changes edited in: `words-*` is
variant A, `icons-*` variant B, and `sbs-*` puts the two side by side on
the same screen. Each is a whole-window colour PNG with its text beside it.

## 1. The buttons

### The two variants

**A: `[copy]` `[run]`** and **B: `[□]` `[!]`**, on the same blocks
(`sbs-icons-120x40`, `sbs-icons-80x24`):

```
A  ┌─ ts ──────────────────────────────────────────────── [copy] ─┐
   │ const session = await openSession({ agent: 'claude', cwd }); │

      ┌─ sh ─ [copy] [run] ─┐
      │ deno task check     │
      └─────────────────────┘

B  ┌─ ts ─────────────────────────────────────────────────── [□] ─┐
   │ const session = await openSession({ agent: 'claude', cwd }); │

      ┌─ sh ── [□] [!] ─┐
      │ deno task check │
      └─────────────────┘
```

- **A** names what each does; every terminal draws it, being ASCII.
  `[run]` suggests running though it only fills the prompt; the shortcuts
  panel and the pick line say "put in the prompt" (§3).
- **B** is shorter and keeps a box at its code's width more often. `!` is
  bash mode's own key and gutter, so it says where the command goes. `□`
  (U+25A1) is one cell in every monospace font installed here (`fc-list`:
  Menlo, JetBrains Mono, Monaco, Andale Mono, Courier New, FiraCode Nerd
  Font); the brackets make it read as a button rather than a missing glyph.

### Place

- **Right end of the top border**, a space before each button and between
  them, then the border's last `─┐`. The language label keeps its place on
  the left, as today, and the code's rows are untouched, so a copy over the
  code reads as it does now.
- **Which boxes.** The copy button on every code box, in a quote and in a
  list too. The run button only on `sh`, `bash` and `console`. An
  unlabelled box: `┌───────── [copy] ─┐` / `┌──────── [□] ─┐`. A table is
  not a code block and gets nothing.
- **Look.** The buttons are in the text's own colour on the dim border, so
  they read as something to press. No hover look: chord reads the mouse
  without motion reports (CHD-172 turned 1003 off). A picked box is drawn
  in the accent colour, buttons bold (§3).
- **Streaming.** A box whose fence is still open gets no buttons until it
  closes: its text is not final.

### A narrow block

A box is at least wide enough for its label, one `─`, and its buttons, as
it already grows for a label wider than its code (`markdowncode`). The
least widths, corners included:

| Box | A | B |
| --- | --- | --- |
| `sh` with both | `┌─ sh ─ [copy] [run] ─┐`, 23 | `┌─ sh ─ [□] [!] ─┐`, 18 |
| `console` with both | 28 | 23 |
| `ts`, copy only | `┌─ ts ─ [copy] ─┐`, 17 | `┌─ ts ─ [□] ─┐`, 14 |
| unlabelled, copy only | `┌─ [copy] ─┐`, 12 | `┌─ [□] ─┐`, 9 |

`deno task check` needs a box of 19. Under A the box grows to 23, the
least it can be, with one `─` between label and buttons (`words-icons-*`,
the box under "Run the checks"); under B it fits as it is, with two
(`icons-icons-*`).

**One cell narrower:** a box is never drawn narrower than its least
width; it grows by that cell instead, its code padded on the right, as for
a wide label. Only when the transcript itself has fewer columns than the
least width (a window under about 30 columns) do the buttons give way: the
run button first, then copy, then the label is cut as today. Their keys
(§3) still work then.

### Clicks

A press and a release on the same button is a click. The whole bracketed
word answers, brackets included: `[copy]` six cells, `[run]` five, `[□]`
and `[!]` three each. A click copies or puts into the prompt, as the keys
do.

- **The wheel** is unchanged: it is its own button, and a button never
  answers it.
- **The selection.** The border is chord's furniture and starts no
  selection (CHD-172); the buttons are part of it, so a press on one starts
  none either. A press there clears a shown selection, as any press
  elsewhere does. A drag that starts in the code and ends on a button is a
  selection, not a click.
- **The terminal's own selection** (shift-drag) is untouched: a shift-held
  press goes to the terminal, never to chord.

## 2. The copy feedback

The selection copy's note, word for word, alone on the status line for 3 s
(`COPIED_NOTE_MS`, `sbs-copied-*`):

```
╭──────────────────────────────────────────────────────────────────────────────╮
│ ›                                                                            │
╰──────────────────────────────────────────────────────────────────────────────╯
  copied 75 chars to clipboard
```

and `sent N chars to the terminal's clipboard` when only OSC 52 went, as
CHD-172. N counts the block's graphemes. What is copied is the block's text
as the agent wrote it, its lines joined with newlines: no border, no label,
no wrapping of chord's, no trailing newline. The copy goes through the
selection copy's clipboard path (`createClipboard`), with its failure note.

## 3. The keys

A leader, then a picking mode, so nothing takes a key the prompt, the
selection or the wheel already uses.

- **`ctrl+x b`** picks a code block. `ctrl+x` is chord's leader (`ctrl+x a`
  for what waits on the person), and the leader line names it
  (`words-leader-*`):

  ```
    ctrl+x …  b a code block · a the one that waits · esc never mind
  ```

- **Picking.** The newest code box on screen is picked; if none is on
  screen, the newest in the transcript, and the view scrolls to show it
  whole. The picked box's border, label and buttons turn to the accent
  colour, the buttons bold, and the status line names the keys
  (`sbs-picked-*`, `sbs-picked-up-*`):

  ```
  A   ↑ ↓ another block · c copy · r put in the prompt · esc done
  B   ↑ ↓ another block · c copy · ! put in the prompt · esc done
  ```

  - **↑ ↓** move to the block above or below, across replies, scrolling
    the transcript so it is whole in view.
  - **c** copies it (§2) and ends picking.
  - **r** (A) or **!** (B), the run button's key, puts it into the prompt
    (§4) and ends picking. On a block without a run button it does nothing,
    and the status line leaves it out (`words-picked-ts-120x40`,
    `icons-picked-ts-120x40`).
  - **esc** ends picking with nothing done.
  - Any other key ends picking and then does what it does today; the wheel
    and pgup/pgdn scroll as usual and keep the pick.
- **Why not plain keys.** Tab is `chat:steer` during a turn and the lists'
  completion; ↑ ↓ are history; letters are text. A mode reached through the
  leader owns its keys only while it lasts, as the agents list does.
- **No code block in the transcript:** `ctrl+x b` leaves the note `No code
  block to pick` for 3 s.
- **Rebindable**, in `bindings.ts`, in a `CodeBlock` context:
  `codeBlock:pick` (`ctrl+x b`, Global), `codeBlock:copy` (`c`),
  `codeBlock:prompt` (`r` under A, `!` under B), `codeBlock:previous`
  (`up`), `codeBlock:next` (`down`), `codeBlock:cancel` (`escape`).
- **The shortcuts panel**, two lines, after `ctrl + x a for what waits on
  you`:

  ```
  A   ctrl + x b to pick a code block
      c r to copy a block or put it in the prompt
  B   ctrl + x b to pick a code block
      c ! to copy a block or put it in the prompt
  ```

  The panel scrolls at 80×24 since CHD-378, so two more lines cost a row of
  scroll.

## 4. After "put into the prompt"

The prompt box in bash mode holding the command, the cursor at its end,
nothing run (`sbs-prompt-*`; the box is the same under both variants):

```
╭──────────────────────────────────────────────────────────────────────────────╮
│ ! deno task check                                                            │
╰──────────────────────────────────────────────────────────────────────────────╯
  ! for bash mode
```

It is today's bash mode exactly, as if the person had typed `!` and the
command: Enter runs it in the session's directory, its output held for the
agent ahead of the next prompt; backspace on an empty draft leaves bash
mode; esc and ctrl+c behave as in bash mode today.

- **A draft already in the box** is never replaced: nothing is put in, the
  draft stays, and the status line says `The prompt holds a draft · ctrl+c
  clears it` for 3 s, in the warning tone of a notice whose ask did not
  happen.
- **During a turn** it goes in all the same; bash mode during a turn works
  as today.

## 5. Open for the owner: what the run button puts in

Three cases, each with options, each mocked as the prompt box after the run
button (`words-q-*`, at both sizes; the prompt box does not depend on the
variant).

### a. A block of several lines

```sh
deno task compile --all
for bin in dist/*/chord; do echo "built $bin"; done
```

- **A. The whole block, as its lines** (`words-q-multi-a-whole-*`). The box
  holds both lines; Enter runs them as one script, in order. What the agent
  wrote runs as written. *Recommended.*

  ```
  │ ! deno task compile --all                                    │
  │   for bin in dist/*/chord; do echo "built $bin"; done        │
  ```

- **B. The first line only** (`words-q-multi-b-first-*`). The rest is left
  to a copy. Safe, but a `for` loop or a heredoc split over lines is cut.
- **C. The lines joined with ` && `** (`words-q-multi-c-and-*`). One line
  that stops at the first failure; breaks any construct that spans lines.

### b. Lines that start with a `$ ` prompt

```sh
$ bun install
$ bun test tests/parse
```

- **A. The `$ ` taken off each line that starts with it**
  (`words-q-dollar-a-stripped-*`). *Recommended:* `$ bun install` would try
  to run a command named `$`.
- **B. Kept as written** (`words-q-dollar-b-kept-*`), the person edits it.

### c. A `console` block with commands and output

```console
$ bun test tests/parse
bun test v1.4.3

 12 pass
 0 fail
```

- **A. Only the `$ ` lines, the prompt taken off**
  (`words-q-console-a-commands-*`); a `console` block with no `$ ` line gets
  copy only, no run button. *Recommended.*
- **B. Every line, output too** (`words-q-console-b-all-*`), the person
  deletes what is not a command.
- **C. Copy only for `console`** (`words-q-console-c-copy-only-*`): the run
  button stays on `sh` and `bash`.

## Colour roles

- Buttons: the text's own colour; border and label dim, as today.
- A picked box: `accent` for its border, label and buttons, the buttons
  bold.
- The copy note: as CHD-172's. The draft notice: `warning` (the `failed`
  tone).
- The prompt after the run button: bash mode's `bash` colour, as today.

## Why

The owner wants a block one press from the clipboard or the shell. The
buttons sit on the border so the code a person reads and copies is
unchanged, bracketed so they read as buttons in any font. A key path through
chord's leader and a short picking mode reaches every block without taking
a key the prompt already owns, and it reads on screen as the box lighting
up with its keys under the prompt. Putting the command into bash mode rather
than running it keeps the person's Enter between an agent's text and their
shell.
