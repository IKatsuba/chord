# CHD-174 — Windows in the resume picker, and `chord --resume` with no id

CHD-173 saves a window record when chord quits with two or more resumable
tabs. The record has an id `w-…`, a time, the tabs in order (each with its
session, agent and cwd) and the tab in front. This design puts those records
in `/resume` beside single sessions, and gives `chord --resume` with no id a
picker before anything opens, as `claude --resume` does.

There is no new widget. A window is one more row in the picker list that
`/resume` already draws (`picker.ts`). The mocks are in
`evidence/CHD-174/mock/`, at 120×40 and 80×24, laid out to exact widths on
the real `/resume` screen (CHD-101's captures) and CHD-114's tab strip. The
directory is `~/src/app` and the front agent is `claude` throughout.

The reference was Claude Code's `claude --resume`, opened in an empty
temporary directory with no prompt sent. It draws a full-screen picker before
any session (`Resume session`, `No conversations found in this project.`,
`Ctrl+A to show all projects`), and Esc exits claude.

## The decisions, in short

| Question | Answer |
| --- | --- |
| (1) Where windows sit | **In one list with the sessions, newest first.** No group of their own. A window's sessions stay on the list as rows of their own too. |
| (2) The row | `when  [directory]  ▣ 3 sessions · claude, codex, claude · <front tab's first prompt>`, in the columns sessions already use. |
| (3) Enter on a window in a running chord | Its tabs open **beside** the ones open, at the end of the strip, and its front tab comes to the front. An empty front tab is reused. Tabs already open are not opened twice. Over the cap of nine, **nothing opens** and the status line says how many to close. |
| (4) `chord --resume` with no id | The same picker, **before any agent starts**, over an empty window. Esc quits, as in Claude Code. |
| (5) Showing a window's sessions | **The summary only, one line.** No expand. The sessions are rows of their own on the same list. |

## (1) One list, by time

Windows and sessions are sorted together, newest first. A window's time is
its record's time, which is when the window was quit.

- **Why not a group of their own.** A person remembers "what I was doing
  ten minutes ago", not "was it a window or a session". Claude Code's picker
  is a single list by time too. A group at the top would push this
  morning's sessions below last week's windows, and with ten rows at 120×40
  and six at 80×24 there is no room to spare.
- **A window's sessions stay on the list.** Each session can still be
  resumed on its own. That is the only way to bring back one tab of a
  window from `/resume`, and hiding them would take away something that works
  today. Because a session was last used when its window was quit, its row
  sits just under its window's row (rows 1–3 in `120-resume.txt`). So the
  list already reads as "the window, then what was in it", without any
  nesting.
- **Agents.** `/resume` lists the front tab's agent's sessions, as today.
  A window holds several agents by nature, so **every window is listed
  whatever its agents are**. A codex tab of a window is not listed as a
  session in a claude tab, which is the same as today.
- **Scope (ctrl+a).** A window is in "this directory" when **every** one of
  its tabs works in this directory. Those are the only windows Enter can open
  here (see (3)). A window with any tab elsewhere shows only under ctrl+a,
  as a session from elsewhere does.

## (2) The window row

```
❯ 1. 10 minutes ago  ▣ 3 sessions · claude, codex, claude · fix the failing date test in the parser
  2. 10 minutes ago  fix the failing date test in the parser
```

- **The columns stay as they are.** The when column comes first and is padded
  with the sessions' times. Under ctrl+a the directory column comes next,
  then the text. A window's text starts with `▣`, and that glyph is what tells
  a window from a session. Sessions get no glyph and no indent, so their
  prompts stay where they are today.
- **`▣ N sessions`**: the number of tabs the record names. A record always
  has at least two.
- **The agents**, in tab order with repeats, as the owner's example has them
  (`claude, codex, claude`), because the order is the strip's order. When the
  list is longer than **30 columns** (`DIRECTORY_WIDTH`, the budget the
  directory column already has), it becomes counts, in order of first
  appearance: `claude ×5, codex ×2, gemini, opencode`. If that is still
  longer than 30, agents are dropped from the end at a `, ` and the rest are
  counted: `claude ×5, codex ×2, gemini +1`. A name is never cut in half.
- **The front tab's first prompt** comes last. Two windows with the same
  agents look identical without it, and it is the same text the session rows
  show, so a window and its front session visibly match. Like every row, it
  is cut at the picker's edge with `…`.
- **The directory under ctrl+a** is the front tab's directory, shortened as
  for sessions (`homePath`, `cutPath` to 30). If the tabs span more than one
  directory, it gets ` +n` for how many others: `~/src/app +1`. The ` +n`
  counts toward the 30 columns and is never the part that gets cut.
- **At 80 columns** the row keeps `▣ 3 sessions · claude, codex, claude` and
  loses the prompt (`80-resume.txt`). Under ctrl+a, with a 30-column
  directory in the list, it keeps only `▣ 3 sessions · claude, …`
  (`80-resume-all.txt`). That is the same cut every session row gets at that
  width, and `▣` and the count still tell the windows apart.
- **The subtitle** becomes `claude's earlier sessions and saved windows in
  this directory.` and `… in every directory.` under ctrl+a. Both fit inside
  76 columns, so neither is cut at 80. CHD-101 showed that a subtitle cut
  mid-sentence reads as a bug. In the empty case, the line reads `No earlier
  sessions or windows in this directory.`
- **Footer**: unchanged, `Enter to resume · Ctrl+a for … · Esc to close`.
  Enter on a window "resumes" it as well.

`▣` (U+25A3) is one column wide in tmux, as `❯` and `⏺` are (checked).

## (3) Enter on a window in a running chord

A single session picked from `/resume` replaces the front tab (CHD-114). A
window does not replace anything that has had a prompt, because one row would
then throw away a session the person is working in. Instead:

1. **Tabs already open are not opened twice** (CHD-121's rule: two runtimes on
   one record would write over each other). They count as present.
2. **The other tabs open in the window's order, at the end of the strip.**
   The window's front tab comes to the front, or, if it was open already, the
   person goes to its tab. This is CHD-114's "a new session goes to the end
   and comes to the front", applied once per window.
3. **An empty front tab is reused.** If the tab in front has never had a
   prompt (as with plain `chord` followed by `/resume`), the window's first
   tab to open takes its place, so the person ends up with exactly the window
   and no stray empty tab. Any other empty tabs are left alone.
4. **Every tab already open**: Enter just goes to the window's front tab. No
   message is shown, because the strip already shows where the person is.

**Against the cap of nine**, the count is: tabs open, minus an empty front
tab that would be reused, plus the window's tabs not already open. If that
is more than nine, **nothing opens**. The picker closes, and the status line
says so in `warning`, as the tenth `ctrl+x c` does (`120-cap.txt`,
`80-cap.txt`). For 7 open and a 3-tab window:

```
  That window needs 3 tabs and 2 are free · close 1 with ctrl+x k, then /resume again     (120)
  That window needs 3 tabs, 2 are free · close 1 with ctrl+x k first                      (80)
```

Why refuse instead of opening the first two: half a window is a third thing,
neither the window nor what was open. It would also leave the person guessing
which tab was dropped. CHD-172 refuses ten ids instead of opening nine, for
the same reason. Asking "open 2 of 3?" would need a prompt chord does not
have, to offer something nobody wants. Closing a tab is one chord away, and
`/resume` keeps its place. The message counts what is needed: with 9 open and
a 2-tab window, it reads `needs 2 tabs and none are free · close 2 …`.

**A window with a tab in another directory.** In a running chord, `/resume`
refuses a session from another directory and gives its command (CHD-101).
A window follows the same rule for each of its tabs. If any tab would be
refused on its own, the whole window is refused, and the transcript gives the
command that opens it, on a line of its own, as CHD-101 does
(`120-elsewhere.txt`):

```
 › /resume
   ⎿  That window has a tab in ~/src/api. Quit and open it there with:
      chord --resume w-7c41e09b
```

If CHD-101's refusal is ever lifted for sessions, this one lifts with it.
There is one rule, not two.

**A missing session record.** The window opens the rest, and the status line
names the one that is missing, exactly as `chord --resume w-…` does (CHD-173).
The row itself is drawn from the window record alone. A window whose session
records are **all** gone is not listed.

### Beside CHD-121's `open in n`

A session that is already open reads `open in 1 · <prompt>`. A window with
some of its tabs open reads `▣ 3 sessions, 2 open · claude, codex, claude · …`.
With all of them open it reads `▣ 3 sessions, all open · …` (`120-open.txt`,
`80-open.txt`). A window cannot say one `open in n`, because its tabs can be
scattered across the strip. So it says how many are open, and Enter takes the
person there (rule 4) or opens the rest (rules 1–2). The mark goes right
after the count, where a cut at 80 columns never reaches it.

CHD-121 is not built yet. If it puts `open in n` somewhere other than at the
start of the session's text, the window's `, 2 open` stays where it is: it is
part of the summary, not a column.

## (4) `chord --resume` with no id

What `claude --resume` does: a picker comes first, and Esc leaves.

- **On screen before a choice**: the header as usual (` chord`, then
  `claude · ~/src/app`, the agent `[agent]` names or the default), empty space
  where the transcript would be, and the same picker at the bottom
  (`120-start.txt`, `80-start.txt`). **No prompt box and no status line.**
  Nothing has started yet, so there is no model, mode or context to report,
  and a prompt box would invite typing that goes nowhere.
- **No agent starts until a choice is made.** The pick decides the agent, the
  directory and the number of tabs. Enter then goes exactly where `chord
  --resume <id>` or `chord --resume w-…` would go. So **a session or window
  from another directory opens here, with no refusal**: nothing hangs on a
  directory yet. The subtitle says `Pick one of claude's earlier sessions, or
  a saved window, to open.` In this picker, `open` means open, not `here`.
- **Rows, ctrl+a and scope** are the same as in `/resume`. There is no
  `open in n`, because nothing is open.
- **Esc quits.** The footer says `Esc to quit`. The terminal comes back with
  nothing printed, because no session had a prompt. Starting an empty session
  instead would launch an agent the person did not ask for. `chord` with no
  flag already does that.
- **Nothing in this directory, something elsewhere**: the picker opens anyway,
  saying `No earlier sessions or windows in this directory.` above `Ctrl+a
  for all directories · Esc to quit` (`120-start-empty.txt`). This matches
  CHD-101 and Claude Code.
- **Nothing anywhere**: no window at all. It is refused before Ink, like
  `--continue`'s refusal: `No earlier claude session or window to resume.` on
  stderr, with a non-zero exit.
- **Not a terminal** (stdin or stdout piped): refused the same way, saying
  `--resume needs an id when not in a terminal`. `-p` with `--resume` is
  already refused.

## (5) A summary, not an expansion

A window row is one line. It does not expand, and it has no second line.

- `picker.ts` draws one line for each choice, with one key set (↑ ↓ j k,
  digits, Enter). Expanding would need a key to open and close a row, rows
  that come and go under the highlight, and numbers that shift. That is a
  tree widget, which is new code against the one rule. It also does not fit
  at 80×24, where six rows are all there is.
- It is not needed. The window's sessions are on the same list, just under
  it (1), and the summary carries the agents and the front tab's first
  prompt, which is what tells two windows apart.

## States, at a glance

| State | 120×40 | 80×24 |
| --- | --- | --- |
| `/resume`, two windows among sessions | `120-resume.txt` | `80-resume.txt` |
| the same with ctrl+a (multi-directory window, nine-tab window) | `120-resume-all.txt` | `80-resume-all.txt` |
| `chord --resume` with no id, before a choice | `120-start.txt` | `80-start.txt` |
| the same, nothing in this directory | `120-start-empty.txt` | `80-start-empty.txt` |
| the cap: 7 open, Enter on a 3-tab window | `120-cap.txt` | `80-cap.txt` |
| a window with two of its tabs open, beside `open in 1` | `120-open.txt` | `80-open.txt` |
| a window with a tab elsewhere, refused with its command | `120-elsewhere.txt` | `80-elsewhere.txt` |

The highlighted row is drawn in the theme's `permission` colour, as today. A
text file cannot show that, so the build's captures need `-e`.

## The build's acceptance screens (CHD-175)

Against the fake agent, with a temporary HOME and XDG directories, at 120×40
and 80×24, under these names in `docs/design/evidence/CHD-175/`:

1. `resume` — `/resume` with two saved windows (one of 3 tabs on two agent
   names, one of 2) and at least four sessions: windows sorted by time among
   them, `▣` rows as above, and the subtitle not cut at 80.
2. `resume-all` — ctrl+a on the same, with a window whose tabs span two
   directories (`~/src/app +1`) and one of nine tabs whose agents fold to
   counts.
3. `opened` — Enter on the 3-tab window from a fresh `chord` that has had
   no prompt: three tabs, no fourth empty one, the recorded front tab in
   front.
4. `beside` — Enter on the 2-tab window with one tab already open that has
   had a prompt: the two added at the end of the strip, the first tab
   untouched.
5. `open-marks` — `/resume` again after 3: the window reads `all open`, its
   sessions `open in n`; Enter goes to the front tab and opens nothing.
6. `cap` — seven open, Enter on the 3-tab window: the status line message,
   still seven tabs, no agent started (check with `ps`).
7. `elsewhere` — Enter on the two-directory window from `/resume`: the
   refusal with `chord --resume w-…` on its own line.
8. `start` and `start-empty` — `chord --resume` with no id, before a choice,
   with no agent process running (`ps`). Then Enter on a window opens it,
   and, in a second run, Esc returns the shell with the cursor visible and
   nothing printed.

Tests: the row text (agents in order, folded to counts, cut at `, ` with
`+n`; ` +n` directories), the merged order by time, the scope rule (every tab
here), and the cap arithmetic (reused empty tab, already-open tabs), all pure.
None of them needs Ink or a real agent.
