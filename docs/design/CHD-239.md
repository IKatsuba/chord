# CHD-239: Agent names after the message arrows read as @name

CHD-225 put `←` and `→` in front of every message between agents, and CHD-230
built it. The name after the arrow is bare today: `← parser · codex`,
`→ main`. The owner settled that an agent's name there reads `@name`: arrow,
one space, `@`, the name, nothing between `@` and the name. The `@` is drawn
in the name's colour and weight, so `@parser` is one bold blue word. The
layout and the arrow colours stay as CHD-225 and CHD-230 set them.

This document settles the rest: which names take the `@`.

## The rule

**`@` marks a name a message can be sent to.** In chord those are the
long-lived agents (`open_agent`, which `send_message` reaches by name) and
`main`, which a child's `send_message` reaches. Nothing else takes it.

- **A task's rows stay bare.** A task agent (`spawn_task`) is named by its
  title or its prompt's first line, `Fix the tokenizer`, and `send_message`
  cannot reach it. `@Fix the tokenizer` would read as a handle called `Fix`
  followed by two loose words. This covers its report, its failed report and
  any message it sends before the report: `← Fix the tokenizer · codex`,
  `← … · report`, `← … · failed`.
- **`← chord` stays bare and dim.** chord is the client, not an agent, and no
  agent can send chord a message. An `@` there would promise one.
- **The agent list's hint follows:** `← message from @main`. It is an arrow
  row naming an agent, the same as the transcript's, and the hint and the
  transcript row it points to should read alike.
- **The agent list's name column does not.** It has no arrow, every row in it
  is an agent already, and an `@` on each row would repeat one character down
  the column and shift it a cell for nothing. The prompt box's title
  (`╭─ parser ─`) and the child view's header (`opened by main`) are not
  message rows either, and stay bare.

So the only test for whether a row changes is: is it an arrow row, and is the
name after the arrow one `send_message` could take? `@` in the prompt stays
the file finder; this changes only what chord draws.

## Every affected row

| Row | Today | With this |
| --- | --- | --- |
| A message from a long-lived child (in) | `← parser · codex` | `← @parser · codex` |
| A message sent to it (out) | `→ parser`, `→ parser · queued` | `→ @parser`, `→ @parser · queued` |
| A queued message from a child (in, above the box) | `← docs · claude: …` | `← @docs · claude: …` |
| The child view, from main (in) | `← main` | `← @main` |
| The child view, to main (out) | `→ main` | `→ @main` |
| A task's message to main, in its `⎿` list | `→ main · queued` | `→ @main · queued` |
| The agent list's hint | `← message from main` | `← message from @main` |
| A task's message, report or failed report | `← Fix the tokenizer · codex · report` | unchanged |
| chord's own message | `← chord` | unchanged |
| The list's name column, the box title, the child header | `parser`, `╭─ parser ─` | unchanged |

Colour: the `@` is part of the name's run, so it takes exactly what the name
takes today. `@parser` in parser's colour, bold; `@main` uncoloured, bold, as
`main` is; the out arrow's dim while delivering and red when refused stay on
the arrow alone, as CHD-230 has them. In the list's hint the whole hint is dim
today, and `@main` stays dim with it.

## States

- **Delivering, refused:** `→ @parser · queued` with the arrow dim, then plain;
  refused, the arrow red. The `@parser` keeps parser's colour throughout, as
  the name does today.
- **Narrow:** nothing new folds. A name is never split from its `@`; at 80
  columns the longest arrow row is the queued one, cut as above.
- **Light terminal, `NO_COLOR`:** the `@` carries no colour of its own, so
  both read as today plus one character.

## Why not the other way

- `@` on every name, tasks and chord included, would be one rule with no
  test, but it would put `@` on names nobody can write to, which is the one
  thing an `@` says.
- `@` in the list's name column would make the list read like a list of
  mentions rather than the agents themselves, and the list already says every
  row is an agent.
