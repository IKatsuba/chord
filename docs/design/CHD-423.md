# CHD-423: a message held behind running tool calls waits in the queue

Since CHD-417, a message to a Claude session whose turn has tool calls
running is held until those calls end, then steered into the turn. While it
is held, the recipient's view shows nothing: the queue above the prompt is
empty and the message appears as `← from @main` only once the agent takes
it (`evidence/CHD-423/today/`, taken with the fake agent's `agents`
scenario under `CHORD_FAKE_STEERING=claude CHORD_FAKE_STEP_MS=40`. parser's
Bash call runs about seven seconds while main messages it.)

The owner decided (2026-10-17) that a held message waits in the queue under
the working line from the moment it is held until it goes in. Then it leaves
the queue as a steered message does today. This is the recipient's view only:
the sender's `→ to @parser` row is unchanged.

## The row

The queue's message row as it is (`queuedMessage`,
`src/ui/transcript/message.ts`), with a note of its own after the header,
the way a message held for the person's answer has one:

```
 ← from @main · after your answer: When the README secti...to docs/FEATURES.md.
 ← from @main · after the running calls: I changed how a s... only what fails.
```

**`· after the running calls`** says why it waits and what ends the wait,
in words the screen already shows: the calls above it say `Running…`. It
is the same shape as `· after your answer`, a few cells longer. The
alternatives read worse: `after this step` names nothing on screen, and
`after its tool calls` reads as if `its` were `@main`'s.

Everything else is the existing row: `←` and the header dim and drawn
whole, the message's first line after `: `, `…` where it has more lines,
and the text alone cut to the width. That cut is the queue's own
(CHD-361), not changed here.

## Where it sits

In arrival order among the other rows, as every row in the queue already
is. A held message is held by one thing at a time: if a permission or a
question is open when it comes, it is held for the answer and says `·
after your answer`; otherwise, with calls running, it says `· after the
running calls`. It never carries both notes. Past the queue's row limit
the newest fold into `… +N more`, as today.

When the calls end, the message goes into the turn: its row leaves the
queue in the same frame its `← from @main` entry is drawn in the
transcript, as a steered message's does now.

## The agents list

A queued message from another agent already marks its recipient's row,
when that tab is not in front, with `← message from @main` (dim). A held
message is a queued message and marks the row the same way, from the moment
it is held. In front, the queue row is enough, and the list row keeps
`✻ working`, as for any queued message.

## Mocks, 120×40 and 80×24

`evidence/CHD-423/mock/held-120x40.txt` and `held-80x24.txt`: parser's view
while both of main's messages are held behind its running Bash call.

```
 ⏺ Bash(deno task test tests/parse)
   ⎿  Running…

 ››› Working… (3s · esc to interrupt)
 ← from @main · after the running calls: I changed how a string at the end of ...ests now and tell me only what fails.
 ← from @main · after the running calls: The printer is fixed too; run the whole parser suite once more.
```

At 80 columns the header, `from @main · after the running calls: `, takes
40 cells and stays whole. The text gets the rest, about 35 cells, cut in
its middle as the queue cuts any row:

```
 ››› Working… (4s · esc to interrupt)
 ← from @main · after the running calls: I changed how a s... only what fails.
 ← from @main · after the running calls: The printer is fi... suite once more.
```

With the longest member name (16) and a runtime, the header is about 55
cells, which still leaves the text a share at 80. Under about 60 columns
the header itself is cut at its end, as CHD-385 settled for the `after
your answer` row.

## Colour and keys

The row is dim from end to end, as every queue row is. No new action and no
new key. Esc interrupting the turn treats a held message as it treats any
queued message from an agent: it never goes back into the person's draft.
