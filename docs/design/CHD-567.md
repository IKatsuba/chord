# CHD-567: a bad item in a settings list costs only itself

The owner's answers: Q346 option 2 (2026-11-09) and B1. Only the words of the
problem lines are new on screen; where they show, and how, is unchanged.

## What it covers

The three lists of names in `teamSelection.constraints` (`src/session/budgets.ts:18`):

- `teamSelection.constraints.agents`
- `teamSelection.constraints.models.<agent>`
- `teamSelection.constraints.modes.<agent>`

An item is bad when it is not a string, is empty, or is longer than 128

## The line

```text
"<list>": item <n> (<value>), <cause>, left out
```

| Part | Decision | Why |
| --- | --- | --- |
| `<list>` | The list's key, quoted, as every settings line opens: `"teamSelection.constraints.agents"`, `"teamSelection.constraints.models.claude"` | The person looks for the list in the file; `….agents.0` reads as a key named `0` |
| `<n>` | The position, **1-based**: `item 1` is the first | A person counts from one; the line is for the person, not a path into Zod |
| `<value>` | The item as JSON (`1`, `""`, `null`, `{"a":1}`, `"x"`), cut to its first 40 characters with `…` when longer | With the position it finds the item in a long list; the 129-character name that `too big` is about would otherwise flood the line |
| `<cause>` | Zod's issue message, lower-cased, as the other validation lines have it: `invalid input: expected string, received number`, `too small: expected string to have >=1 characters` | Same source, same voice as `"theme": invalid option: …`; no words of ours over the library's |
| ending | `, left out` | `ignored` already means a whole key costs itself; `left out` is what `offeredAgents` says of a name taken out of a list (`"offeredAgents": no agent named cdex, left out`) |

**Several bad items: one line each,** in the list's order. Each line names the
list and its item, which is the owner's "one problem line naming the list and the
item"; their causes differ, and one line holding several would be long and
unreadable at 80 columns. The flood today was the same item eight times, not one
line per real item.

**A list every item of which was left out stays `[]`** (B1: an explicit empty
allowlist denies everything), and gets one more line, after its items' lines:

```text
"teamSelection.constraints.agents": no item left; the list now allows no agent
"teamSelection.constraints.models.claude": no item left; the list now allows no model for claude
"teamSelection.constraints.modes.claude": no item left; the list now allows no mode for claude
```

It is its own line because it is about the list, not an item, and it is the one
consequence a person would not guess: the list is narrower than nothing written.
