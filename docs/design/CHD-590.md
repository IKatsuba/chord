# CHD-590: the line for a task an agent closed

`close_agent` lets an agent stop a task it started itself. The lead's settled
choices: for an agent's close the parent gets no ahead note (the tool's answer
tells the caller), and the transcript line names who stopped it. Over ACP,
`_chord/agents/close` is the client acting for the person without a key. Only
the end of the task's line is new on screen; its marker, tone, place and the
rest of the line are unchanged.

## Today

The line is worded in `src/ui/transcript/ended.ts` (`case 'stopped'`), from the
key the task recorded in `cancel(by)` (`src/session/tasks.ts`):

```text
■ fix-tests · task · stopped with x after 2m
■ fix-tests · task · stopped with esc after 2m
■ fix-tests · task · stopped after 2m
```

The first is the background view's `x` (`src/ui/app/sessions.ts:611`,
`cancel('x')`), the second the parent's Esc, the third a cancel with no key.
Each sends the parent `The person stopped this task before it reported.`

## The lines

| Who stopped it | The line's end | Ahead note to the parent |
| --- | --- | --- |
| the person, `x` | `stopped with x after 2m` (unchanged) | kept |
| the person, Esc | `stopped with esc after 2m` (unchanged) | kept |
| an agent's `close_agent` | `stopped by <caller> after 2m` | none |
| `_chord/agents/close` over ACP | `stopped after 2m` | kept |

`<caller>` is the name the caller has everywhere else in chord, the one
`send_message` and the agents list use, as written, never truncated:

```text
■ fix-tests · task · stopped by main after 2m        main's own close
■ fix-tests · task · stopped by ship after 2m        a team's lead
■ fix-tests · task · stopped by developer after 2m   a member
■ fix-tests · task · stopped by review-pr after 2m   a child agent or task
```

At 80x24 the line is laid out as a long task name is today: nothing is cut
from `stopped by <caller>`; an error reason after it, if any, is what gets
truncated.

The ACP line is confirmed: a bare `stopped`, as a cancel with no key already
reads. It names no client, since chord does not know the client's name as the
person knows it, and the ahead note stays because it is the person who stopped
the task through it.

## Rules

- **The first stop counts.** A task already being stopped keeps the first
  stopper's words: `x` then an agent's close reads `stopped with x`; a close
  then `x` reads `stopped by <caller>`. This is how `cancel` keeps its first
  key today.
- **`by`, not `with`.** `with` names a key the person pressed; `by` names an
  agent. A reader tells the two apart at a glance without a new marker or
  colour.
- **Tone stays `dim`, marker stays `■`.** Stopping a task is not an error,
  whoever does it.
- **No new key.** The person's `x` is unchanged; an agent's close has no key.
  The shortcuts panel does not change.

## Why

The person reading the parent's transcript should know a task ended because
an agent chose to end it, not because they pressed something, and which agent.
The caller already knows from the tool's answer, so a note to the parent would
say it twice.
