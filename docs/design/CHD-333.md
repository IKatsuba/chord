# CHD-333: a proposal's table, opened, shows every agent whole

The owner's rule (CHD-332): reviewing a proposal, the person sees everything
that will be written to the team file. Opened (ctrl+o), that covers every cell
of the table: name, agent and model, mode, role.

## What 94706480 draws, and why it is not enough

The role wraps in its own column. That works for a new proposal at 80 columns,
where the role gets 24 cells (`evidence/CHD-333/proposal-opened-80x24.txt`).
For a change it falls apart (`evidence/CHD-333/change-opened-80-wide.txt`):

```
         lead      claude ·…  default                            Splits the
                                                                 job, says
                                                                 who edits
                                                                 which
                                                                 files,
                                                                 reports to
                                                                 main
      ~  tester    claude ·…  acceptEdits was bypassPermissions  Writes the
                                                                 failing
```

- The model is cut, `claude ·…` and `codex · …`, in the opened view, so the
  owner's rule now fails on another cell. Which model a member runs is the
  thing a person most needs to see.
- The role is 10 cells wide and runs 4 to 7 lines a row, one or two words a
  line, under a column of blank space. It reads as a column of words, not a
  sentence.
- Each row is 5 to 7 lines tall, so at 80x24, where the save box leaves about
  7 lines of transcript, one screen shows one member.

At 120x40 the same change reads well (`evidence/CHD-333/change-opened-120x40.txt`);
the trouble is only that the last column is the one that pays for every other
column's width.

## The shape: opened, the role goes on its own line under its row

Opened, each member is two rows: the first has the change mark, name, agent ·
model and mode, all whole; the second has the role, starting under the agent
column and spanning to the right edge, wrapping there.

80 columns, a change:

```
 ⏺ Team(bugfix) · change
   ⎿  Fixes a bug end to end: a failing test first, then the fix, then a
      review of the diff.

         lead      claude · opus          default
                   Splits the job, says who edits which files, reports to
                   main
      ~  tester    claude · sonnet        acceptEdits was bypassPermissions
                   Writes the failing test, then proves the fix
         coder     codex · gpt-5.3-codex  auto
                   Writes the fix, in the files the lead names
      ~  reviewer  claude · opus          plan was read-only
                   Reads the diff and edits nothing

      lead's instructions
```

80 columns, a new proposal:

```
      lead      claude · opus          default
                Splits the job, says who edits which files, reports to main
      tester    claude · sonnet        acceptEdits
                Writes the failing test, then proves the fix
      coder     codex · gpt-5.3-codex  auto
                Writes the fix, in the files the lead names
      reviewer  claude · opus          plan
                Reads the diff and edits nothing
```

- The role is dim, as it is now, so the eye still runs down the names; the
  mode keeps its warning colour and the `was …` its own, on the first row.
- The change mark `~`, `+`, `-` stays on the first row only.
- At 200 columns it is the same shape; no width switch, so the layout never
  jumps when the terminal is resized with the proposal open.
- `/team show <name>` opened is the same table and takes the same shape.

### Folded stays as it is

One line a member, the role cut with `…`, so the table and the save box fit
at 80x24. Folding is the summary; opening is the whole.

### Keys

Nothing new: ctrl+o opens and folds, as today.

## Library first

@cliffy/table does this as it is: a second row per member whose role cell is
`new Cell(role).colSpan(n)` under two empty cells, with the existing
`maxColWidth` on the spanned width. Tried under bun in the repository:

```
~  tester  claude · sonnet  acceptEdits was bypassPermissions
           Writes the failing test, then proves the fix
   lead    claude · opus    default
           Splits the job, says who edits which files,
           reports to main
```

Nothing is written around the table that is not written now: a member's first
row is still the one with its name.

## When a row does not fit: the mode wraps first, the model last

f326bd73 keeps a long model whole by wrapping it inside its column. At 80
columns, in a change that holds `claude-sonnet-4-5-20250929` and a long
changed mode, this splits the id inside a word (`claude-sonnet-4-` /
`5-20250929`). It also wraps `codex · gpt-5.3-codex` for a member whose own row
would fit, because one wide mode narrows the agent column for every row. The
model's second line sits in the same column as the role under it, so on a
plain screen it reads as the start of the role
(`evidence/CHD-333/change-long-model-opened-80x24-a.txt`, `-b.txt`):

```
         coder            codex ·           auto
                          gpt-5.3-codex
                          Writes the fix, in the files the lead names
      -  security-review  claude ·          bypassPermissions
                          claude-sonnet-4-
                          5-20250929
```

Where the first row does not fit, the cells give way in this order:

1. **The mode cell first, at its spaces.** `bypassPermissions was acceptEdits`
   goes to two lines, with `was acceptEdits` under the new mode. The mode
   itself is one word and stays on the first line in its warning colour. The
   `was …` keeps its dim colour on the line it lands on.
2. **Then agent · model, at its spaces only.** `claude ·` on one line and the
   model id whole on the next. This is the same for every row, because the
   column narrows for all of them.
3. **Only when both are down to their longest word** may @cliffy/table break
   inside a word. That happens under about 50 columns. It is a last resort,
   and it is still better than cutting.

The role row is unchanged: it starts under the agent column and runs to the
right edge.

The same change, 80 columns (content width 74):

```
         lead             claude · opus                        default
                          Splits the job, says who edits which files, reports to
                          main
      ~  tester           claude · sonnet                      bypassPermissions
                                                               was acceptEdits
                          Writes the failing test, then proves the fix
         coder            codex · gpt-5.3-codex                auto
                          Writes the fix, in the files the lead names
      +  reviewer         codex · gpt-5.3-codex                read-only
                          Reads the diff and edits nothing
      -  security-review  claude · claude-sonnet-4-5-20250929  bypassPermissions
                          Reviews the diff for security problems and edits nothing
```

Content width 60, where step 2 is needed:

```
      -  security-review  claude ·                    bypassPermissions
                          claude-sonnet-4-5-20250929
                          Reviews the diff for security problems and
                          edits nothing
```

Every model and mode on screen is whole and unbroken. A row that fits is drawn
exactly as before. The fake agent's own change at 80x24 has no long model, so
it keeps its one-line `bypassPermissions was acceptEdits`.

Library first: @cliffy/table does this as it is. The widths are
`minColWidth`/`maxColWidth` per column, as now. The mode column gets what the
row leaves, but never less than its longest word. The agent column gets the
same treatment after it. Cliffy wraps both at spaces. Nothing is rewritten
before the cells, and both outputs above come from that trial under bun in the
repository.
