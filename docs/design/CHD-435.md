# CHD-435 — a start that needs a sign-in says how to sign in

chord does not sign agents in: it never calls ACP's `authenticate` (owner,
2026-10-18). An agent that is not signed in fails its start. It answers
`authRequired` (-32000) to `session/new`, `session/load` or
`session/resume`, or, for droid, fails "Sign-in was cancelled" after chord
cancels its sign-in elicitation. Today that shows as the bare start
failure:

```
 ⏺ kimi did not start: The agent exited: Authentication required
```

(`evidence/CHD-435/before-120.png` and `before-80.png`, drawn on a stand-in
agent command that prints that and exits.)

The words, settled in Q166, are the agent's own:

- its error message;
- the `name` and `description` of each `authMethods` entry it sent in
  `initialize`;
- one fixed line from chord.

chord keeps no table per agent.

## The row

The failure row stays where it is, under the header, with `⏺` and the
headline in `error`, exactly as today: `<agent> did not start: <the agent's
message>`. Under it, a result block hangs from `⎿`, as a tool's result
does:

1. When the agent sent any `authMethods`, one line says `<agent> offers this
   sign-in:` (or `these sign-ins:` for two or more). Each method follows on a
   line of its own, indented 2 under the text, in the order sent: its
   `name` in bold, then ` · ` and its `description` when there is one. A
   description that wraps hangs under the name.
2. Always, the fixed line: `chord does not sign agents in. Sign in with
   <agent>'s own CLI in a terminal, or set its API key where it offers
   one.`

`<agent>` is the name the headline already uses (`shownAgent`). The block's
text is in the terminal's own foreground. The method names are bold, and
nothing else is styled. The agent's words go through `Ansi` as they are,
backticks included: they are not markdown. The `⎿` is dim, as a result's
is. Every line wraps at the room it has (`wrapMode: 'word'`) and hangs
under its own text.

A method whose `name` and `description` are both empty is left out. If
nothing is left, line 1 goes too.

  Names only: `chord: droid offers: device-pairing, factory-api-key`. With

- **A child opened with `open_agent`,** in its parent's note. The fixed
  line is turned around for an agent reader, who is not the one to sign in:

  ```

  ```

## States

- **Sign-in failure:** the block above. Only an `authRequired` error, or
  droid's cancelled sign-in, gets the block. Any other start failure keeps
  today's single row.
- **A resumed or continued session** fails the same way on `session/load`
  or `session/resume`, and gets the same row.
- **Narrow:** at 80 columns the lines wrap and hang under their text, as
  above. A long agent message (auggie's) takes two or three rows in the
  headline, and the block follows it.
- **Streaming, waiting on the person:** none. The start has failed, and
  the prompt stays, as today.
- **The agents list** keeps `✗ failed to start`, unchanged.

## Keys

No new key and no new action. After the failure the window is today's: the
prompt is there, and ctrl+c quits as it does now. The way on is outside
chord (sign in, then start chord again), so there is nothing to bind. The
shortcuts panel is unchanged.

## Why

- The agent knows how it is signed in to; chord does not, and keeps no
  table that would go stale (Q166).
- The headline keeps today's shape, so a person who knows the old row reads
  the new one at once. (The before capture's "The agent exited:" comes from
  its stand-in agent exiting. An `authRequired` error carries the agent's
  message alone.)
- `⎿` is how chord already hangs what follows from a row, so the block
  reads as the failure's detail, not as a second message.
- The fixed line comes last: it is the way on, and it is the line a person
  acts on.
