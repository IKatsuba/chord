# CHD-485: riff, chord's own agent, on libfx

riff is an agent of chord's own beside the ACP agents chord runs: a person
with a ChatGPT or Grok plan and nothing else installed signs in once and
works in chord. It is built on libfx (npm `libfx`, Apache-2.0,
vercel-labs/fx), the fx engine as a JavaScript library with a native addon
and a WebAssembly fallback. libfx runs the model loop, streaming, retries,
steering and journals; chord gives it the model, the credentials, the
instructions and every tool.

Every choice below that is the owner's was answered on CHD-485 between
2026-11-08 and 2026-11-09; `docs/decisions.md` has one entry per decision.
The evidence is in `docs/design/evidence/CHD-485/`: `gate.md` (libfx under
`bun build --compile`), `search.md` (the search and list library),
`commands.md` (which shell commands auto admits), and the architects'
drafts in `drafts/` (`brief.md`, `protocol.md`, `interface.md`,
`runtime.md`, `auto.md`). Where this file and a draft differ, this file
holds; the drafts are the record of how it was reached.

## Two rules over everything

- **One approach for every agent** (the owner's rule). Where chord already
  treats agents one way, riff follows it: its traffic runs through the
  enricher chain like any agent's, its tool calls are drawn by the existing
  renderer, its cost is chord's estimate as for every agent that gives
  none, its context gauge is the standard `usage_update`. Only what has no
  precedent is riff's own: sign-in, the credential store, the tools, the
  permission modes and the auto review.
- **Libraries as they are.** libfx, fff, unbash and the MCP SDK are used
  through their documented surface. The two reaches the owner allowed are
  named where they are used: the libfx assets imported by their path inside
  `node_modules`, and the Grok token revocation chord calls itself.

## The parts

```text
chord (window)                               chord --riff-agent (one per riff session)
├── OpenTUI, sessions, chord's MCP server    ├── the riff adapter: an ACP agent (SDK agent side)
├── the sign-in box and its driver           ├── libfx: engine (native, Wasm fallback), local() store
├── Bun.secrets store (window side)  ── ACP ─┤ ├── the review engine (auto)
└── spawnAgent → stdio ─────────────────────►├── host tools: read, list, search, edit, write, shell, skill
                                             ├── fff in a Worker (search, list)
                                             └── MCP clients (settings' servers, chord's own)
```

- **A child process on a hidden flag** (owner, Q1 B). chord starts itself
  as riff the way it starts its resource worker (`execPath()`, plus
  `main.tsx` from source; the binary alone compiled), with a hidden flag
  (`--riff-agent`), and opens it with `openAgent` like `fx acp`. Spawn,
  stop bounds, SIGKILL, stderr and "agent gone" are the existing ones. A
  fault in libfx's native core costs that session, not the window. One
  riff session per process, so one libfx agent name, `riff`.
- **The adapter** turns libfx into an ACP agent on the SDK's agent side
  (`connectAgentApp`), written over a `Stream` and tested over an in-memory
  pair. Everything above `connectAgent` stays as it is: enrichers, record,
  reducer, permissions, cancel, `-p`, `chord acp`.
- **riff in the agent list.** `riff` is a `ListedAgent` with `from:
  'builtin'` (a new value beside `npx`, `uvx`, `cli`, `settings`);
  `chord agents` writes it as `built in`. `claude` stays the default
  (owner, Q5); riff is the picker's first row. `chord riff` starts it.
  Settings take `agents.riff` as any agent's (model, effort, mode).

### Sign-in: where it lives

The window signs riff in (owner, S1), in a box of chord's own over the
prompt, framed as the permission prompt and the pickers are. The child only
reads the stored credential and writes refreshed ones back. Without one,
the child answers `session/new` and `session/resume` with `-32000`
(`authRequired`) and its two auth methods, `chatgpt` and `grok`; for riff
alone the window opens the box instead of CHD-435's words. CHD-435 stays as
it is for every other agent. `-p` and `chord acp` print the existing
sign-in failure with `run chord riff to sign in`.

Its life:

1. `chord riff`, or riff picked, with no credential: the window opens as
   for any agent, the header says `riff · not signed in`, a row says why,
   and the box opens on the provider step. The session is not started; the
   prompt has no keys while the box does.
2. Provider → way → waiting (browser or code) → success, failure, expired
   or cancelled.
3. Success: the box closes, a row says how it went and where the
   credential is kept, and the session starts. The header's second line
   becomes `riff · ChatGPT · <model>`.
4. Esc on the first step, or from a later one back to it: the attempt
   ends, the loopback listener closes, polling stops, and the row says
   `Not signed in. /login to sign in, or /new for another agent.` The
   prompt answers chord's own commands only; a typed prompt gets the status
   note `riff is not signed in: /login`.
5. `/login` opens the box again at any time; `/logout` signs out.

### Signing out and switching

- **`/logout`** (riff only; with another agent it is not on the list): a
  confirm box, then the credential is deleted under the lock, the window's
  own riff turns and its children's are cancelled at once, and the session
  ends with the signed-out line (owner, L2). For Grok, chord then revokes
  the refresh token at xAI's revocation endpoint (owner); for ChatGPT
  nothing is revoked (libfx and fx have no revocation for it) and the box
  says so. Other windows find out at their next prompt, which fails
  `authRequired` and opens the sign-in box.
- **`/login`**: the box of A, the signed-in provider marked `✔`. Picking it
  again signs in to another account (one account per provider; the new one
  replaces the old); picking the other provider signs in to it. Success
  starts a new session in place, as `/clear` does; the transcript stays
  above under a row naming the plan. The other provider's credential is
  kept until `/logout`. A new riff session runs on the provider last
  signed in to, kept in chord's state directory.

### Permission prompts

Two modes (owner): **ask** and **auto**, toggled by shift+tab, kept per
session, auto by default. No full-access mode.

`Allow … for this session`, `Deny` (Esc). "For this session" covers the
real path for edit and write, and the exact command string for shell;
never a command's first word or prefix. Grants live in the session's
memory and still hold after a switch to auto.

## Credentials

- **The store** is Bun.secrets (owner), in `src/platform/secrets.ts`, one
  service and one entry per provider holding libfx's credential JSON (one
  account per provider). Every call goes through one serial queue per
  process, each bounded at 20 s (owner). A timeout bounds the caller only:
  the queue stays serial; a read past its bound is dropped, a write or
  delete stays queued in order and reports late. (Seen on one macOS
  machine: 20 concurrent calls wedged every later Bun.secrets call in that
  process; Linux and a locked keychain are not verified.)
- **No store** (Secret Service missing, or the first call fails): riff does
  not start; G above.
- **The window** signs in and writes the entry under the provider's
  cross-process lock (`proper-lockfile`, in chord's state directory; an
  in-process mutex beside it, as the file lock is not reentrant).
- **The child** reads the store at `session/new`. libfx calls
  `credentials()` inside `refreshLock`; under the lock chord reads the store
  itself, never a cached copy, so a rotation another process saved is seen.
  `onCredentials(next)` writes by compare-and-set against what this process
  last read: it writes only if the store still holds that value; already
  saved is a no-op; absent or another account's chain is refused and the
  process's credential is signed out. A write failure keeps the rotation in
  memory, retries it at the next lock, and sends the window
  `_chord/credentials {provider, state}` (`unsaved`, `saved`,
  `signed_out`, `account_changed`); a missed notice still ends in
  `authRequired` at the next prompt. (Trial T8: two independent processes
  refreshing one rotating token; the naive cache spent a rotated token
  eight times, compare-and-set ended both turns cleanly.)
- **At each prompt** the child reads the store once (queued, outside the
  lock); absent or another account fails the prompt `authRequired`
  (owner, L2).
- **Logout** takes the lock, deletes, releases; a later compare-and-set
  write from any process is refused, so no stale rotation brings a
  sign-in back. Grok: after the delete, chord posts the refresh token to
  `https://auth.x.ai/oauth2/revoke` as fx does (fx
  `src/core/auth/grok_oauth.zig:24`, logout `:435`; owner's consent to this
  code beside libfx) and reports the outcome.

## Sign-in, underneath

- All four flows are libfx's (`libfx/chatgpt`, `libfx/grok`: browser and
  device code). chord adds the listener, timers and cancellation.
- **The loopback listener** opens after `startSignIn()` returns and before
  the address is shown; it closes on the callback's finish, Esc, the
  10-minute deadline or leaving. ChatGPT: port 1455, `/auth/callback`. Grok:
  the port and path of libfx's `redirectUri`. Bind order: `127.0.0.1`,
  then `[::1]`; `EADDRINUSE` on either is "port taken" (another listener on
  either family can receive the browser); on a `::1` failure the v4
  listener is stopped first; no IPv6 loopback keeps v4 alone; never
  `hostname: 'localhost'`. Grok's random port taken: both listeners closed
  and `startSignIn()` called again, up to three times. Only `GET` on the
  callback path is answered; anything else is 404 and the wait goes on.
- **Device code**: `startDeviceSignIn`, then `completeDeviceSignIn` with
  the attempt's signal; libfx polls and throws on expiry.
- **One state machine**, pure, in `src/riff/sign_in.ts`, driven by
  `src/riff/sign_in_run.ts`; each attempt has an id and the window drops a
  state from any attempt but the current one, after the driver aborts it.

## Tools

libfx turns on none of fx's tools (with host tools given, the core's only
own tool is the provider-run `web_search`), so all are chord's, in the
child (owner: all six, plus skills):

| Tool | Library | `idempotent` | `writes` | ACP kind |
| --- | --- | --- | --- | --- |
| `read` (a file, a range) | `node:fs`; `file-type` refuses binaries | true | false | `read` |
| `list` | fff (`glob`, `directorySearch`) in the Worker | true | false | `search` |
| `search` | fff (`grep`) in the Worker | true | false | `search` |
| `edit` (replace a unique string) | `node:fs`, `diff` for the diff | false | true | `edit` |
| `write` (whole file) | `node:fs`, `diff` | false | true | `edit` |
| `shell` | chord's `src/shell.ts` `runShell` | false | true | `execute` |
| `skill` (load a skill by name) | chord's own, on fx's model | true | false | `read` |

- **fff** (`@ff-labs/fff-bun`, exact pin, owner): its `grep()` is a
  synchronous FFI call, so it runs in a Bun `Worker` whose loader is in
  `src/platform/`; one finder per session's directory, destroyed with the
  session. Search and list work **inside the session's directory only**,
  on fff's own semantics (owner): `list` is "files under the session
  directory matching fff's pattern" with directories from
  `directorySearch`; `*` crosses `/`; results in fff's order, paginated;
  its regex lets `\s` cross lines; it drops tracked-but-ignored files and
  symlinks and ignores `.git/info/exclude`, and outside a git repository
  hides dotfiles and `node_modules`. The tools' descriptions say all of
  that to the model. chord does not filter fff's output. An outside path is
  reached only by `read`, under a grant.
- **Paths** are resolved with `realpath` at the effect, not at the ask: a
  symlink inside the project pointing outside is outside. Open the real
  path, `fstat` the handle and compare `dev`/`ino` with a `stat` of it; on a
  mismatch, refuse. A parent-directory swap between `realpath` and `open`
  is acknowledged, not closed.
- **An approved edit whose file changed** while the prompt waited: `edit`
  and `write` record the file's SHA-256 (or its absence) when they build
  the diff, re-read at the effect, and refuse with "the file changed since
  this edit was proposed; read it again" if it differs.
- Every tool takes the call's `signal`; libfx abandons a tool that ignores
  it, so all of chord's honour it. `shell` stops its process group on
  abort.
- On native, idempotent calls of one response run up to 16 at once; a
  write or a shell runs alone; on Wasm, one after another.

## The auto review

libfx exposes no mode, reviewer or permission API, so the review is
chord's own call to the plan's model through libfx, modelled on fx v0.0.16
(`src/core/permissions/auto_classifier.zig`, policy text and schema
Apache-2.0, attributed):

- **Reviewer** (owner): `gpt-6-luna` on a ChatGPT plan, `grok-4.5` on a Grok
  plan, with the person's own credential. A second `createFxEngine` per
  session, made at the first review: same provider and credential callbacks
  (so refreshes still go through the one lock), the reviewer model, memory
  persistence, no MCP, one host tool `permission_decision` (`decision` ∈
  {`clear`, `caution`}, optional `rationale` ≤ 240 bytes). Each review is a
  new conversation on it; the tool's `execute` records the decision and
  cancels the turn. Each review is one plan request.
- **Policy** (owner, A1 b): fx's policy, which cautions on concrete prompt
  injection or malicious activity, plus a caution on destructive or
  irreversible actions, such as `rm -rf`, a force push or publishing.
- **What it sees** (owner, A2): fx's shape and caps: the normalized pending
  action (command with cwd; a file mutation with path, pre-image, counts
  and diff; a tool's arguments), each field ≤ 64 KiB; the person's
  requests (1 KiB, for shell, outside reads, MCP tools); this turn's prior
  tool results, newest first, at most 16, 1 KiB each, 8 KiB in all, marked
  untrusted; the current git branch; never the assistant's prose. A field
  cut by a cap sends no review: the outcome is "incomplete".
- **Timing** (fx's): 30 s per attempt; a throw, timeout or transient
  failure retries once; a malformed reply retries once; a permanent
  failure does not retry; a caution is never retried into approval.
- **Outcomes** (owner, A3, A4): clear runs the call; caution, incomplete or
  failed asks the person in the window with the rationale or the reason,
  allow once or deny, timing out after 5 minutes into a denial the model is
  told of; in `-p` and `chord acp` they deny. One review per exact call
  and at most 64 per turn; past that, the person is asked (denied in `-p`
  and `chord acp`).
- **The reviewer model not served** (owner, A5): libfx cannot tell ahead of
  time and matching an error's text would be guessing, so any permanent
  review failure moves the session from auto to ask, with a notice naming
  the model.
- **What auto admits without review** (owner, A6 b): reads, lists and
  searches inside the session's directory; edits and writes inside it on
  non-sensitive paths (not `.git/`, `.env*`, key files); calls matching a
  grant; and the shell commands fx admits, by chord's port of fx's
  classification over `unbash` (below). Reviewed: reads outside, edits
  outside or on sensitive paths, every MCP tool, every other shell command,
  and anything that does not parse.
- **The shell commands admitted** (owner, both of fx's lists as fx has
  them): fx's direct read-only set (`printf`, `pwd`, `ls`; `wc`, `cat`,
  `head`, `tail`, `grep` filtering a pipe; `git status`, `diff`, `log` with
  fx's listed flags; at most 8 pipe stages; no unquoted `$ * ? ~ ; ( ) { }`,
  no `>`, `&`, `||`, here-documents or assignments), and fx's known
  reversible list (`node -v`, `which`, `git status`, `git remote -v`, `git
  worktree list`, `git fetch` with fx's listed options, `npm`, `bun`,
  `pnpm`, `yarn` `install`, `ci`, `test`, `run <script>` without the global
  flags, `zig build`). The second list is reversible, not read-only:
  installs reach the network and run lifecycle scripts, `test` and `run`
  run the project's scripts, `zig build` runs `build.zig`, `git fetch`
  writes refs. `unbash` 6.0.4 (ISC, pure TypeScript) parses the command;
  chord's port of fx v0.0.16's `src/core/shell_command/command_effect.zig`
  rules (Apache-2.0, attributed) decides. It passed 218 of 218 cases (29
  bypasses from fx's CHANGELOG, fx's own tests, 70 ordinary commands) from
  source and compiled on all four targets. `shell-quote` is not used for
  this: it reads `2>&1`, `\2>&1`, `2 >&1` and `'2'>&1` alike.
- **How an admitted command runs** (owner): the direct read-only set runs
  without a shell, through chord's port of fx's direct executor (each pipe
  stage's argv from fixed executables, `PATH=/usr/bin:/bin`, the C locale,
  its own process group, piped, output capped at 64 KiB) and of `safe_git`
  (a trusted git path, a version check, `-c` overrides, filter names read
  from the repository's config, a same-repository check), Apache-2.0,
  attributed. So an alias, a function, a shell option, a `PATH` entry or a
  repository's `core.fsmonitor` cannot change what was classified. The
  reversible list runs through `$SHELL -c`, as in fx.
- **shift+tab** (owner, A7): the agent's `mode` option has `ask` and `auto`;
  shift+tab toggles them through the existing mode cycle; the choice is
  kept in the session's sidecar; the default is `auto`.

## MCP, chord's own tools, skills and instructions

- **MCP servers** from settings and `.mcp.json` (owner): `serversFor` gives
  riff the session's servers like any agent. Each goes through an
  `@modelcontextprotocol/sdk` client of chord's (stdio, streamable HTTP or
  SSE) and `libfx/mcp`'s `createMcpAdapter`. chord allocates each server a
  unique prefix (sanitized to libfx's rule, at most 27 characters, `_2`,
  `_3` on a clash) from a wrapper that records `listTools`, checks the
  adapter's names against libfx's rule and refuses rather than guesses, and
  keeps an original-name map for the ACP title `mcp__<server>__<tool>`.
  MCP tools are `idempotent: false`. Elicitation from those servers is
  relayed to chord's form (owner).
- **chord's own MCP server** (owner: in, as for every agent): it is HTTP
  with a bearer token per session, so it works with no special path; riff
  can spawn tasks, open agents, send messages, run monitors and be a team
  member or lead. Its read-only tools (`list_agents`, `get_budgets`,
  `list_monitors`) are marked idempotent.
- **Instructions** (owner, I2): chord's base instructions, then the
  `AGENTS.md` files from the repository root down to the session's
  directory, then `~/.config/chord/AGENTS.md`, read at session start into
  libfx's `instructions` under a 32 KiB cap (truncated with a note), within
  libfx's 64 KiB. The base instructions tell the model to read an
  `AGENTS.md` in any deeper folder it works in. No `CLAUDE.md`.
- **Skills** (owner): on demand, as fx does them (fx
  `src/builtins/skills.zig` discovery, `src/tools/skills/skill.zig` tool):
  `SKILL.md` files from `.agents/skills/` in the project and
  `~/.agents/skills/` only; each skill's name and description in the
  instructions; chord's own `skill` tool loads a skill by name with its
  resources, paged by offset. `libfx/skills` is not used (owner).

## Sessions and resume

- **Store** (owner, R1): `createFxAgent` with `local({ dir })` from
  `libfx/durable-local`, imported statically (libfx's default store loads by
  `new URL` and fails compiled; its default directory is the temporary
  one), under chord's state directory. Session ids are libfx's `wrun_…`.
  Cleanup is CHD-602.
- **Two truths**, as with Claude and Codex: chord's record is what was
  shown (drawn on resume, served by `chord acp`); libfx's store is what the
  model knows. No record format change. A JSON sidecar per session beside
  libfx's store holds the provider, account, model, effort and mode, since
  `session/resume` carries no configuration.
- **A turn a crashed process left open** (owner, T2): libfx's `resume()`
  runs an open turn, and a plain next prompt runs it first, unseen. On
  every reopen riff calls `await session.cancel()` and then
  `session.resume()`: `cancelled` with a `messageId` means a turn was open
  and is now ended (riff sends only the line 'The interrupted turn was
  cancelled.'; the dead turn's open call stays as libfx left it, and the
  window draws it as ended, as it does every agent's cut-off call); `idle`
  means none was. In eight crash trials this ran no model request and no
  tool of the dead turn. It follows
  from libfx's code order and is not a documented guarantee, so a
  fake-crash test in chord's suite counts model requests and tool runs and
  fails above zero.

## Models and effort

- riff carries a model list per provider in source, each with its context
  window and the plan's default first, as other agents carry their models
  in their own config options; libfx has no list for plans. `/model` is the
  `model` config option, applied to the next turn
  (`agent.session(id, { model })` keeps the history).
- `effort`: `default`, `low`, `medium`, `high`, `xhigh`. A level the model
  does not offer ends the turn with `LIBFX_MODEL_UNSUPPORTED_EFFORT`; riff
  answers `-32603` and resets the option to `default`.
- The list's entries and windows need checking against the live plans,
  which needs the owner's go-ahead for a real call.

## The build

- **Assets** (owner, the gate's option A): `fx-core.wasm` and the target's
  `libfx.node` are imported with `with { type: 'file' }` by their path
  inside `node_modules` (`node_modules/libfx/fx-core.wasm`,
  `node_modules/@libfx/libfx-<platform>/libfx.node`) and passed through
  libfx's documented `nativeAddon` (the path) and `wasm` (the bytes), with
  `backend: 'auto'`. Glibc below 2.34, an unwritable or `noexec`
  temporary directory, or a broken addon then all land on Wasm. libfx is
  exact-pinned.
- **One addon per binary**: a compile plugin in `scripts/dev/compile.ts`,
  beside `jsxDevRuntime`, resolves a virtual `chord:libfx-native` to the
  target's `libfx.node` with `loader: 'file'`. A plain import of all four,
  or one behind a `define`, embeds all four (+34 MB). From source the plugin
  does not run and libfx finds its addon in `node_modules`.
- **fff** embeds itself (its own `with { type: 'file' }`); the Linux builds
  add `--define FFF_LIBC='"gnu"'`, as its README documents.
- **The build fails on a layout change** (the owner's condition), in order:
  1. the plugin's resolve fails `Bun.build` when the file is missing,
     naming the package and version;
  2. `scripts/dev/libfx_assets.ts`, run by `compile` and by a test in the
     static job, checks every target's platform package is in libfx's
     `optionalDependencies` at libfx's version, its `index.js` still names
     `./libfx.node`, `fx-core.wasm` exists and starts with `\0asm`, libfx's
     version is the pinned one, and `libfxApiVersion` is 3;
  3. `bun dev selftest <binary>` runs one riff turn with a tool call on the
     fake provider on native, then with native disabled on Wasm.
- **Size**: +9.8 MiB (darwin-arm64), +11.1 MiB (darwin-x64), +9.8 MiB
  (linux-arm64), +11.1 MiB (linux-x64) for libfx; +5.2 to 10.7 MiB for fff;
  +0.8 MB of JavaScript for `local()`; +0.23 MB for unbash.

## Tests

Nothing reaches a real model, provider or sign-in endpoint, by
construction: every libfx network call goes through a `fetch` chord passes,
and every Bun.secrets call through a store chord passes.

- **The model**: a fake OpenAI Chat Completions server on `localhost`
  through libfx's custom provider (the gate ran a whole turn with a tool
  call this way); scenarios `text`, `tools`, `edit`, `shell`, `hang`,
  `retry`. This provider exists only for tests, `--fake` and `--qa`, never
  in settings (owner, Q3).
- **The plan path**: `provider: 'codex' | 'grok'` with a fake `fetch` that
  answers the client-version lookups, the model list and a Responses
  stream (tool calls and reasoning included), 401 then refresh, refresh
  rejected.
- **Sign-in**: libfx's functions with a fake `fetch` playing the auth
  endpoints; the listener on a random port, never 1455; one test asserts
  libfx's ChatGPT address still carries `redirect_uri=http://localhost:1455/auth/callback`.
- **Credentials**: the queue and its bound over an injected backend; two
  independent cells on one backing store and one lock directory with a
  rotating fake provider; logout racing a refresh; a late write after
  logout refused.
- **Tools**: in a temporary directory; abort mid-call; limits; a symlink
  pointing outside; an edit whose file changed; fff's set differences
  pinned so an fff upgrade that changes them fails.
- **Auto**: a fake reviewer: clear, caution, malformed then valid,
  malformed twice, timeout twice, permanent failure (auto → ask), budget
  exhausted; the 5-minute timeout with fake timers; the command classifier
  over the 218-case table.
- **Resume**: the fake-crash test of T2.
- **The build**: `libfx_assets.ts` passes on the installed tree and fails on
  copies with the addon renamed, a platform package removed, the Wasm
  missing, a version off; `selftest` as above.
- **The window**: the sign-in box, `/login`, `/logout`, the auto ask and
  their keys through `tests/ui/harness.tsx`; `--fake` and `--qa` give riff
  the fake provider, a memory store already signed in or not, and a
  fixture sign-in, never Bun.secrets.

`tests/` mirrors `src/`: `src/riff/*` under `tests/riff/`, the platform
modules (`secrets.ts`, `loopback.ts`, the fff Worker loader) under
`tests/platform/`.

## The providers' terms

libfx signs in with the Codex CLI's OpenAI client and the fx CLI's xAI
client, as fx and Mastra Code (mastra-ai/mastra,
`mastracode/sdk/src/auth/providers/openai-codex.ts` and `xai.ts`) do. riff
follows the same practice (owner, Q9): no terms line in the sign-in box,
no experimental mark, and the guide does not quote libfx's statement on
terms, since neither fx's nor Mastra's sign-in mentions them. The owner's
reading of the current terms is recorded on CHD-485.

## Why

riff is a child process because a fault in a 0.0.x native library should
cost a session, not the window, and because then everything above the ACP
connection, enrichers to records to `chord acp`, carries it with no second
path. The window signs riff in because ACP has no way for an agent to show
an address or a code while it signs in, and the box keeps every state in
chord's tests. The credential lives only in the system's store, written
by compare-and-set under one lock, so two windows and their children never
spend a rotated refresh token twice and a sign-out stays signed out. riff
follows chord's treatment of every other agent wherever there is one, so a
person sees riff's calls, costs and gauge exactly as they see Claude's or
fx's. The tools and the auto review are riff's own because libfx turns on
none of fx's; they follow fx's own design where the owner chose it, and
use libraries where one fits as it is.
