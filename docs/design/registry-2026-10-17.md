# The registry refresh of 2026-10-17 (CHD-432)

The owner (2026-10-17): adapters move all at once, through `bun dev registry`.
The refetch is committed alone as d27e225f. This page is what the team found
between the old pins and the new ones, what that means for a person using
chord and for the fake agent, which open tasks and owner questions it
changes, and a plan in order. It gives options and a plan for the owner, not
decisions. Nothing beyond the registry commit is built, and the refresh is
not merged, until the owner has seen this.

Everything here was read from the packages' `dist/` and release notes, read
only. No live agent was run. Paths in the findings point into each new
package's `dist/` unless they name `src/` or `tests/`.

## 2. What each agent can do, as chord sees it

All 25 agents in the registry, at the new pins, over ACP as chord speaks it
today. Each cell gives what holds and how it is known:

- `c`: read in the adapter's code or bundle at the new pin.
- `n`: from release notes, docs or binary strings only.
- `r`: established by earlier work in this repository at an older pin
  (`docs/design/CHD-1.md`, `CHD-378.md`, `docs/decisions.md`), and not
  changed by what the readers found.
- `—`: not read. Nothing is guessed.

`✓` means the agent has it, `✗` that it has not, and `◐` partly. A note,
by the agent's prefix, says how. Nothing was run.

**How the code was read.** Most agents were read from their npm, PyPI or
source packages. Some were read under limits:

- copilot and droid are native binaries, read from release notes and
  strings.
- grok has no public source after 1.0.45, so it was read from its notes and
  that source.
- Under the owner's rule of 2026-10-18 (CHD-433), the bundles of
  licence-restricted agents (bob, nova, auggie, qoder) were read as
  plain text only for the ACP contract: messages, fields, capabilities and
  observable behaviour. No internal names, quoted code or file and line
  cites into them are kept, and docs or release notes are cited first where
  they state a fact.
- nova's 1.1.55 README licence forbids reverse-engineering its obfuscated
  bundle, so it was read as plain text only, with nothing decoded.
- qoder's findings from a `webcrack` read of its bundle were removed. What
  is left of qoder comes from its docs only.

Nothing was deobfuscated for what this page keeps, and no derived copy of
any bundle is kept in the repository.

### Notes by agent

**claude** (0.93.0)

- **cl1.** `session/cancel` on the subagent's own session id, announced by
  `capabilities.cancel` (0.91).
- **cl2.** `async_task_*` and `_session/async_task/stop` only under
  `_meta.jetbrains.air`, which changes rawInput, rawOutput and subagent text
  across the board (Q26). Declaring AIR at all switches the subagent shape
  and drops Edit and Write rawInput (CHD-433's reading).
- **cl3.** Fork is advertised, but ACP's `session/fork` has no fork point
  (CHD-101). claude takes one through `_meta.jetbrains.air.fork`, without
  AIR (CHD-433's reading). `session/list` has paging and a cwd filter.
- **cl4.** Kinds `allow_once`, `allow_always`, `reject_once`, never
  `reject_always`. The ids are `allow-once`, `allow-with-updates`, the skill
  ids, seven `exit-plan-*` ids and `reject`.
- **cl5.** Plan entries. Since 0.93, an approved ExitPlanMode also comes as a
  markdown `plan_update` (C8).
- **cl6.** The whole output comes on the completing update, to a client that
  asks for terminal output in `_meta`.
- **cl7.** Background agents alive past a cancel, and the task-notification
  cycle.
- **cl8.** Custom instructions in `session/new` `_meta`. Their use by a
  client that is not AIR is unchecked.
- **cl9.** Session titles and its own usage (`_meta.quota`,
  `_claude/rateLimit` and others) reach every client, AIR or not (CHD-433's
  reading).
- **cl10.** Its own `/mcp` is hidden behind chord's (CHD-433's reading).

**codex** (2.2.2)

- **cx1.** `cancel` looks up only root sessions, so a child id announced in
  `subagent_spawned` stops nothing.
- **cx2.** Answers `startedNewTurn` where Claude's answers `promptRequired`.
- **cx3.** Tokens and context, no cost, and nothing mid-turn (CHD-374,
  CHD-405). The answer's `usage` is now the whole turn's (X6).
- **cx4.** Per kind of approval, among them `allow_for_session`, `decline`,
  `cancel`, and a network amendment that is `reject_always` when it blocks a
  host. The plan sends `implement_plan` or revise.
- **cx5.** MCP OAuth through a URL elicitation from its own `/mcp`.
- **cx6.** `plan_update` by id, markdown or a file, under
  `clientCapabilities.plan`.
- **cx7.** Also stays `in_progress` while it waits on an approval.
- **cx8.** Found by the CHD-433 reading: its `/mcp` and `/status` are
  hidden behind chord's (X2); an SSE MCP server fails `session/new`;
  `session/list` returns the person's other Codex threads; and it spends
  unseen on a model call for each title and, in `agent` mode, a model
  reviewer for approvals (X6–X9).

**gemini** (0.64.0)

- **ge1.** A subagent is one tool call of kind `think`, with no progress
  inside it.
- **ge2.** A background shell is one ordinary call titled `[background]`.
- **ge3.** A prompt sent while one runs aborts the running turn.

### claude-agent-acp 0.87.0 → 0.93.0

Read by developer.

**Breaks in chord:**

- **C1. Subagents now come in the ACP subagents RFD's form** (0.90, #1320).
  A client that is not AIR, as chord is, gets `subagent_update {sessionId,
  title, description, capabilities: {cancel: {}}, state: {state:
  'running'}}` in place of `subagent_spawned` (`native-subagents.js:930-952`).
  A subagent ends with `{state: 'idle', stopReason: 'end_turn' | 'cancelled'
  | 'error'}`, or `{state: 'unknown'}`. chord maps `idle` to completed
  whatever the stopReason, and maps `unknown` to nothing
  (`src/session/transcript/subagents.ts:232-249`). So a failed or cancelled
  Claude subagent reads `✓`, and a lost one runs on screen for good.
- **C2. Background subagents outlive a parent's cancel** (0.91 #1348, 0.93).
  chord marks every running subagent cancelled on Esc, "as the adapters do"
  (`src/session/transcript/turn.ts:139-151`). After Esc, an agent that is
  still alive shows as cancelled, and its later requests are refused
  silently (CHD-158), now in the common case.
- **C3. The fake agent's subagent scenarios play the draft
  `subagent_spawned`**, which only codex still sends. The `subagentupdate`
  scenario lacks `capabilities.cancel`, `requires_action`, `idle` with a
  stopReason, and `session_message`.

**Changes a person sees:**

- **C4.** A subagent's title is now `name (role)`, and its description is
  the short task. The full prompt comes in a new `session_message` update,
  which chord drops, so `ctrl+o` no longer shows a subagent's whole task.
- **C5.** `requires_action` while a subagent asks reads as running. This is
  harmless.
- **C6.** A tool call the turn ends without a result is now `failed`, with
  one line: "Claude stopped this tool call before it ran.", "The turn was
  cancelled before this tool call returned a result.", or "Claude ended the
  turn without returning a result for this tool." A terminal exit comes with
  a null code. After Esc, a grey `Waiting…` becomes `✗ failed`. To be
  checked against CHD-417's cut path and CHD-422's "an unfinished call waits

**Reads oddly on screen:**
